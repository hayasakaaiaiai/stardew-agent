# NPC 恋爱功能 Windows 全量游戏验收清单

> 2026-11-09。本清单供用户进入游戏逐项填写，空白不代表通过。开发期间没有进行本轮 Windows 游戏验收，也没有替用户安装测试版。
>
> 本轮分支是 **`codex/npc-romance`，功能提交 `abd6479` 已推送**，尚未合并 `main`。执行下面的拉取与切换命令；只更新 `main` 或生活分支拿不到恋爱功能。本分支已包含此前三类生活功能，Mod 和后端必须同时更新。

行为范围见 [恋爱功能 spec](npc-romance-spec.md)，人物文案与来源见 [角色内容依据](npc-romance-content.md)。安装和恢复副本沿用 [生活功能验收清单](npc-life-game-checklist.md) 的方式，本文件覆盖恋爱新增流程及必要旧功能回归。

结果栏填“通过”“失败＋现象”或“尚未执行＋原因”。失败时记录编号、NPC、原版关系、游戏日期和时刻、实际地图、目的地、显示的有效分钟、开关设置，并保留 SMAPI 和后端相关日志。自由模型回复的人物感与事实准确性另记，不能把一句“约好了”或“完成了”当作菜单计划或实际结算。不要提供 `.env` 或密钥。

## 1. 获取代码、安装和恢复副本

先退出游戏及旧后端，保留原 Mod。使用测试存档，同时保留对应的后端记忆副本：游戏存档通常在 `%APPDATA%\StardewValley\Saves`，后端记忆在代码目录的 `.runtime\game`。做恢复点时，退出两端后一起备份这两部分；恢复到另一条测试分支时也成对还原。

在自己的 Windows 仓库根目录执行以下命令；首次切换会跟踪同名远端分支。拉取后的历史应包含功能提交 `abd6479` 及其后的文档更新。如有本地改动冲突，先保留改动，不使用强制覆盖或删除数据解决。

```powershell
git fetch origin
git switch codex/npc-romance
git pull --ff-only
git log -2 --oneline
```

代码目录和游戏路径按实际位置替换。继续使用原 Windows 目录也可以，不必搬动 `.env` 与记忆数据。若复制源码，不要带上 Mac 的工作树 `.git` 指针、`node_modules`、`bin`、`obj`；另建测试目录时使用测试存档及配套记忆副本。

```powershell
Set-Location E:\stardew-agent-romance-test
npm ci
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }

# 先只编译，游戏目录替换为自己的安装位置。
dotnet build mod/StardewAgentBridge -c Release '-p:GamePath=E:\games\steamapps\common\Stardew Valley' -p:EnableModDeploy=false

# 退出游戏并备份旧 Mod 后，安装同一版本。
dotnet build mod/StardewAgentBridge -c Release '-p:GamePath=E:\games\steamapps\common\Stardew Valley' -p:EnableModDeploy=true
Test-Path 'E:\games\steamapps\common\Stardew Valley\Mods\StardewAgentBridge\assets\romance-profiles.json'
npm run bridge
```

保持后端窗口运行，再用 SMAPI 启动游戏。环境沿用生活功能：Node.js 24、.NET SDK 8 或更高、星露谷 1.6、SMAPI 4。新菜单和约会结算本身不额外调用模型，自由聊天和原有夜间整理仍使用已配置的模型服务。

| 编号 | 操作 | 预期 | 结果 |
|---|---|---|---|
| P01 | 记录 `git log` 的提交、后端目录和 Mod 安装目录 | 两端均为本轮恋爱代码；没有另一旧后端占着默认端口 `47711` | |
| P02 | 检查源码 `data/romance/profiles.json`、`src/agent/romance.ts`、`mod/StardewAgentBridge/Romance.cs` | 文件齐全；原版 12 位角色配置来自同一份 JSON | |
| P03 | 执行编译和安装，检查安装目录的 `assets/romance-profiles.json` | 编译成功，`Test-Path` 返回 `True`；未重复装两个同名 Mod | |
| P04 | 读入单人测试存档，等待同步完成后交谈 | 正常聊天可用，没有循环同步或角色资料加载错误 | |
| P05 | 检查 `%APPDATA%\StardewValley\ErrorLogs\SMAPI-latest.txt` 与后端窗口 | 无本轮异常；失败时保留原始错误和恢复点，不通过清空记录掩盖问题 | |

## 2. 开关、资格和测试安排

配置在游戏 `Mods\StardewAgentBridge\config.json`。首次运行会生成；修改后退出并重启游戏。旧配置没有 `Romance` 字段时按默认开启处理。

| 开关 | 完整测试设置 | 作用 |
|---|---|---|
| `Romance` | `true`，另测关闭 | 允许新恋爱计划、NPC 回邀和记忆重点选择 |
| `OfferContinueChat` | `true` | 原版台词后显示扩展菜单 |
| `NpcMeetings`、`MeetingsGoTogether` | 均 `true` | 实际出发和跟随所需；关闭时不能强行带走 NPC |
| `MeetingsChangeFriendship` | `true`，另测 `false` | 约会沿用原有活动好感规则和日上限 |
| `LifeActivities` | 常规为 `true`，另测 `false` | 控制普通生活活动；恋爱约会有自己的开关 |
| `SharedGoals`、`LifeSocial`、`SendLetters` | 回归测试时为 `true` | 共同目标、生活社交和原有信件回归 |

用现有测试档或副本准备三类原版关系：恋爱中、订婚、已婚；另有 8 心普通朋友与科罗布斯室友作为反例。不要只靠心数判断是否恋人。优先在非节日、非剧情、非原版拒绝交谈期的普通日进行主流程。

建议每位角色分两天完成两个地点；把改约、提前结束、离线和回滚放在副本中分开测。约会实际出发与普通约定／生活活动共用每天最多 3 次启动额度，不要求一天完成整张清单。开始后提前结束仍占当次额度；确认计划、回看记忆本身不是一次已完成活动。

| 编号 | 操作 | 预期 | 结果 |
|---|---|---|---|
| E01 | 与原版恋人说完原版台词 | 出现“我们的约会与回忆”；若先收到 NPC 回邀，可选“改天再说”，再交谈打开玩家入口 | |
| E02 | 与 8 心普通朋友交谈、在聊天中说“我们约会吧” | 不因高心或一句聊天成为原版恋人，不创建恋爱菜单计划 | |
| E03 | 与科罗布斯室友、非名单角色及孩子交谈 | 没有新恋爱入口；科罗布斯原有家庭陪伴保留 | |
| E04 | 在节日、原版事件中或拒绝交谈期尝试新安排 | 不插入新活动、不夺取剧情控制；正常条件恢复后可继续测 | |
| E05 | 约会菜单任一步选“先不安排”或退出，之后重新查看 | 没有半成品计划、额外启动次数或新增完成回忆 | |

## 3. 12 位角色的完整矩阵

每一行都执行：玩家发起并完成地点 A；在冷却允许的另一日接 NPC 回邀并完成地点 B；两个地点分别选择两种相处方式，核对邀请、菜单推荐顺序、完成收尾和该角色自己的回忆。不要把“某一角色通过”代替全部 12 人通过。

“安静”与“聊天”只是双方约定的相处方式及对话语境，完成门槛相同。聊天方式不要求调用模型才能完成，也不自动证明聊过任何具体话题。没有拍照、演奏、绘画、野餐物品或新动画奖励。

| NPC | 地点 A | 地点 B | 默认优先方式 | A 玩家发起／完成／收尾 | B NPC 回邀／完成／收尾 | 独立回忆／人物感 |
|---|---|---|---|---|---|---|
| 阿比盖尔 | 山间 `Mountain` | 小镇 `Town` | 聊天 | | | |
| 亚历克斯 | 海滩 `Beach` | 小镇 `Town` | 聊天 | | | |
| 艾利欧特 | 海滩 `Beach` | 森林 `Forest` | 聊天 | | | |
| 艾米丽 | 小镇 `Town` | 森林 `Forest` | 聊天 | | | |
| 海莉 | 海滩 `Beach` | 小镇 `Town` | 聊天 | | | |
| 哈维 | 小镇 `Town` | 森林 `Forest` | 聊天 | | | |
| 莉亚 | 森林 `Forest` | 海滩 `Beach` | 安静 | | | |
| 玛鲁 | 山间 `Mountain` | 小镇 `Town` | 聊天 | | | |

森林指煤矿森林，山间指木匠店与山湖所在整张地图，不要求站在某棵树或湖边。每位角色仅提供本行两个目的地，不能把别人的地点或文案混进来。谢恩不承诺被恋爱治愈，海莉不宣称已经拍出照片，塞巴斯蒂安的邀请不把晴天说成雨天；既有原版心事件仍按已看事件限制。

## 4. NPC 回邀与冷却

回邀发生在见面、原版台词之后，不是自动寻路上门或寄信。全局每个游戏日最多一次；同一 NPC 两次回邀至少间隔 3 个游戏日。未接受也会占当天回邀机会，不会因为反复交谈重弹。

| 编号 | 操作 | 预期 | 结果 |
|---|---|---|---|
| I01 | 无待办计划、符合关系且同步完成时与 NPC 交谈 | 出现该角色自己的邀请；只有继续选完并确认才创建计划 | |
| I02 | 回邀选“今天先聊聊天” | 转入普通聊天，没有自动计划、物品消耗或拒绝惩罚 | |
| I03 | 回邀选“改天再说”，同日再与同一人及另一位恋人交谈 | 当天不再弹第二次恋爱回邀；仍可主动从菜单商量 | |
| I04 | 记录邀请日 D；在 D+1、D+2、D+3 分别检查同一人 | 前两天不重复；D+3 在无其他人先占当天回邀且条件合格时可再邀请 | |
| I05 | 确认一个待进行计划后反复交谈 | 不另发一份回邀覆盖原计划，仍可查看、改约、取消 | |
| I06 | 邀请后正常睡觉保存，退出重进 | 冷却随存档保留，不因重启刷新；回滚另见恢复测试 | |

## 5. 计划、改约、取消与实际出发

可选今天／明天及 10:00、14:00、17:00。**出发地点是 NPC 当时真实所在处**：在约定时刻起 60 游戏分钟内走到它身边，选择“按计划一起出发”，再一起走向目的地。菜单计划不会使 NPC 提前自行站在目的地等待。

| 编号 | 操作 | 预期 | 结果 |
|---|---|---|---|
| D01 | 依次选地点、日期、时间、方式，最后选“就这样约好” | 查看计划时四项一致；当前仍未出发、未完成 | |
| D02 | 下午打开今天时段；再查看明天时段 | 今天过去的时刻不可选；明天正常提供三个时刻，没有后天或任意时刻 | |
| D03 | 未出发时改到另一合法时间和该 NPC 的第二地点 | 原计划被更新，只保留一份待办；旧目的地、旧时间不能启动另一场 | |
| D04 | 改约流程中退出，再查看原计划 | 原计划完整保留，不因退出丢失或部分改写 | |
| D05 | 取消时先选“保留安排”，再重新打开并确认“取消约会” | 前一次不取消；确认后待办消失，无完成回忆、失约惩罚或奖励 | |
| D06 | 约 14:00；分别在 13:50、14:00、15:00 尝试出发，使用独立副本 | 13:50 不启动，14:00 和 15:00 可启动；不能一次活动重复启动 | |
| D07 | 约 14:00，直到 15:10 才找 NPC | 已过出发窗口，不能补记出发或完成；旧安排结束，无新增失约惩罚 | |
| D08 | 到约定时找真实 NPC，先出发，再跨地图走到目的地 | NPC 从当前位置正常跟随，不因确认计划瞬移到目的地 | |
| D09 | 已出发后打开约会入口 | 查看当前活动进度并可结束；途中不能直接把目的地重写为另一张地图 | |
| D10 | 同一 NPC 有未结束的普通约定时尝试出发约会 | 明确拒绝冲突，不抢走已有约定的 NPC，不消耗一次失败启动额度 | |
| D11 | 另一项生活活动或做饭接续等待未结束时再安排／出发约会 | 要求先结束当前活动；不同时控制两个人或两个活动 | |
| D12 | 同日用普通约定、生活活动及约会占满 3 次，再试新出发 | 第 4 次被拒绝；不因恋爱菜单绕过日限额 | |

## 6. 到场计时、完成和结束

以菜单显示的有效分钟为准。只有双方位于约好的地图、相距不超过 8 格、没有菜单暂停／剧情／传送且正常走过完整 10 分钟区间，才累积时间；跨图或打开菜单的区间不会补算。到场后留足三个完整有效区间，再确认进度至少 30 分钟。

| 编号 | 操作 | 预期 | 结果 |
|---|---|---|---|
| T01 | 目的地选海滩，在镇里或路途中正常跟随 30 分钟 | 约会进度保持 0；不能把路程计为海滩相处 | |
| T02 | 两人到正确地图、贴近，连续正常走时；再打开进度 | 有效分钟增加，到至少 30 分钟可选择“结束这次活动”完成 | |
| T03 | 到场后远离 NPC 超过 8 格，随后重新靠近 | 远离区间不计时，重新满足条件后才恢复；不补算中断时段 | |
| T04 | 打开背包／对话菜单暂停，再关闭；中途跨一次地图 | 暂停、传送和无效区间不加分钟；剩余活动仍能继续或退出 | |
| T05 | 用已有测试工具跳时，或利用普通睡觉跨日；不要为此安装新工具 | 不把大幅跳时当连续相处，跨日不继承昨天分钟；没有工具可把跳时项记为尚未执行 | |
| T06 | 有效分钟不足 30 时选择“今天先回去” | 提前结束、NPC 释放控制，无完成回忆、完成好感或失约惩罚 | |
| T07 | 有效分钟达到 30 后结束 | 只完成一次恋爱约会，出现该角色收尾；不再同时结算一份普通散步奖励 | |
| T08 | 分别以“安静地陪着彼此”和“留些时间聊聊”完成 | 两者均靠真实到场计时；不要求聊天条数、不自动生成具体聊天内容或照片、演奏、作品 | |
| T09 | 从出发起经过 90 游戏分钟；有可用测试情境时另测 22:00 夜间退出 | 自动收尾，已累计至少 30 分钟才算完成，否则为提前结束；NPC 不无限跟随 | |
| T10 | 在不同地图结束，观察 NPC 回程、换图及下一段原版日程 | NPC 恢复日程，配偶正常回家；旧回程不把后来新活动的 NPC 再传走 | |
| T11 | 先关闭 `MeetingsChangeFriendship` 完成一次，再开启测试 | 关闭时可完成但不加活动好感；开启时沿用原有规则，没有恋爱专属重复奖励 | |
| T12 | 同日聊天与多次活动接近已有好感日上限 | 不超过 Agent 既有每日 +30 总预算；实际增量可受原版上限影响，回看或重连不再加一次 | |
| T13 | 同行时进入不支持普通同行的矿洞等场景 | 活动中断并释放 NPC，不自动变成矿洞同伴；此中断不记完成，即使此前已累计 30 分钟 | |

## 7. 共同回忆、历史时态与重访

完成时显示该角色的收尾气泡和提示，不必当场选片段；下次交谈进入“我们的约会与回忆”，可选“选一个想记住的片段”。当前菜单展示首次与最近 3 次完成，去重后最多 4 项；底层保留最近 24 次并独立保留首次。最早一条记录是本功能可确认的首次，不能当作原版交往起点或周年。

| 编号 | 操作 | 预期 | 结果 |
|---|---|---|---|
| M01 | 未有完成记录，只计划／出发／提前结束时查看回忆 | 没有把计划或中断列成完成；不补造旧档以前的约会 | |
| M02 | 完成后选“以后再选”，正常保存，次日再选 | 完成记录一直保留，次日仍可补选片段 | |
| M03 | 对三个不同完成记录分别选地点、天气、相伴时间 | 每次只保存本次所选重点；日期、地图、天气、有效时长来自那次实际完成 | |
| M04 | 一次选完再打开同条记录、退出重进并反复回看 | 已选内容一致，不重复选择、不重复好感或新增一场约会 | |
| M05 | 在晴天完成，改在雨天回看；再做一次反向测试 | 旧回忆仍显示源日期和源天气，不改写成今天的天气；不会再次播放带“今天”的旧完成收尾 | |
| M06 | 与两位不同恋人分别完成，再各自回看 | 各人只看到自己的经历；不能把另一人的约会当作当前 NPC 的记忆 | |
| M07 | 从完成记录选“再约一次，重访这里” | 创建新的待办，并保持原来源地点；没有当场增加完成次数 | |
| M08 | 改约重访的时间，或取消重访 | 改时仍保留原地点和来源；取消不删除旧回忆、不把旧完成再算一次 | |
| M09 | 实际出发并完成重访，正常保存重进 | 新完成有新的源日期与真实天气，旧完成仍在；两次记录不混写 | |
| M10 | 长期测试完成超过 24 次约会，再回看首次和近期 | 首次仍可见、可作为重访来源，近期菜单不无限增长；中间旧记录不冒充最新记录 | |
| M11 | 在生活好友分享入口寻找一条恋爱完成记录 | 恋爱回忆不进入公开可分享来源，不自动向其他 NPC 宣告恋情 | |
| M12 | 在计划、出发、完成、选择片段后各进行一次自由聊天 | 分别承认对应阶段；未完成不说已经结束，方式只表示约定或意图，不编造聊过的具体内容 | |
| M13 | 带旧印象的 NPC 完成约会，睡觉整理后再聊天 | 原有印象和其他真实记忆仍可用，恋爱摘要没有覆盖全部旧记忆 | |
| M14 | 旧档第一次记录约会时询问“我们什么时候开始交往” | 不把本功能首次记录当作交往起始日，不编造未记录的周年、亲吻或原版事件 | |

## 8. 关系改变与角色边界

## 9. 保存、回滚、离线和兼容门禁

正常保存指通过原版睡觉保存，不把退标题当作新进度已落盘。回滚测试用已保留的成对副本分叉；进行中的跟随不跨读档自动续算。旧后端测试只在隔离副本中做，测试后恢复同一新版后端，不在正式档混用版本。

| 编号 | 操作 | 预期 | 结果 |
|---|---|---|---|
| S01 | 约明天，正常睡觉保存，退出两端并重启 | 日期、时刻、地点、方式与待办一致；到时可真实出发 | |
| S02 | 改约后睡觉保存；另一副本取消后保存 | 改约与取消各自准确恢复，没有旧待办复活或两份计划 | |
| S03 | 完成但未选片段时保存重启；再选片段后另存重启 | 两个阶段分别持久，完成次数和已选状态不丢、不重复 | |
| S04 | 计划已确认但未睡觉，退出标题再读当天存档 | 回到该保存点真实状态；未保存的计划／邀请冷却不能污染回滚分支 | |
| S05 | 活动进行中退标题，再读原档或另一个测试档 | 旧菜单、控制器、分钟和延迟回程不进入新会话；读档不自动补成完成 | |
| S06 | 从同一成对恢复点，一支完成约会，另一支取消或改地点 | 两支仅承认各自发生的事实；旧分支的完成不出现在新分支 | |
| S07 | 开始约会前停止后端，再尝试新计划、出发和记忆选择 | 同步未就绪时不创建新动作；原版游戏不被拖住 | |
| S08 | 已经出发后停止后端，再与同行 NPC 交谈 | 可通过首层“结束当前活动”进入原生进度并结束，不能趁断线开启新约会或继续自由模型聊天 | |
| S09 | S08 分别在不足 30 分钟和达到 30 分钟后结束，再恢复新版后端 | 分别保存真实中断／完成，NPC 先释放；重连只同步一次，不再次发好感或再控制 NPC | |
| S10 | 完成记录后连续重启后端、重连和读同一保存点两次 | 无重复完成、重复片段、重复回邀或好感增加；既有日期仍为源日期 | |
| S11 | 新版 Mod 接不支持恋爱能力的旧后端，存档尚无恋爱记录 | 不出现可执行的新恋爱入口；原有兼容的生活和聊天不被恋爱功能永久锁死 | |
| S12 | 已含恋爱记录的副本接旧后端 | 明确提示“恋爱记录需要新版后端，请同时更新后端和 Mod”；保留原记录，暂停不兼容同步与新聊天，不假装同步完成 | |
| S13 | S12 切回新版后端，等待完整同步 | 恢复可用，历史完整，没有因旧版拒绝而被清空或重复导入 | |
| S14 | 保存待办和已完成回忆后退出游戏，设置 `Romance=false` 再启动 | 没有新回邀、计划、出发、改约或片段选择；仍可查看旧回忆、取消已有待办 | |
| S15 | S14 再开启 `Romance` | 未过期且未取消的待办和历史继续保留；不能把关闭期间已过期计划补成完成 | |
| S16 | `Romance=true`、`LifeActivities=false`，其余出发前提满足 | 恋爱约会仍可独立计划、出发、完成；普通独立生活活动按自己的开关关闭 | |
| S17 | 分别关闭 `NpcMeetings` 或 `MeetingsGoTogether` 后尝试出发，再恢复 | 不夺取 NPC，提示所需开关；恢复后按真实计划时间和资格判断，失败尝试不扣启动额度 | |
