# roster 与对话原型设计

> 状态：已实现并实测（2026-10-18），结果见 §11。不涉及记忆系统；记忆系统（M1）在 `codex/npc-memory-store` 分支上开发。

## 1. 目标

在接入游戏之前，先用命令行验证三件事：
- 便宜模型拿着约 600 token 的角色卡，能不能演得像。
- 会不会剧透还没触发的心事件。
- 每轮对话用多少 token、花多少钱、要等多久。

结果过关再做 M3（SMAPI Mod）。这一步不做：调度器、合并场景调用、记忆写入、白名单动作、Mod。

## 2. 交付物

| 部分 | 位置 | 说明 |
|---|---|---|
| roster | `src/services/roster/` | 解析、校验角色卡，按心数和事件渲染成 prompt 文本 |
| 模型客户端（最小版） | `src/services/model/client.ts` | OpenAI 兼容接口，流式输出，记录用量和延迟 |
| 对话 | `src/agent/dialogue.ts` | 拼 prompt、解析输出。纯函数，不依赖 `NpcAgent` |
| 命令行 | `tools/chat.ts` | 交互聊天和批量探测 |
| 场景和探测题 | `tools/chat/scenarios/*.json`、`tools/chat/probes/*.md` | 见 §6、§7 |
| 测试 | `tests/roster.test.ts`、`tests/dialogue.test.ts` | 离线，不调用模型 |

全部是新文件。唯一要改的已有文件是 `package.json`，加一个 `chat` 脚本。不新增依赖：HTTP 用 Node 自带的 `fetch`。

## 3. roster

### 3.1 解析

- 文件名是 id，必须在 `SOCIAL_NPCS` 里；一级标题是显示名。
- 二级标题固定。必填：身份与背景、性格、说话风格（含 `### 示例台词`）、人际关系、喜好、按心数解锁的话题、不能说的内容。可选：可送物品、特殊条件。
- 列表项的格式：

| 部分 | 格式 | 备注 |
|---|---|---|
| 人际关系 | `- 名字（id）：描述` | 不在 34 人名单里的人物省略 id |
| 可送物品 | `- 物品名：说明` | 物品名到 ID 的对应在 M3 做 |
| 按心数解锁的话题 | `- N+：内容` | 内容开头可以带“（条件）”，见 §3.2 |
| 不能说的内容 | `- 条件：内容` | 条件写法见 §3.2 |

### 3.2 条件

“不能说的内容”每条以第一个“：”为界，前面是条件。条件分三种：

| 写法 | 例子 | 判定方式 |
|---|---|---|
| 条件里有“事件 <编号>” | 看过 6 心事件（事件 4，深夜墓地）之前 | 程序判断：列出的事件一个都没看过时，这条生效 |
| “N 心之前” | 10 心之前 | 程序判断：心数低于 N 时生效 |
| 以“任何时候”开头 | 任何时候：不说出自己的真名 | 程序判断：一直生效 |
| 其他 | 新房子盖好之前 | 原样交给模型，让它结合“世界事实”自己判断 |

话题里的“（肯特回来后）”“（约会中）”这类条件也原样交给模型。世界状态里会给出这些事实（§4.1 第 4 项），所以模型能判断。

校验时，条件里写了“之前”却没有事件编号的，只警告，不报错。现有卡片里有这几条：
- 潘姆：新房子盖好之前。
- 科罗布斯：14 心事件。游戏导出里没有这个事件的编号。

另外有一条要改卡：德米特里厄斯那条“任何时候：不知道玛鲁在造机器人（看过玛鲁的 10 心事件 10 之前）”写错了。应该改成“看过玛鲁的 10 心事件（事件 10）之前：……”，因为他在那个事件里亲眼见过机器人。

### 3.3 渲染

```ts
render(id, view): { stable: string; gated: string }
// view: { hearts, seenEvents, relation, purpose: 'dialogue' | 'scene', includeGifts }
// relation: 'stranger' | 'friend' | 'dating' | 'engaged' | 'married' | 'roommate'
```

- `stable`：身份与背景、性格、说话风格、示例台词、人际关系、喜好。只随卡片文件变化，放在 prompt 前面，能命中前缀缓存。`purpose: 'scene'` 时省略示例台词，省约 70 token（M2 才用到）。
- `gated`：当前心数够得着的话题、当前生效的禁忌、特殊条件；`includeGifts` 时加上可送物品。随心数和事件变化，放在 `stable` 后面。

### 3.4 重新加载

原型在启动时加载，命令行里用 `/reload` 手动重新加载。解析失败时保留旧版本并打印错误。监听文件变化、自动重新加载放到 M2。

## 4. 一次对话调用

### 4.1 prompt 布局

按“越稳定越靠前”排，和设计文档 §9.2 一致：

1. 世界规则、文风、输出格式（所有 NPC 相同）
2. 角色卡 `stable`
3. 角色卡 `gated`
4. 世界状态：日期、季节、天气、时间、地点、关系状态，以及世界事实（第几年、肯特在不在、社区中心或 Joja 的进度、巴士修没修好、玩家性别和称呼等）
5. 记忆：原型里是空的，接口见 §4.3
6. 今天和这个 NPC 的对话，作为 user / assistant 消息
7. 玩家这一句

### 4.2 输出格式

使用服务商的 JSON 输出模式，模型只输出一个 JSON 对象，`reply` 放第一个字段：

```json
{"reply":"嘿。下雨天你也出门了？……我正打算去找青蛙。","emotion":"happy","options":["一起去吧","你喜欢青蛙？","我得回农场了"],"remember":[{"text":"玩家下雨天来找我聊天","importance":2}],"end":false}
```

台词仍然能一边生成一边显示：`ReplyStream` 从还没写完的 JSON 里逐字解出 `reply` 的值，转义符被切在两个分块之间也能处理。

最初的设计是“先写台词，再写一行 `@@`，最后一行 JSON”。实测 `deepseek-flash` 大多只输出台词、忽略后半部分，成功率 0/6 到 3/6，所以改成了 JSON 模式。JSON 模式在这个模型上有两个怪癖，已经处理：
- 开着推理、而 “json” 只出现在系统提示里时，模型只输出空白。所以玩家这一句后面附上“（用 json 回复）”，历史消息里不带。
- 即使这样，偶尔仍会输出空白。内容为空时自动重试一次，统计时把两次的 token 和耗时都算进这一轮。

- `emotion`：`neutral`、`happy`、`sad`、`blush`、`angry`、`special`，对应原版头像表情。
- `options`：下一轮给玩家的 3 个选项。
- `remember`：这轮要记住的事。原型里只打印出来，不写入。
- `end`：NPC 主动结束对话。
- 解析失败时：用已经显示出来的台词作为回复，给 3 个通用选项，并记一次格式失败。
- 历史消息里只保存回复正文，不保存 JSON，省 token。

### 4.3 记忆接口

```ts
interface DialogueMemory {
  context(query: string): Promise<{ summary?: string; memories: { text: string }[] }>;
  remember(items: { text: string; importance: number }[]): Promise<void>;
}
```

原型用空实现。两条线合并后，用 `NpcAgent.context()` 和 `record()` 实现这个接口，`dialogue.ts` 不用改。

## 5. 模型客户端（最小版）

- 配置从 `.env` 读：`NPC_MODEL_ENDPOINT`、`NPC_MODEL_NAME`、`NPC_MODEL_API_KEY`，另有可选的：
  - `NPC_MODEL_THINKING`：`disabled`、`low`、`high`（默认）、`max`。`disabled` 发送 `thinking: {type: disabled}`，其余发送 `reasoning_effort`。
  - `NPC_MODEL_TIMEOUT_MS`：默认 60000。原型里放宽，是为了量出真实耗时，不把回复截断。
  - `NPC_MODEL_MAX_TOKENS`：默认 4000，包含推理 token。
- 当前配置：DeepSeek 官方接口，模型 `deepseek-flash`（DeepSeek-V4.1-Flash），推理强度 `high`。
- 请求 `{endpoint}/chat/completions`，`stream: true`，并要求在流的最后返回用量。
- 还没收到响应就断开的连接错误（比如 TLS 握手时被重置），最多重试 2 次；超时不重试。
- 每次调用记录：首字延迟、总耗时、输入 token、输出 token、缓存命中的输入 token。缓存命中数取服务商返回的字段，比如 DeepSeek 的 `prompt_cache_hit_tokens`；没有这个字段就记为空。
- 不做：排队、限流、`dialogue` / `background` 两个档位。这些在 M2 的模型网关里做。

## 6. 命令行

```sh
node tools/chat.ts abigail --scenario rainy-spring --hearts 4 --seen 1,2
```

- 输入数字选选项，输入其他内容就是“自己说”。
- 斜杠命令：

| 命令 | 作用 |
|---|---|
| `/hearts N` | 设置心数 |
| `/seen 4`、`/unseen 4` | 标记事件看过 / 没看过 |
| `/relation dating` | 设置关系 |
| `/world key=value` | 改世界状态或世界事实 |
| `/prompt` | 打印上一次发出的完整 prompt |
| `/stats` | 本次会话的 token、延迟、格式失败次数 |
| `/reload` | 重新加载角色卡 |
| `/reset` | 清空今天的对话 |
| `/save` | 把对话记录写到文件 |

- 批量探测：`node tools/chat.ts --probe abigail` 依次发送 `tools/chat/probes/abigail.md` 里的题目。对话和每轮的 token、延迟写到 `.runtime/transcripts/<时间>-<npc>.md`，方便人工看。
- 场景文件（JSON）包含：日期、季节、天气、时间、地点、玩家名、玩家性别、农场名、世界事实、心数、已看过的事件、关系。

## 7. 探测题和验收

先写 6 位，各有侧重：

| NPC | 侧重 |
|---|---|
| 阿比盖尔 | 心事件多，身世伏笔 |
| 谢恩 | 抑郁和酗酒这类敏感话题 |
| 贾斯 | 小孩，只聊孩子的话题 |
| 矮人 | 学会矮人语之前听不懂 |
| 科罗布斯 | 周五只说“……” |
| 刘易斯 | 和玛妮的秘密恋情 |

每位约 10 题：日常 3 题、按心数的话题 2 题、剧透探测 3 题、越界 2 题（问现实世界、问它是不是 AI、要它出戏）。每题可以临时改条件，比如 `- [hearts=2] 你会吹长笛吗？`。

建议的验收线（可以改）：

| 指标 | 目标 |
|---|---|
| 剧透探测 | 一次都不说出没解锁的内容 |
| 格式 | 至少 95% 的轮次能解析 |
| 首字延迟 | 中位数小于 2 秒 |
| 总耗时 | 95% 的轮次小于 8 秒（对应设计文档 §7.6 的超时） |
| 每轮输入 token | 记录下来，用来校准设计文档 §9.3 |

演得像不像，由你看对话记录主观判断。

## 8. 测试

离线运行，不调用模型：
- roster：34 张卡都能解析；三种条件都能正确识别；心数过滤正确；`stable` 部分不随心数和事件变化，保证能命中前缀缓存。
- dialogue：输出解析覆盖四种情况：正常、没有 `@@`、JSON 坏掉、流式分块正好切在 `@@` 中间。另外检查 prompt 各部分的顺序。

## 11. 实测结果（2026-10-18）

6 位 NPC、58 道探测题，`deepseek-flash`、推理强度 `high`：

| 指标 | 结果 | 验收线 |
|---|---|---|
| 格式 | 58/58，没有触发空白重试 | 至少 95% |
| 首字延迟 | 中位数 1.4–1.8 秒 | 中位数小于 2 秒 |
| 总耗时 | P95 2.6–4.9 秒，没有超过 8 秒的 | 95% 小于 8 秒 |
| 每轮输入 | 约 1400–1600 token，缓存命中 71–82% | 记录 |
| 每轮输出 | 约 90–130 token，其中推理 35–63 | 记录 |

剧透探测第一轮发现两处，都已修好并复测通过：
- 贾斯 4 心时被问到父母，说出了“他们不在了”。原因是这件事只写在“按心数解锁的话题”里，那里只管“不主动提”。修法：卡片支持“N 心之前”条件，给贾斯加了一条；规则里写明没解锁的往事被直接问到也不说具体内容。
- 谢恩没经历悬崖事件，却顺着玩家的问题承认“那天”发生过什么。修法：规则里写明，玩家说起没发生过的事，不要顺着承认。

还没解决的：
- **事件之后知道的事**：看过心事件后，对应的禁忌会解除，但模型并不知道事件里发生了什么。比如谢恩看过 7 心事件后本该在戒酒，他却说“昨晚就一瓶”。需要给卡片加一种“看过某事件之后”的正向内容，下一步设计。
- 偶尔有小的事实错误，比如矮人说族里“就剩我一个了”，而他的卡片里写着火山里还有别的矮人。

对话记录在 `.runtime/transcripts/`（不进仓库）。
