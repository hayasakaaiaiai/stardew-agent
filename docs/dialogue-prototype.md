# roster 与对话原型设计

> 状态：已实现并实测（2026-10-18），结果见 §11。不涉及记忆系统；记忆系统（M1）在 `codex/npc-memory-store` 分支上开发。

## 1. 目标

在接入游戏之前，先用命令行验证三件事：
- 便宜模型拿着约 600 token 的角色卡，能不能演得像。
- 会不会剧透还没触发的心事件。
- 每轮对话用多少 token、花多少钱、要等多久。

结果过关再做 M3（SMAPI Mod）。这一步不做：调度器、合并场景调用、记忆写入、白名单动作、Mod。

| 部分 | 位置 | 说明 |
|---|---|---|
| roster | `src/services/roster/` | 解析、校验角色卡，按心数和事件渲染成 prompt 文本 |
| 模型客户端（最小版） | `src/services/model/client.ts` | OpenAI 兼容接口，流式输出，记录用量和延迟 |

## 3. roster

### 3.1 解析

- 文件名是 id，必须在 `SOCIAL_NPCS` 里；一级标题是显示名。
- 二级标题固定。必填：身份与背景、性格、说话风格（含 `### 示例台词`）、人际关系、喜好、按心数解锁的话题、不能说的内容。可选：可送物品、特殊条件。
- 列表项的格式：

| 部分 | 格式 | 备注 |
|---|---|---|
| 人际关系 | `- 名字（id）：描述` | 不在 34 人名单里的人物省略 id |
| 可送物品 | `- 物品名：说明` | 物品名到 ID 的对应在 M3 做 |
| 按心数解锁的话题 | `- N+：内容` | 内容开头可以带“（条件）”，见 §3.2 |
| 不能说的内容 | `- 条件：内容` | 条件写法见 §3.2 |

### 3.2 条件

“不能说的内容”每条以第一个“：”为界，前面是条件。条件分三种：

| 写法 | 例子 | 判定方式 |
|---|---|---|
| 条件里有“事件 <编号>” | 看过 6 心事件（事件 4，深夜墓地）之前 | 程序判断：列出的事件一个都没看过时，这条生效 |
| “N 心之前” | 10 心之前 | 程序判断：心数低于 N 时生效 |
| 以“任何时候”开头 | 任何时候：不说出自己的真名 | 程序判断：一直生效 |
| 其他 | 新房子盖好之前 | 原样交给模型，让它结合“世界事实”自己判断 |

话题里的“（肯特回来后）”“（约会中）”这类条件也原样交给模型。世界状态里会给出这些事实（§4.1 第 4 项），所以模型能判断。

校验时，条件里写了“之前”却没有事件编号的，只警告，不报错。现有卡片里有这几条：
- 潘姆：新房子盖好之前。
- 科罗布斯：14 心事件。当时以为游戏导出里没有编号；2026-10-21 在 `Beach` 事件里查到是 `7771191`，已补上（`legacy-cleanup.md` §6）。

另外有一条要改卡：德米特里厄斯那条“任何时候：不知道玛鲁在造机器人（看过玛鲁的 10 心事件 10 之前）”写错了。应该改成“看过玛鲁的 10 心事件（事件 10）之前：……”，因为他在那个事件里亲眼见过机器人。

### 3.3 渲染

```ts
render(id, view): { stable: string; gated: string }
// view: { hearts, seenEvents, relation, purpose: 'dialogue' | 'scene', includeGifts }
// relation: 'stranger' | 'friend' | 'dating' | 'engaged' | 'married' | 'roommate'
```

- `stable`：身份与背景、性格、说话风格、示例台词、人际关系、喜好。只随卡片文件变化，放在 prompt 前面，能命中前缀缓存。`purpose: 'scene'` 时省略示例台词，省约 70 token（M2 才用到）。
- `gated`：当前心数够得着的话题、当前生效的禁忌、特殊条件；`includeGifts` 时加上可送物品。随心数和事件变化，放在 `stable` 后面。

### 3.4 重新加载

原型在启动时加载，命令行里用 `/reload` 手动重新加载。解析失败时保留旧版本并打印错误。监听文件变化、自动重新加载放到 M2。

## 4. 一次对话调用

### 4.1 prompt 布局

按“越稳定越靠前”排，和设计文档 §9.2 一致：

1. 世界规则、文风、输出格式（所有 NPC 相同）
2. 角色卡 `stable`
3. 角色卡 `gated`
4. 世界状态：日期、季节、天气、时间、地点、关系状态，以及世界事实（第几年、肯特在不在、社区中心或 Joja 的进度、巴士修没修好、玩家性别和称呼等）
5. 记忆：原型里是空的，接口见 §4.3
6. 今天和这个 NPC 的对话，作为 user / assistant 消息
7. 玩家这一句

### 4.2 输出格式

使用服务商的 JSON 输出模式，模型只输出一个 JSON 对象，`reply` 放第一个字段：

```json
{"reply":"嘿。下雨天你也出门了？……我正打算去找青蛙。","emotion":"happy","options":["一起去吧","你喜欢青蛙？","我得回农场了"],"remember":[{"text":"玩家下雨天来找我聊天","importance":2}],"end":false}
```

台词仍然能一边生成一边显示：`ReplyStream` 从还没写完的 JSON 里逐字解出 `reply` 的值，转义符被切在两个分块之间也能处理。

最初的设计是“先写台词，再写一行 `@@`，最后一行 JSON”。实测 `deepseek-flash` 大多只输出台词、忽略后半部分，成功率 0/6 到 3/6，所以改成了 JSON 模式。JSON 模式在这个模型上有两个怪癖，已经处理：
- 开着推理、而 “json” 只出现在系统提示里时，模型只输出空白。所以玩家这一句后面附上“（用 json 回复）”，历史消息里不带。
- 即使这样，偶尔仍会输出空白。内容为空时自动重试一次，统计时把两次的 token 和耗时都算进这一轮。

- `emotion`：`neutral`、`happy`、`sad`、`blush`、`angry`、`special`，对应原版头像表情。
- `options`：下一轮给玩家的 3 个选项。
- `remember`：这轮要记住的事。原型里只打印出来，不写入。
- `end`：NPC 主动结束对话。
- 解析失败时：用已经显示出来的台词作为回复，给 3 个通用选项，并记一次格式失败。
- 历史消息里只保存回复正文，不保存 JSON，省 token。

### 4.3 记忆接口

```ts
interface DialogueMemory {
  context(query: string): Promise<{ summary?: string; memories: { text: string }[] }>;
  remember(items: { text: string; importance: number }[]): Promise<void>;
}
```

原型用空实现。两条线合并后，用 `NpcAgent.context()` 和 `record()` 实现这个接口，`dialogue.ts` 不用改。

## 5. 模型客户端（最小版）

- 配置从 `.env` 读：`NPC_MODEL_ENDPOINT`、`NPC_MODEL_NAME`、`NPC_MODEL_API_KEY`，另有可选的：
  - `NPC_MODEL_THINKING`：`disabled`、`low`、`high`（默认）、`max`。`disabled` 发送 `thinking: {type: disabled}`，其余发送 `reasoning_effort`。
  - `NPC_MODEL_TIMEOUT_MS`：默认 60000。原型里放宽，是为了量出真实耗时，不把回复截断。
  - `NPC_MODEL_MAX_TOKENS`：默认 4000，包含推理 token。
- 当前配置：DeepSeek 官方接口，模型 `deepseek-flash`（DeepSeek-V4.1-Flash），推理强度 `high`。
- 请求 `{endpoint}/chat/completions`，`stream: true`，并要求在流的最后返回用量。
- 还没收到响应就断开的连接错误（比如 TLS 握手时被重置），最多重试 2 次；超时不重试。
- 每次调用记录：首字延迟、总耗时、输入 token、输出 token、缓存命中的输入 token。缓存命中数取服务商返回的字段，比如 DeepSeek 的 `prompt_cache_hit_tokens`；没有这个字段就记为空。
- 不做：排队、限流、`dialogue` / `background` 两个档位。这些在 M2 的模型网关里做。

## 6. 命令行

```sh
node tools/chat.ts abigail --scenario rainy-spring --hearts 4 --seen 1,2
```

- 输入数字选选项，输入其他内容就是“自己说”。
- 斜杠命令：

| 命令 | 作用 |
|---|---|
| `/hearts N` | 设置心数 |
| `/seen 4`、`/unseen 4` | 标记事件看过 / 没看过 |
| `/relation dating` | 设置关系 |
| `/world key=value` | 改世界状态或世界事实 |
| `/prompt` | 打印上一次发出的完整 prompt |
| `/stats` | 本次会话的 token、延迟、格式失败次数 |
| `/reload` | 重新加载角色卡 |
| `/reset` | 清空今天的对话 |
| `/save` | 把对话记录写到文件 |

- 批量探测：`node tools/chat.ts --probe abigail` 依次发送 `tools/chat/probes/abigail.md` 里的题目。对话和每轮的 token、延迟写到 `.runtime/transcripts/<时间>-<npc>.md`，方便人工看。
- 场景文件（JSON）包含：日期、季节、天气、时间、地点、玩家名、玩家性别、农场名、世界事实、心数、已看过的事件、关系。

| 指标 | 目标 |

## 11. 实测结果（2026-10-18）

6 位 NPC、58 道探测题，`deepseek-flash`、推理强度 `high`：

| 指标 | 结果 | 验收线 |
|---|---|---|
| 格式 | 58/58，没有触发空白重试 | 至少 95% |
| 首字延迟 | 中位数 1.4–1.8 秒 | 中位数小于 2 秒 |
| 总耗时 | P95 2.6–4.9 秒，没有超过 8 秒的 | 95% 小于 8 秒 |
| 每轮输入 | 约 1400–1600 token，缓存命中 71–82% | 记录 |
| 每轮输出 | 约 90–130 token，其中推理 35–63 | 记录 |

剧透探测第一轮发现两处，都已修好并复测通过：
- 贾斯 4 心时被问到父母，说出了“他们不在了”。原因是这件事只写在“按心数解锁的话题”里，那里只管“不主动提”。修法：卡片支持“N 心之前”条件，给贾斯加了一条；规则里写明没解锁的往事被直接问到也不说具体内容。
- 谢恩没经历悬崖事件，却顺着玩家的问题承认“那天”发生过什么。修法：规则里写明，玩家说起没发生过的事，不要顺着承认。

还没解决的：
- **事件之后知道的事**：看过心事件后，对应的禁忌会解除，但模型并不知道事件里发生了什么。比如谢恩看过 7 心事件后本该在戒酒，他却说“昨晚就一瓶”。已在 §12 解决。
- 偶尔有小的事实错误，比如矮人说族里“就剩我一个了”，而他的卡片里写着火山里还有别的矮人。

对话记录在 `.runtime/transcripts/`（不进仓库）。

## 12. 看过事件之后知道的事（已实现）

§11 发现：看过心事件后，对应的禁忌会解除，但模型不知道事件里发生了什么，只能瞎猜。这一节给卡片补上这部分内容。

已确认的范围：
- 写现有禁忌引用的 116 个“NPC × 事件”，再加上其他 NPC 在场或合理会听说的事件，估计约 40 条。
- 只写不管玩家怎么选都会发生的部分。玩家选择带来的差别（比如艾利欧特写了哪类小说）等 M3 的 Mod 能回报选择时再加。

### 12.1 卡片写法

新增可选小节 `## 看过事件之后（可选）`，放在“不能说的内容”后面。每行一条：

```
- 事件 <编号>（标签）：发生了什么，以及之后会怎么提起
```

- **编号**：玩家看过这个事件，这条才进入 prompt。可以是自己的心事件，也可以是别人的事件。一条只写一个编号；一件事对应两个编号的（莉亚 8 心的艺术展 53 和网店 584059），分开写两条。
- **标签**：几心事件、谁的、在哪。模型看到的事件名就是它。
- **内容**：一两句，不超过 60 字，用第三人称。
- **别人的事件**：只写这个 NPC 在场看到的，或者按情理会听说的；不在场、也不太可能听说的不写。

### 12.2 渲染

- 放在 `gated` 部分，“现在可以聊的话题”后面，标题是“已经发生过的事”，只列玩家看过的事件。
- 和“不能说的内容”配合使用：禁忌在看过事件后解除，这一节补上解除之后能说什么。
- 现在写在话题里的“（看过 8 心事件后）……”这类条件，挪到这一节。

### 12.3 篇幅

每条约 40 token。实测全部事件都看过时，prompt 净增（新增条目减去解除的禁忌）：艾米丽 +506、谢恩 +438、阿比盖尔 +425，其余可结婚角色 200–350，其他 NPC 0–340。比最初估计的高一些，因为在场的别人的事件比预想多。这部分在缓存前缀之后，同一天的对话之间仍然能命中缓存。

### 12.4 校验

- 每条必须能解析出一个事件编号，同一张卡里编号不能重复。
- 编号不要求出现在“不能说的内容”里，因为在场的别人的事件通常没有对应禁忌。

### 12.5 样例：阿比盖尔

```
## 看过事件之后（可选）

- 事件 1（2 心，在她房间打游戏）：她打《草原王者大冒险》卡关发脾气，玩家陪她打了一局。她很感激，后来常说那局帮她过了第一关。
- 事件 2（4 心，雨天的深山）：她在雨中的树下吹长笛被玩家撞见，两人一起避雨，玩家拿出竖琴和她合奏了一曲。她把这当成两人的小秘密。
- 事件 4（6 心，深夜墓地）：她向玩家坦白一直在偷偷练剑、想去冒险。皮埃尔赶来叫她回家帮忙做饭，她气他只因为她是女孩就这样，拉着玩家跑开躲进灌木丛说悄悄话。
- 事件 3（8 心，灵板）：她写信请玩家晚上来房间玩灵板，灵板却暴露了她喜欢玩家。她又羞又慌地把玩家推出门，第二天一早跑到农场道歉。
- 事件 901756（10 心，矿井）：她想下矿探险，被一大群蝙蝠吓得缩在角落发抖，承认自己没有想象中坚强。玩家安慰她之后，她表白并亲了玩家。
- 事件 6963327（14 心，农场北边的小路）：玩家被灌木丛里窜出的怪物袭击晕倒，她冲上去杀了怪物，那是她第一次杀生。她让玩家以后小心，说不想失去玩家，还把怪物埋了。
- 事件 733330（山姆的 3 心事件）：之后山姆和塞巴斯蒂安邀请她来乐队当鼓手。她从没打过鼓，觉得挺有意思。
- 事件 4081148（山姆的 8 心事件，祖祖城的演出）：她和山姆、塞巴斯蒂安的乐队去祖祖城演出，她打鼓，玩家也来看了。
- 事件 2123243（艾米丽的 8 心事件，镇长家的服装疗法）：她参加了艾米丽办的服装疗法聚会，换上一整套盔甲，觉得很过瘾。
```

渲染进 prompt 后是这样（假设玩家看过事件 1、2、4）：

```
### 已经发生过的事
- 2 心，在她房间打游戏：她打《草原王者大冒险》卡关发脾气，玩家陪她打了一局。……
- 4 心，雨天的深山：她在雨中的树下吹长笛被玩家撞见……
- 6 心，深夜墓地：她向玩家坦白一直在偷偷练剑……
```

### 12.6 实现和实测

- 33 张卡共 201 条（桑迪没有相关事件）：自己的心事件，加上在场的别人的事件，比如服装疗法、艺术展、蛋糕走秀、山姆的演出、谢恩的几个事件。
- 艾米丽和刘易斯原来写在话题里的“（看过……后）”两条，已经挪进这一节。
- 测试保证：卡片里被禁忌隐藏的每个事件，在这一节都有对应条目，禁忌解除后不会出现空白。

## 13. 接入记忆系统（已实现）

目标：命令行里的 NPC 能记住跨轮、跨天的对话，存档和不存档的效果和游戏里一致。这一步只用记忆系统已有的接口（`createRuntime`、`saves.load`、`NpcAgent.context` / `record`、`prepare` / `confirm` / `startDay`、`returnToTitle`），不改记忆分支的代码。

### 13.1 每一轮读什么、写什么

| 时机 | 调用 | 内容 |
|---|---|---|
| 调用模型前 | `agent.context({ query: 玩家这句话, nowGameTime })` | 召回的记忆，以及今天和这个 NPC 的对话记录 |
| 拿到回复后 | `agent.record({ seq, gameTime, log, memories })` | `log` 是这一轮的原话 `{ player, npc }`；模型决定是否记和重要度，`memories` 正文取本轮玩家完整原话，记为 `private`（2026-10-21 来源修复见 `reliability-fixes.md`） |

- 今天的对话记录从记忆系统读，不再放在命令行的内存里。命令行重启后，同一天的对话还在，记忆系统的临时日志会恢复它。
- 不写 `state`。`state` 是整对象快照，现在没有需要它的字段，留给后面的计划和情绪。
- `seq` 由命令行按当前这次读档递增；重启后从当天已记录的最大序号接着编。
- 游戏时间按记忆系统的约定：`绝对游戏日 × 1440 + 当天分钟`，绝对游戏日由年、季节、日期算出。

### 13.2 进 prompt 的样子

记忆块放在“当前情况”之后、对话之前（设计文档 §9.2 的第 3 层）：

```
## 你记得的事
- （3 天前）玩家说她最喜欢下雨天
- （今天）玩家答应下次带紫水晶来
```

- 召回上限：6 条、600 个字符，约 400 token。记忆系统的默认值是 8 条、4000 字符，对一轮对话来说太多。
- 召回分两路：按玩家这句话做相关检索，加上最近的 3 条。记忆系统的相关检索要求词面匹配，没对上词时一条都没有，所以要给最近的记忆留位置。
- 今天的对话最多带最近 10 轮，更早的靠召回补。

### 13.3 命令行里模拟存档

存档身份保存在 `.runtime/chat/<存档名>.json`：谱系 ID、这次读档的 nonce、当前游戏日、最近一次确认的提交 ID。新增命令：

| 命令 | 对应游戏里的 | 记忆系统里做的事 |
|---|---|---|
| `/sleep` | 睡觉并存档 | `prepare` + `confirm` 新提交，`startDay` 进入第二天，日期前进一天 |
| `/rollback` | 不存档退回标题，再读档 | `returnToTitle` 丢弃今天的内容，换一个新的 nonce，从上次存档重新读 |
| `/quit` | 后端被关掉 | `runtime.close()`，保留临时日志；下次用同样身份启动会恢复今天的对话 |
| `/memories` | — | 打印这个 NPC 现在能召回的记忆，调试用 |

- `--save <名字>` 选存档，默认 `cli`；`--fresh` 开新存档。数据库放在 `.runtime/chat/memory.sqlite`。
- 有存档时，日期以存档为准，场景文件只提供天气、地点和世界事实。
- 批量探测仍然不带记忆，每道题互相独立。

### 13.4 代码位置

- `src/agent/dialogue-memory.ts`（新文件）：用 `NpcAgent` 实现 `DialogueMemory`，负责格式化“几天前”、截取最近 10 轮、分配 `seq`。
- `DialogueMemory` 接口调整：`context` 同时返回今天的对话，`remember` 改为 `record(exchange, remembered)`，一次写入这一轮的原话和要记住的事。
- `tools/chat.ts`：加存档命令；没有 `--no-memory` 时默认接入记忆。

### 13.5 测试

离线，用假模型和真实的记忆运行时（临时目录）：
- 一轮对话写入原话和记忆，下一轮的 prompt 里能看到它们。
- `/sleep` 之后，第二天还能召回昨天的记忆，并显示为“1 天前”。
- `/rollback` 之后，今天的对话和记忆都没了，昨天存档前的还在。
- 关掉运行时再用同样身份打开，今天的对话恢复，`seq` 接着往下编。
- 流式返回到一半连接断开：还没显示台词就重试，已经显示了一部分就报错。

### 13.6 实现中发现并修掉的问题

| 问题 | 原因 | 修法 | 实测 |
|---|---|---|---|
| 有历史对话后，常常只返回空白 | 历史里模型的回复是纯文本，而当前要求 JSON | 历史回复存成 `{"reply":"…"}` | 空白从 4/6 降到 0/6 |
| 改完后模型只回 `{"reply":"…"}`，漏掉其余字段 | 模仿了历史回复的精简写法 | 玩家这句后面的提示列出全部字段 | 字段齐全从 3/6 升到 8/8 |
| 玩家说的喜好经常没被记住 | 规则对 `remember` 的描述太笼统 | 明确列出要记的：玩家的喜好、计划、承诺、经历、心里话 | 记下玩家爱好从 4/6 升到 7/8 |
| 用管道喂输入时，命令行读不到后面的行 | 等模型回复时 readline 已读完并关闭 | 改用异步迭代器逐行读取，未处理的行会缓冲 | 脚本化会话可以跑完 |
| 流式返回到一半连接被断开，程序崩溃 | 本机流量经过代理，连接偶尔被重置 | 还没显示台词就重试一次；命令行单轮失败只打印警告，这一轮不写进记忆 | 已加测试 |

### 13.7 实测

跨天会话（阿比盖尔，9 轮，格式 9/9，没有触发重试）：
- 第一天说“最喜欢下雨天”“下次送你紫水晶”，`/sleep`。
- 第二天问喜欢什么天气，答“下雨天嘛，你昨天说的”；问答应过什么，答“紫水晶呗……别赖账啊”。
- 说“打算卖农场搬去城里”后 `/rollback`，再问，答“搬走？我完全没听说”。这条记忆已经被丢弃。

6 位 NPC 的 66 道探测题重跑：格式 66/66，没有触发重试，首字中位数 1.5–1.8 秒，总耗时 P95 3.3–6.6 秒。谢恩“悬崖”那题回答在边缘（“我不太记得那天了”），上一轮是“哪有什么悬崖”，模型的回答有随机性。

## 14. 好感度影响对玩家的记忆（已实现）

已确认：好感度影响“想起多少”“忘得快慢”和“说起来的语气”，全部在读取时生效。写入不受影响，数据不丢，好感涨回来就能想起来。

### 14.1 分档

| 心数 | 召回上限 | 只想得起重要度 ≥ | 想得起多久以前的 | 语气 |
|---|---|---|---|---|
| 0–1 | 2 条 | 4 | 3 天内 | 模糊：“好像听你说过……” |
| 2–4 | 3 条 | 3 | 7 天内 | 有印象 |
| 5–7 | 5 条 | 2 | 28 天内（一季） | 记得清楚 |
| 8 及以上 | 6 条 | 不限 | 不限 | 记得很清楚，合适时会主动提起 |

- 正在约会、订婚、结婚或是室友，一律按最高一档。
- 今天的对话不受影响：刚说过的话总记得，照常放进历史。
- 重要度是模型写记忆时给的 1–5 分。

### 14.2 语气怎么进 prompt

记忆块的标题后面加一句说明，例如 0–1 心：

```
## 你记得的事（你和玩家还不熟，这些只是模糊的印象；提起时用“好像”“记不太清”这类说法）
- （2 天前）小林说她最喜欢下雨天
```

8 心及以上：“你很在乎玩家，这些都记得很清楚，合适时可以主动提起”。中间两档不加说明。

### 14.3 实现

- `DialogueMemory.context(query)` 改为 `context(query, standing)`，`runTurn` 把当前心数和关系传进去。
- 新增 `recallPolicy(standing)`，返回上表的一行，单独导出方便测试和调参。
- `AgentMemory` 先从记忆系统多取一些候选（相关 20 条、最近 10 条），按重要度和天数过滤，再按召回上限和 600 字符截取。
- 只改对话这一侧，不改记忆系统。

### 14.4 测试

- 同一组记忆，0 心只召回 3 天内、重要度 ≥ 4 的；8 心全部召回。
- 约会中即使心数低，也按最高一档。
- 低档的记忆块带“模糊”说明，最高档带“记得很清楚”，中间档不带。
- 今天的对话在 0 心时照样完整进入历史。

### 14.5 实测

阿比盖尔，同一段对话分别用 0 心和 8 心：第一天说“最喜欢下雨天”“下周一定给你带紫水晶”，第二天问一次，再睡 3 天，到第五天再问一次。

| | 0 心 | 8 心 |
|---|---|---|
| 第二天能想起的 | 一条都没有 | 昨天的两条都在 |
| 第二天问“答应过什么” | “我们才刚认识吧，我可不记得你欠我什么” | “当然记得！你说下周给我一块紫水晶” |
| 第五天开场 | 普通寒暄 | 主动提起“紫水晶的事我可还记着呢” |
| 第五天问“答应过什么” | “你可别随便编个承诺来糊弄我” | “我可是数着日子等的” |

- 同一句“送紫水晶”，模型在 0 心时给的重要度是 3，在 8 心时给的是 4。0 心只想得起重要度 4 及以上的事，所以两条都想不起来，“模糊”语气这次没有机会出现。
- 如果觉得 0 心太健忘，最简单的调法是把这一档的重要度门槛从 4 降到 3。2026-10-20 用户决定降到 3，见 `legacy-cleanup.md` §4。
