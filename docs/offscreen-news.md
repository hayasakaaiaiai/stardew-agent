# 自主行动第一步：玩家不在场时 NPC 也传话

> 状态：已实现，等 Windows 游戏内验收（2026-10-20）。分支 `m2c-offscreen-news`，建在 `m2b-npc-news` 上，目录 `/Users/a11/Documents/ChatGPT/stardew-agent-gifts`。对应 `design.md` §7 的“按时间自主行动，彼此互动”和 §7.5 的转述规则。

## 1. 效果

白天玩家送了阿比盖尔一块紫水晶。第二天傍晚，阿比盖尔在酒吧和格斯待了一个小时，格斯就知道了；晚上格斯回到镇上碰见潘姆，潘姆也听说了。第三天玩家找潘姆聊天，她可能会说：“听格斯说，你送了阿比盖尔一块紫水晶？”

整个过程不调用模型：游戏每到整点，Mod 告诉后端哪些 NPC 在玩家看不到的地方待在一起，后端用代码把前一晚决定好的新鲜事（`docs/npc-news.md`）传过去。

## 2. 决定

| 问题 | 决定 | 来源 |
|---|---|---|
| 第一步做什么 | 玩家不在场也传话 | 用户 2026-10-20 选择 |
| 传几手 | 当事人说出去算第一手；听到的人可以再转告别人一次，算第二手；第二手的不再往下传 | 用户选择“可以再传一手” |
| 每天多花的模型调用 | 0，只用代码 | 用户选择 |
| 什么算“待在一起” | 每个游戏整点看一次：室内同一张地图就算；室外 6 格以内，连成一片的算一组 | 推荐：酒吧、杂货店里的人一般都能互相听到，室外的镇子很大 |
| 玩家所在的地图 | 不算，留给看得见的碰面聊天（`npc-chat.md`） | 推荐：玩家就在旁边却没看到他们说话，会显得奇怪 |
| 一个小时传多远 | 只用整点之前已经知道的事来传，所以一小时最多往下走一手；同一屋里的人都直接听当事人说 | 推荐：避免一个小时里传遍全镇 |
| 同一件事听到两次 | 每个人对同一个当事人的新鲜事只记一次；第一手和第二手都有时听第一手 | 推荐 |
| 能传多久 | 只在写下它的第二天里传，和第八步一样 | 推荐：简单，不会传成陈年旧事 |
| 听的人记什么 | 第一手：`阿比盖尔跟我说："……"`，重要度 3；第二手：`格斯跟我说，阿比盖尔说过："……"`，重要度 2；都是 `heard`、`normal`，来源写当事人和转述的人 | 第二手不那么可靠，也就不那么重要；按心数的回忆门槛下，2–4 心的 NPC 不会想起第二手的事 |
| 看得见的碰面聊天 | 也可以说第二手的新鲜事（“阿比盖尔说过：……”）；只挑对方还不知道的 | 推荐：两边规则一致 |
| 正在“继续聊”时 | Mod 先留着这一小时，对话结束再发；期间又到整点就换成新的一份 | 和 `scene.shown` 同样的原因：当天事件的序号要保持顺序 |
| 回滚 | 写进当天事务，跟存档保存或回滚 | 已有机制 |
| 关掉 | Mod 配置 `OffscreenNews` | — |

## 3. 消息

Mod → 后端 `town.hour`：`groups`（几组游戏内名字，每组至少 2 人）、`date`。和生命周期消息一样可靠、等 `ack`，按序号去重；日期不是当前这天、名字不在 34 位里的，确认但不记，不停用 AI。

后端把这一小时里谁听到了什么写成一个当天事件：每位听的人一条变化，日志里是 `heard: [{ origin, from, share, hand }]`，供之后判断谁已经知道、谁还能往下传。

## 4. 成本

- 模型调用 0，token 0。
- 每个游戏日最多 20 条 `town.hour`（6:00 到 2:00 的整点），只有有人在一起时才发；后端读几位 NPC 的状态和当天日志，没有新鲜事就不写。
- 被想起时，每条传话记忆和其他记忆共用现有的条数和 600 字预算；按目前的写法一条约 25–40 token。

## 5. 改了哪些文件

| 文件 | 改动 |
|---|---|
| `src/agent/news.ts` | 新鲜事带上当事人和第几手；从当天日志读听到过什么；一小时内谁听到什么（纯函数 `spread`）；两种记忆的文字 |
| `src/agent/scene.ts` | 碰面聊天的新鲜事可以是第二手的，prompt 里写“阿比盖尔说过：……” |
| `src/bridge/memory.ts` | `gossip()` 读每人能说什么、已经知道什么；`townHour()`；写入时按“同一当事人只记一次”去重；碰面聊天改用同一套 |
| `src/bridge/protocol.ts`、`server.ts` | `town.hour` 的校验和处理；日志“镇上传话：格斯记下了：……” |
| `mod/.../Town.cs`（新）、`ModEntry.cs`、`ModConfig.cs`、`SaveSync.cs` | 整点找出在一起的人；不在“继续聊”时发；加进可靠消息；新的一天、读档、回标题时清空 |

不改记忆内核和数据库表；协议版本仍是 3。

## 6. 测试

`tests/offscreen-news.test.ts` 4 项，完整 `npm test` 134/134，类型检查和构建通过；Mod Release 编译 0 警告、0 错误。
- 能说什么：自己的新鲜事和第一手听来的；第二手的不再往下传；不会把当事人自己的事告诉他。
- `spread`：同屋的人都直接听当事人说；一小时不连传；第一手优先；每人只记一次。
- `town.hour` 的校验。
- 整条链路：夜里写下新鲜事；第二天 18:00 阿比盖尔和格斯在一起，格斯记第一手；19:00 格斯和潘姆在一起，潘姆记第二手（同组里不认识的名字被忽略）；重发这一小时只记一次；20:00 潘姆和山姆在一起，山姆听不到；另一天的整点不起作用；潘姆的“继续聊”里有这条；格斯在碰面聊天里转述给塞巴斯蒂安，塞巴斯蒂安记第二手；不保存退出后全部作废。

## 7. Windows 游戏内测试清单（用户来做）

1. 切到 `m2c-offscreen-news`，重新编译安装 Mod，`npm run bridge`。
2. 第一天和阿比盖尔“继续聊”并送她喜欢的东西，睡觉保存。
3. 第二天待在农场，不去镇上。后端日志里，整点后出现“镇上传话：……记下了：阿比盖尔跟我说……”，再晚些可能出现“……跟我说，阿比盖尔说过……”。
4. 第三天去找听到的人“继续聊”，问“最近听说什么了吗？”：他们可能提起。
5. 正在“继续聊”时跨过整点：这轮对话正常，关掉对话后日志里才出现镇上传话。
6. `config.json` 里把 `OffscreenNews` 改成 `false`：不再有镇上传话。
