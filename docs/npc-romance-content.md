# 恋爱约会内容与角色依据

2026-11-09。本文件对应 [约会资料](../data/romance/profiles.json)，覆盖原版 12 位可恋爱角色。这里只新增菜单文案和角色化的约会建议，不改角色卡、原版事件、人物往事或游戏物品。完整行为、同步与测试结果以本轮恋爱功能 spec 为准。

## 1. 数据契约

顶层为 12 项数组，每项字段如下：

| 字段 | 含义与使用边界 |
|---|---|
| `id` | 角色小写 ID；与既有角色卡及原版 NPC 名称的小写一致 |
| `name` | 中文角色名 |
| `opening` | 玩家主动提出约会时，NPC 给出的原创回应；没有接受某个日期前不写成已约好 |
| `invitation` | NPC 提议安排约会的原创短句；不预设玩家已接受，也不虚构过去的约会 |
| `closing` | 实际达到完成门槛、当场结束时的原创反馈；包含“今天”的台词只适用于当场，旧回忆展示应使用记录中的源日期 |
| `venues` | 恰好两个不同地图，每项为 `map` 与菜单 `label`；地图白名单为 `Forest`、`Beach`、`Town`、`Mountain` |
| `focus` | `quiet` 或 `talk`，用于推荐相处方式，不是已经安静相处／实际聊天的事实 |
| `references` | 依据文件的仓库相对路径；角色卡承接已整理的性格与语气，Wiki 文件承接原版背景、日程、兴趣依据 |

后端与 Mod 使用同一份 JSON。角色 ID、地点范围、字段和文字安全由程序校验，不能因替换数据就让未知 NPC 成为恋人或执行新的物品动作。所有菜单文字均为新写，未照抄游戏或 Wiki 台词。

## 3. 事实与关系边界

- 恋爱资格由原版 `dating`、`engaged`、`married` 判断；普通高心朋友与 `roommate` 不使用这些恋爱菜单和台词。
- 表达方式可以推荐安静或聊天；完成事实只基于实际计时、地图、同在场及真实游戏事件。选择“聊聊”不能自动生成聊过某个话题的记忆。
- 回忆里的日期、地点、天气、时长由原生事实提供。玩家选择的 `place`、`weather`、`company` 只是记忆重点，不创造事件。
- 原创邀请不预设晴天、下雨、特定季节或已经见到动物。选择海滩也不保证沙滩上的特定位置、对象或过场出现。
- 新约会不是原版心事件，不能解锁角色卡里需要“已看事件”的往事，不越过角色卡的保密和剧情限制。
- 多人交往不自动推断排他承诺；没有“永远只爱你”“其他人都不重要”之类与原版当前事实可能冲突的静态文案。
- 未记录过的交往起点、第一次接吻、旧周年不补写。首次记录指本功能首次真实完成的约会，不等于角色人生中第一次约会。
- 文案不附赠物品，不新增图片、照片、雕塑、乐曲或动画。Mod 使用原版对话框、选项和表情；角色卡继续提供普通自由聊天的语气。

内容结构检查包括：12 个 ID 恰好覆盖本轮名单且不重复；每人两个不同白名单地图；`quiet`／`talk` 范围；文字非空、长度有限且无原版控制字符；所有 `references` 路径实际存在。程序侧严格校验与全仓测试由实现集成时执行，不能将内容文件通过检查写成游戏内约会已通过。
