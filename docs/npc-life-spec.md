# NPC 生活功能完整开发 spec

> 2026-11-09。用户已明确要求按 spec 自主连续实现三类功能、无需中途确认，完成后由用户统一游戏内测试。此授权覆盖先前设计确认门及必要既有文件接入。H 线、推送和合并 main 不在授权内。

## 1. 交付范围

| 类别 | 本轮必须完成 |
|---|---|
| 可完成玩法 | 莉亚 3 浮木三阶段故事；以相同机制承载威利、玛鲁有资料依据的小委托；明确接取、真实扣料、后续活动、完整／提前结束结局、感谢信、存档回滚 |
| 人物状态、关系与故事 | 34 位 NPC 都能依据真实生活事件保留情绪与信任；明确失约后的道歉修复；原版好友同场分享真实共同活动，只有实际听到的人得到记忆；阶段变化影响后续对话 |
| 陪伴与家庭 | 森林散步、一起采集、陪钓鱼、共同烹饪、配偶外出散步、家庭晚餐。活动有入口、开始、客观完成条件、取消、回日程、事实记忆和持久恢复 |

“全量”指三类中本表列出的功能全部接入可运行的产品流程，不以方案、孤立函数或静态演示代替实现。不是给 34 人各写一篇虚构人物剧情。委托的角色与材料依据记录在内容资料中；卡片事实及原版事件不擅改。

## 2. 执行顺序与完成门

1. **S0 公共基础**：有限事件格式、持久生活日志、分批可靠同步、当前读档屏障、原版菜单入口、后端原子写入。
2. **S1 可完成玩法**：接取与真实材料交付、三阶段目标、活动关联、两种结局、每日一封感谢信。
3. **S2 人物与社交**：情绪／信任、真实失约与道歉、有来源的好友传话，接入实际聊天 prompt。
4. **S3 活动与家庭**：六类活动、原版消耗与行为、配偶兼容、取消及日终收尾。
5. **S4 完整验收**：Node 语义和 WebSocket/SQLite 集成测试、类型检查、构建、Mod Release 编译、适用的离线 C# 检查、token 实测、文档及游戏内测试清单。

可以并行编写独立模块，按上述依赖顺序整合。发现单点问题优先保留复现并继续独立部分，交付前解决影响本表的阻断项。测试与编译通过不能写成真人游戏体验已通过。

## 3. 共同基础契约

Mod 是已执行游戏行为的事实来源。新的生活事件只使用固定 kind 及经过校验的参数，不允许自由文本触发物品／奖励。

`LifeEvent` 字段：`id`、`npc`（小写名单 ID）、`day`（绝对游戏日）、`kind`；可选 `goal`、`activity`、`item`、`count`、`minutes`、`other`、`sourceId`、`friendship`。ID 为 `life-<serial>`；递增序号与游戏一起保存回滚。`friendship` 仅记录 Mod 已实际应用的活动好感，与聊天共用每 NPC 每日 -40/+30 范围；原约定失约已发 `meet.ended`，不再次携带或扣除好感。

kind 白名单：`goal.accepted`、`goal.delivered`、`goal.completed`、`goal.closed`、`activity.completed`、`activity.cancelled`、`activity.missed`、`social.shared`、`relationship.apology`。新事件模块校验所有取值范围与种类组合。

生活日志保留已发生记录，不能按内存 ACK 删除，避免保存后断联退出丢事实。分批至多 32 条：`life.sync {events, final}`；每批经现有 envelope 校验、记录后 ACK，最后一批回 `life.ready`。无记录也发空 final 探针。重连／读档先重放日志，目标同步完成前不开放新生活动作和带生活上下文的对话。

后端在每位 NPC 当前存档分支的 `log.lifeState` 中保存生活投影和已处理 serial 高水位，旧批次重放不重复变信任或写记忆。新旧 loadNonce 不能交叉应用，事件按源日保留事实；补同步不重做物品和好感动作。生活日志如达安全上限（4096 条），明确暂停新生活动作，保留原记录，不静默截断。

通过现有记忆事务一次写入日志、observation 和生活投影，不写 NPC 的整体 state，不改 SQLite schema、M1 内核、密钥或游戏原文。读取先查当天日志，再沿当前提交祖先找最近生活投影，按 head/NPC 缓存已提交结果。这样稍后完成的夜间印象、计划不会被生活状态快照遮住。协议版本仍为 3，后端 hello 增加 `lifeProtocol:1` 独立确认能力；新 Mod 面对不支持生活消息的后端明确提示升级，普通聊天保持可用。

## 4. 玩法规则

莉亚沿用已确认的一次交齐消耗 3 块浮木、不限期、无额外礼物。原版菜单承担接取、交付、立即活动、改天、提前关闭；普通送礼不抵交付、不占送礼次数。材料身份从原版数据核对，交付回调重新检查背包、读档身份、阶段、容量，失败不扣。

| 角色／目标 ID | 一次消耗 | 后续实际活动 |
|---|---|---|
| 莉亚 `leah-driftwood-v1` | 3 块浮木（原版内部名 `Driftwood`） | 森林同行累计 30 游戏分钟 |
| 威利 `willy-catfish-v1` | 1 条鲶鱼（`Catfish`） | 陪钓鱼累计 20 游戏分钟，并实际钓到至少 1 条鱼 |
| 玛鲁 `maru-copper-v1` | 1 块铜锭（`Copper Bar`） | 森林观察自然，同行累计 30 游戏分钟 |

角色和材料依据见 §9。每个目标在每条存档分支只能完成一次，重约不重收。Mod 内部活动携带 `goalId@attemptId`，发往后端时只保留白名单 goal；旧尝试无法终结新尝试，普通活动不能误完成故事。首次接取需 8 心、非配偶／室友；后续目标同行需 09:00–17:00、可用原版日程、开启赴约和同行。玩家带 NPC 实际走到活动地点，不自动完成或跳到目的地。

已接取目标的查看和退出入口不因心数下降／结婚消失。交付后可以选择只保留材料结局，不编造未发生同行。谢信按真实结局固定原创措辞，原版信箱投递，全 Agent 每天最多一封，由 Mod 实际入箱处统一裁决；故事信未寄出则持久顺延。没有附赠物品。

## 5. 人物与关系规则

信任为有限档位 -3 至 3，仅生活事件改变，不代替原版心数。情绪包含原因与到期日，专门提示最长 3 日，之后保留事实记忆。实际完成每天每 NPC 最多增加一次信任；明确失约留下最多 3 条未修复记录。道歉只让对应记录进入等待行动状态，不立刻加好感／信任；之后实际完成生活活动才逐步修复，每天最多一次。普通取消或材料结局不当作失约。未交料／待同行目标即使超过 3 日仍有阶段提示。

好友分享必须双方和玩家同图且相互距 8 格内，玩家二次确认；来源是最近 7 日内可公开的实际完成事件并关联 `sourceId`。名单为莉亚／艾利欧特、山姆／塞巴斯蒂安、山姆／阿比盖尔、塞巴斯蒂安／阿比盖尔、玛鲁／潘妮、艾米丽／桑迪，来自已有角色卡关系。只写发送者和实际接收者记忆，不能把传闻变成听者亲历或自动扩散到全镇；家庭餐、配偶散步和私密的道歉修复不传播。同一来源对同一听者不重复写记忆。

生活上下文包装现有 `MemoryContext`，保留旧印象。只给正在对话的该 NPC 当前有效的摘要，不把整个生活日志常驻 prompt，不额外调用模型。实际分词与输出效果分别报告。

## 6. 活动规则

| 活动 ID | 客观完成条件 |
|---|---|
| `forest_walk` | 双方在森林真实同行、近距离累计 30 游戏分钟后结束 |
| `foraging` | 同行期间玩家真实采集至少 1 件，且有效同行至少 20 游戏分钟 |
| `fishing` | 同行期间玩家真实钓获至少 1 条鱼，且有效同行至少 20 游戏分钟 |
| `cooking` | 双方在场，原版烹饪菜单使用玩家已知配方和材料实际产出至少一道菜 |
| `spouse_walk` | 配偶可外出实际同行 30 游戏分钟，结束后恢复日程，不受旧普通地点拒绝配偶的规则误挡 |
| `home_dinner` | 玩家和配偶／室友同在农舍，玩家明确选择交出一份符合条件的熟食，真实扣除后记录家庭餐叙 |

原版菜单、表情和跟随路径复用；不增加美术或自绘 UI。所有活动检测地图、剧情、节日、日终、玩家取消、NPC缺失；暂停区间不计时，不用开始结束两个时间戳相减猜有效时长。活动终止释放角色控制并恢复日程；延迟回程绑定原 nonce／日，日终丢弃，新约定接管后取消旧回程。断线或等待 ACK 时仍能用原版菜单结束当前活动，禁止新动作与接续做饭。物品产物走原版机制，不免费生成。

独立活动需 8 心或配偶／室友，普通日 09:00–19:00 开始。采集角色为莉亚、莱纳斯、艾米丽、桑迪、雷欧；钓鱼角色为威利、艾利欧特、莱纳斯、塞巴斯蒂安或配偶。烹饪在升级农舍的原版厨房完成，使用已知配方和背包／冰箱材料。农舍内结束散步可接续做饭，NPC 暂驻等待原活动同步确认，Esc、离图、日终或 25 秒超时释放控制。

普通约定和生活活动共用每天 3 次启动额度（惊喜拜访沿用既有豁免），失败启动退回额度；同一 NPC 同一已成功活动每天一次。家庭餐也占一次，必须消费 CookingCategory 且可食的熟食。活动好感沿用现有分档；关闭 `MeetingsChangeFriendship` 后仍保留事实和态度。

## 7. 验收矩阵

- 基础：格式非法、NPC隔离、未来日期、重复／乱序、旧nonce、后端重启、新连接全量重放、取消迟到结果、保存／回滚／分叉。
- 目标：不足材料、多堆扣除、重复菜单、普通礼物、各阶段退出、重复约定、普通活动不能完成目标、材料结局、婚后退路、信件去重与日额度。
- 关系：每类事件态度、信任上下限、3日到期、取消不惩罚、道歉不可刷、非好友拒绝、来源不存在拒绝、秘密不传播、听者身份准确。
- 活动：六类完整开始到结束、实际物品消耗／产出、临界时间、离图、远离、菜单与剧情暂停、重约、配偶路径、日终和回程。
- Prompt：旧印象保留、未完成不写成完成、非相关NPC不带、各阶段token对照；真实模型不保证正确，证据与离线结论分开。

用户在 Windows 进行全量真机测试；开发阶段不自动启动游戏或修改用户存档。最终报告列出全部开关、入口、前提、操作步骤、预期、已验证层级及仍需用户验证内容。

### 实现时的调整

- 初稿的 `state.life` 改为原子日志 `log.lifeState`：独立回归复现了“第 2 天先写生活、保存后第 1 天夜间印象才完成”会遮挡新印象的问题。改为日志后不再覆写记忆内核 state。
- 不新增任意日期的目标约定；交料后选择“现在一起去／改天再去”，实际同行走现有原版跟随。暂停、未达成、配偶状态改变均可回到待同行或材料结局。
- 没有真实模型调用，也没有更改通用角色扮演规则。新增的是与当前 NPC 有关的事实摘要，实际生产函数分词见下节。
