## 1. 安装、入口和前置

保留正常游戏存档、Mod 和后端数据备份。按本分支 README 编译部署；新 DLL 与新 JSON 必须来自同一提交。不要用调试跳时来代替真实钟步，不在正常存档上测试旧版本覆盖。三分支内容可用独立副本或明确回滚到选择前的副本分别测试。

退出测试游戏与后端，执行：

```powershell
git fetch origin
git switch codex/npc-long-goals
git pull --ff-only
npm ci
```

再按 README 更新完整 Mod，并从同一分支启动 `npm run bridge`。保留原 `.env` 和成对的游戏／后端测试数据；不要只替换 DLL 遗漏 `assets/long-goals.json`，也不要将已产生长线历史的存档覆盖回旧版验收副本。

## 3. 六个真实工作日

“工作日”指实际满足条件的游戏日，不等于连续自然日。示例：第 D 天开启，第 D+1、D+2 天完成第一章；第二章最早 D+3、D+4；第三章最早 D+5、D+6。每天的阶段必须在同一个允许工作地图中累计满 30 分钟，且前后阶段不能落在同一天。

| ID | 操作与预期 | 结果 |
|---|---|---|
| W01 | 开启当日不计第一阶段；次日正常钟步才可开始。第一阶段完成当日继续等待，不会再完成第二阶段。 | |
| W02 | 七项目各记录六个阶段的游戏日、工作地图及完成时刻；每章两日严格不同，总计至少六个工作日。 | |
| W03 | 前章完成当日不能为下一章观察、汇报、交料、选方案或工作；次日开启这些入口，不必另行接取。 | |
| W04 | 允许地图内正常静止 10、20 分钟仍不完成；同日同图累计到 30 分钟才完成一个阶段。 | |
| W05 | 未满 30 分钟时换工作地图，即使新旧地图都允许，也从新地图重新累计；已完成阶段不丢失。 | |
| W06 | 未满 30 分钟跨日，旧日分钟清零；完成的第一阶段保留，下一日仍需新满 30 分钟完成第二阶段。 | |
