# 主动靠近与赴约的 Windows 脚本验收

用户要求继续测试新推送，沿用此前“手测部分写脚本测”的授权。目标为 `m2c-approach / e8ec3c3`、`m2c-meetings / 9c4ca4a`，保留 `770af1d` 的事实回答和此前 Windows 修复；不合入 main，不部署正常安装。

沿用独立 `World` 副本、配置身份校验、原档 SHA256 和实际原版进程。新增 `actions` 章节：直接调用生产挑选／监视入口，走路由原版控制器更新，保存和重读使用游戏流程。受控日程、名单、时间与关系用于覆盖边界，和夜间整合到实际动作的整条链路分别报告。NPC 的移动轨迹逐秒保留，不能用直接改坐标冒充寻路到达。

主动靠近和第一条完整赴约链路使用正常速度；后续八地点的路线拓扑检查把测试 NPC 的步速从 2 调到 8，到达后恢复 2。这些场景沿用 World 的固定时钟，由脚本推进到检查时刻；路线仍由原版控制器执行并真实切换地图，只核对去回落点和衔接，不据此宣称自然时钟下准时。

另加 `actions-timing`：用原版路线走到出发前一站，再打开游戏自然时钟，等待原版时间推进触发赴约路线；记录实际抵达时刻，核对不晚于约定。仍使用步速 2，去程不手动触发 `checkSchedule`。该样本和八地点拓扑检查分开报告。正常游戏不会调用这些测试命令。

`actions-incoming` 从 12:50 打开自然时钟，覆盖原有 13:00 路线尚未结束、赴约路线到点排队的情况。`actions-checks` 直接检查原版排队数、靠近结束后自动接管的原版控制器，再只观察它到达，不能用之后手动启动路线证明自动恢复；另留清楚可见的招呼画面。`actions-places` 可单独重跑八地点，生产规划修复后无需重复不相关的靠近条件矩阵。

- 主动靠近：走到旁边、等候、原路返回、交谈结束、玩家离图、日程到点排队及恢复；心数、配偶、已经聊过、忙碌、临近下一站、时间、地图、开关及每日额度。
- 赴约：八个地点的原版去／回路线、到达和招呼、未来日程保留；同地点容量、开关、迟到、无日程和配偶；可靠结果重放、未到达不记、保存及回滚。
- 后端：检查 `seek`／`meet` 来源、时间与答复边界，模拟错误模型结果及协议消息，复核真实模型有限样本和 o200k 成本。测试不改变正常 prompt；发现缺陷时先保留失败证据，修复及成本另列。

最终计数、失败记录、实际执行范围和人工体验的剩余边界写入本轮报告与 `docs/status.md`。
