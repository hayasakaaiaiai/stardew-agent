## 2. 开关、角色和入口

配置文件为游戏 `Mods\StardewAgentBridge\config.json`。首次运行可生成配置；修改后退出并重启游戏验证。旧配置没写的新字段按默认开启处理。

| 开关 | 全量测试设置 | 作用 |
|---|---|---|
| `OfferContinueChat` | `true` | 原版 NPC 台词结束后出现扩展选择框 |
| `SharedGoals` | `true` | 三个角色的共同目标接取、交付和出发 |
| `LifeActivities` | `true` | 独立活动和家庭餐入口 |
| `LifeSocial` | `true` | 当面道歉、好友在场分享 |
| `NpcMeetings`、`MeetingsGoTogether` | 均 `true` | 故事同行和独立同行/烹饪的启动前提 |
| `MeetingsChangeFriendship` | `true`，另测一次 `false` | 活动沿用赴约好感规则；与 `ChatChangesFriendship` 分开 |
| `SendLetters` | `true`，另测关闭后重开 | 故事信及原有 Agent 信投递 |
| `NpcMineCompanion` 等旧功能开关 | 保留原设置；回归时开启对应项 | 验证原有矿洞、农活及聊天流程 |

## 3. 每天安排和共同限额

普通约定与生活活动启动共用每天最多 3 次。每次成功启动的故事同行、森林散步、采集、钓鱼、烹饪各占一次；家庭餐成功也占一次。已经开始后提前结束仍占次数。接取、材料交付、查看进度、道歉和分享不占同行启动次数。厨房没有成功打开的初始失败不占次数。同一 NPC、同一种已经完成的独立活动当天不能再刷。

建议按实际游戏日拆分，不要求一天塞完：

| 测试日/副本 | 建议安排 | 预算 |
|---|---|---|
| A 第一天 | 三人接取/交料；莉亚故事同行；一次采集 | 2 次，预留 1 次边界测试 |
| A 第二天 | 威利故事钓鱼；玛鲁故事森林同行 | 2 次，预留 1 次取消测试 |
| A 第三天 | 非配偶从外面同行回农舍，接续做饭 | 外出与烹饪合计 2 次；不要先用完额度 |
| B/C 家庭日 | 配偶/室友散步、原版做饭、家庭餐 | 合计 3 次；也可分两天测试 |
| 后续普通日 | 好友分享、道歉与实际兑现、原有约定回归 | 道歉/分享不占次数，后续兑现占活动次数 |
| 恢复副本 | 目标提前结局、断线、回滚、信件额度 | 从对应恢复点分别测试，避免已关闭目标不可重接影响其他项 |

| 编号 | 步骤 | 预期 | 结果 |
|---|---|---|---|
| D01 | 同日用普通约定和生活活动合计占满 3 次，再尝试第 4 次 | 第 4 次不能启动；没有新控制器、扣料或额外活动好感 | |
| D02 | 一项生活活动刚开始便提前结束，再检查可用次数 | 不退还这次启动额度；不会记成失约 | |
| D03 | 对同一 NPC 完成一种独立活动，再次尝试同种活动；次日再试 | 当天拒绝，次日恢复；故事结局不因次日刷新而可重复完成 | |
| D04 | 分别关闭和开启 `MeetingsChangeFriendship` 完成同类活动 | 关闭时活动仍能完成但不加赴约好感；开启时沿用原有日上限，故事交料/结局本身不额外加点 | |
| D05 | 同一天对同一非配偶 NPC 聊天并完成多次不同活动 | Agent 好感增量共用每日最高 +30；原版上限/书籍效果可能使实际增量更少。日志只记录实际改变量 | |

## 5. 六类活动的真实完成和取消

独立活动入口为原版台词后的“一起做点事”。开始时段均为 09:00–19:00，家庭餐也遵守此时段。同行和烹饪还要求 NPC 至少 8 心或为配偶/室友、非节日剧情、没有同 NPC 的未结束普通约定，开启赴约与一起逛；家庭餐要求配偶/室友同农舍和实际熟食。最多同时一项活动。分钟只按双方近距离、符合地点条件的正常时钟推进累计，不能靠暂停菜单或调时补算。

| 编号 | 活动与步骤 | 预期 | 结果 |
|---|---|---|---|
| A01 | 任一合格非配偶选“去森林散步”；到森林并保持 8 格内累计 30 分钟，结束 | 只森林内有效区间计时；达到条件才完整完成；普通散步不替代故事阶段 | |

## 6. 情绪、好友分享和关系修复

可分享的是最近 7 天内已经完成的公共活动或目标。家庭散步、家庭餐不公开。允许的原版好友对为：莉亚↔艾利欧特、山姆↔塞巴斯蒂安、山姆↔阿比盖尔、塞巴斯蒂安↔阿比盖尔、玛鲁↔潘妮、艾米丽↔桑迪。角色必须实际同图，分别距玩家不超过 8 格，彼此也不超过 8 格。两人是否恰好同场取决于日程；本清单不要求用文本把另一人“叫到现场”。

| 编号 | 步骤 | 预期 | 结果 |
|---|---|---|---|
| S01 | 分别在接取、交付、进行中、完成、提前关闭阶段与当事 NPC 自由聊天 | 其上下文能区分实际阶段；未交料不称交过，未完成同行不称完整完成；不自动推进目标或扣物 | |
| S02 | 与未参与、未听到消息的另一 NPC 询问这段事 | 不获得本轮生活事件的亲历或自动传闻记录；模型若自行编造，单独记录为内容问题 | |
| S03 | 完成莉亚公共活动后，等莉亚与艾利欧特真实在场，选“和在场的朋友聊聊共同经历”→“一起聊聊” | 只有确认后分享；当事人和在场朋友有反馈；听者之后应以“听说/听对方说”而不是亲历来谈 | |
| S04 | 对另外五个好友对，在合格的实际场景重复分享 | 每一对都按实际发送者/接收者归属；不会串成另一位朋友的来源 | |
| S05 | 同场陌生组合、朋友不在附近、只有玩家口头说朋友在场，分别尝试分享 | 无合格分享入口或不执行；没有远程传播或全镇同步记忆 | |
| S06 | 打开分享确认后选“这次不说”；已分享同一来源后重复尝试 | 取消不产生听闻；同一事件不重复发给同一听者 | |
| S07 | 只完成家庭散步/家庭餐后寻找好友；另测试超过 7 天的旧公共活动 | 家庭私事不进入候选；过期来源不作为本次新分享候选 | |
| S08 | 用原有约定系统明确约好，确保 NPC 实际到场等待，玩家不去且等候结束 | 才产生真实失约与失落；仅取消约定、拒绝邀约、提前结束生活活动不产生失约 | |
| S09 | 之后当面选“为之前失约道歉”，确认一次，再重复尝试 | 道歉本身不增加原版好感或直接抹掉矛盾；当天重复道歉被阻止 | |

| S11 | 有失约但没有道歉就完成活动；另找从无失约的 NPC | 前者不把未处理的失约自动抹掉；后者不出现可刷信任的无事道歉入口 | |
| S12 | 当天已经完成过活动，再道歉并完成第二项；次日再实际完成 | 同日不绕过一次信任结算；仍待修复的记录可在之后实际兑现时修复 | |
| S13 | 事件后连续过 3 个以上游戏日再聊天 | 短期情绪提示到期，不持续声称“刚刚发生”；真实历史仍可按记忆召回 | |

S04 可在结果栏逐对记“山姆/塞巴斯蒂安；山姆/阿比盖尔；塞巴斯蒂安/阿比盖尔；玛鲁/潘妮；艾米丽/桑迪”。如果模型没有主动提到一条记忆，不能仅凭“没说”判定记忆缺失；结合明确询问和日志判断。信任是有限内部状态，不是新画出来的心形进度条。

## 8. 断线、重启、保存和回滚

这里的“断线”指停止后端进程，保留 SMAPI 游戏运行；“重启后端”是从同一个测试代码目录重新执行 `npm run bridge`。等待同步恢复后再判断新动作是否可用。不要通过删除 `.runtime`、改存档身份或清空 Mod 数据来代替重连。

| 编号 | 步骤 | 预期 | 结果 |
|---|---|---|---|
| R01 | 菜单已经打开时停止后端，再确认接取、交付或新的活动 | 新生活动作被同步/连接前提挡住；不发生半次交付或离线新开活动 | |
| R02 | 已经开始并接近达标的同行中停止后端，继续满足条件，让活动自然结束 | NPC 释放，已发生结果在游戏侧保留；断线不伪造失约；不能因此重复加好感 | |
| R03 | R02 后不退出游戏，重启后端并等待恢复，和 NPC 交谈 | 补回真实完成事实，恢复新动作；只补日志，不再扣料、加点、发第二次完成奖励 | |
| R04 | 已接取或交付后，停止后端，正常睡觉保存；退出两端后重新启动并读档 | 已保存的材料和目标进度保留并可恢复同步；日志仍可证明先前实际交付 | |
| R05 | 后端停止期间完成活动并保存，随后退出，再重连读档 | 保存过的完成事件可以重放；没有丢失生活记录或保留孤立跟随 NPC；若原存档同步保护报错，保留错误和两侧数据检查，不自动判通过 | |
| R06 | 在早晨已保存恢复点之后，接取/交付/完成任意动作，直接退出到标题且不睡觉；重新读同一早晨 | 当日未保存的物品消耗、目标、好感及生活事实一起回滚；不凭后端旧 ACK 保留未保存剧情 | |
| R07 | 当天先保存过阶段，再做后续未保存动作并退出 | 恢复到最后保存的阶段，既不退回更早阶段，也不保留未保存完成或信件 | |
| R08 | 活动或做饭接续等待时退出到标题，再读另一测试存档 | 旧菜单、旧 NPC 控制和延迟回调不进入新档；另一档没有旧人物故事状态 | |
| R09 | 同一已保存进度连续重启后端两次、读档两次 | 记忆、信任、物品、好感、信箱和每日启动次数不因重放重复增加 | |
| R10 | 恢复较早的游戏及对应记忆副本，另走完整/提前结束分支 | 新分支只承认自己的事实；旧尝试完成不结束新尝试，普通活动不误完成目标 | |
| R11 | 只在隔离测试环境用不支持生活能力的旧后端连接新版 Mod | 明确提示升级，生活入口不可用；不假装已完成生活同步；原有聊天兼容流程不被永久锁死 | |
| R12 | 正常保存并退出后，下一天检查 NPC 日程、启动额度和已有目标 | 新的一天活动次数刷新；目标与信件持久状态保留；没有续算昨天的未完成活动分钟 | |
| R13 | 已有活动进行中停止后端，与这位 NPC 再交谈，首层选“结束当前活动”，内层选择结束 | 首层只有“结束当前活动”/“离开”，内层可继续或结束；结束后 NPC 回日程，可保存真实完成或提前结束结果。不能趁断线开始新活动、接续做饭、聊天或分享 | |
| R14 | 接续做饭等待确认时停止后端，与同一 NPC 交谈，选“结束当前活动”→“结束这次等待” | 等待菜单另有“再等等”；原生退出、Esc、超时都能释放 NPC。不打开新厨房，不多扣一次启动 | |
