# 节日记忆

> 状态：已实现，等 Windows 验收（2026-10-21）。分支 `festival-memories`，建在 `group-events` 上，目录 `/Users/a11/Documents/ChatGPT/stardew-agent-gifts`。对应 `design.md` 状态表里“节日本身作为世界事件记入观察”。和设计稿不一样的地方见 §10。

## 1. 效果

花舞节上玩家请阿比盖尔跳了舞。第二天找她聊天，她记得和农场主一起跳了舞；塞巴斯蒂安也记得“看到农场主和阿比盖尔跳了舞”。冬日星盛宴上玩家抽到给潘妮送礼，潘妮记得是农场主送的。复活节的彩蛋大寻宝阿比盖尔又赢了，在场的人都记得农场主没赢。

和送礼记忆（`npc-gifts.md`）一样：Mod 发一条可靠消息，后端按模板给在场的 NPC 各记一条，不调用模型，跟当天保存或回滚。

## 2. 决定

| 问题 | 决定 | 来源 |
|---|---|---|
| 记哪些 | 花舞节舞伴；冬日星盛宴秘密礼物；比赛结果（复活节彩蛋大寻宝、冰雪节钓鱼比赛、星露谷展览会展台名次）；夏威夷宴会州长对汤的评价 | 用户 2026-10-21 选择 |
| 谁记 | 节日里实际出现的 NPC（节日事件里的演员）。结果说的就是他的人（舞伴、送礼的两人、赢的 NPC、短裤的主人刘易斯）不管 Mod 有没有在演员里看到都记 | 用户选择；后半句是实现时补的 |
| 记不记到场 | 不记。月光水母之舞、万灵节这种没有结果的节日不写记忆；没有结果时 Mod 也不发消息 | 用户选择 |
| 什么时候发 | 节日结束、玩家离开会场的那一刻发 `festival.ended`；结果在节日进行中边看边记下来。中途离场就只发已经发生的结果。正在“继续聊”时先不发，聊完再发（和 `town.hour` 一样，保证当天事件的顺序） | 推荐：节日结束后原版的事件对象就没了，有的结果只能在进行中读 |
| 写法 | 按模板，用 NPC 自己的视角，不写相对日期（回忆时自动加“3 天前”）。旁观的人写明“我看到”；赢了比赛的 NPC 写“我赢了” | 和送礼记忆一样；“我看到”见 §8 |
| 不知道是谁干的 | 汤难喝到州长晕倒、汤里有镇长的紫色短裤，原版刘易斯也不知道是谁放的，所以只写看到的结果 | 不把没确定的事算到玩家头上 |
| 种类 | `observation`，可见性 `normal`（节日上大家都看得见）；夜间整合原样保留，和送礼记忆一样 | — |
| 协议版本 | 不变：旧后端不认识就忽略（Mod 的可靠队列会一直补发，所以 Mod 和后端要一起更新，和 `town.hour` 一样） | — |
| 关掉 | Mod 配置 `FestivalMemories` | — |

## 3. 每项结果怎么读、记什么

所有结果都从原版的 `Game1.CurrentEvent`（`isFestival` 为真）和玩家对象上读，不改游戏代码，不用 Harmony。位置都在游戏 1.6.15 的 `Event`、`Farmer` 里核对过。

**节日开始和结束**：`Game1.CurrentEvent` 就是当前地点的 `currentEvent`；换到节日临时地图时原版把同一个事件对象带过去。Mod 看到 `id` 为 `festival_<节日>` 的事件就开始记，`isFestival` 变成假（原版 `exitEvent` 会这样设）就算结束。展览会的钓鱼小游戏会把玩家换到自己的地图上，但把节日事件一起带过去；为防别的情况，节日对象不再是当前事件时，要等到连事件都没有了（`Game1.eventUp` 为假）才算结束。结束过的节日对象当天不再记第二次，所以不会重复发。在场的人是节日期间出现在 `actors` 里的 34 位中的人，取并集。

### 3.1 花舞节（`spring24`）舞伴

- **怎么读**：原版答应跳舞时设 `Game1.player.dancePartner`，当天一直保留。正式跳舞要等玩家找刘易斯开始主活动，所以 Mod 等主活动脚本执行过 `playMusic FlowerDance` 那条命令，才读舞伴；只约了舞伴就离场不算。舞伴是别的玩家时不记。
- **记什么**：

| 谁 | 记忆 | 重要度 |
|---|---|---:|
| 舞伴 | 花舞节上农场主邀请我跳舞，我们一起跳了。 | 4 |
| 其他在场的人 | 花舞节上我看到农场主和阿比盖尔跳了舞。 | 2 |

### 3.2 冬日星盛宴（`winter25`）秘密礼物

- **怎么读**：节日开始时原版抽好 `secretSantaRecipient`（玩家要送给谁）和 `mySecretSanta`（谁送玩家）。玩家把礼物交给对方后，原版把 `secretSantaRecipient` 清空（`chooseSecretSantaGift`），接着播放送礼人给玩家礼物的场面（`doingSecretSanta` 为真）。原版搭这个场面时，抽到的送礼人不在会场就换成刘易斯，所以送礼人在场面开始后再读。这份礼物走 `receiveGift(..., updateGiftLimitInfo: false)`，不进原版的每日送礼计数，现在的送礼记忆抓不到。
- **记什么**（送的什么东西读不到，不写）：

| 谁 | 记忆 | 重要度 |
|---|---|---:|
| 收到玩家礼物的人 | 冬日星盛宴上农场主抽到给我送礼，送了我礼物。 | 3 |
| 给玩家送礼的人 | 冬日星盛宴上我抽到给农场主送礼，礼物送到了。 | 3 |

## 4. token

写入时不调用模型，固定成本 0，正常对话的 prompt 不变。被想起时每条（含“- （3 天前）”）按 o200k 实测 **22–32 token**，24 种文字平均约 26（用 `festivalMemories` 实际产出的文字量）。最长的是汤“少了一个人的材料”32、旁观者看到短裤 31。

| 改动 | 每条 token |
|---|---:|
| 设计稿样句 | 18–29（只量了 8 句） |
| 实现初版（“刘易斯镇长”） | 20–36 |
| “刘易斯镇长”改“镇长”、汤里短裤改成“汤里有……” | 20–30 |
| 旁观者加“我看到”（§8） | 22–32，每条旁观者记忆 +2 |

按现在的回忆规则（`dialogue-memory.ts` `recallPolicy`）：8 心以上或亲密关系全都想得起；5–7 心重要度 2 以上、28 天内；2–4 心重要度 3 以上、7 天内；0–1 心重要度 3 以上、3 天内（`legacy-cleanup` 把门槛从 4 降到了 3）。所以比赛名次、普通的汤只有 5 心以上才想得起；秘密礼物、短裤、州长晕倒 0 心也能在 3 天内想起。

## 5. 消息

Mod → 后端，可靠消息，后端回 `ack`：

```json
{"type":"festival.ended","lineageId":"…","loadNonce":"…","seq":57,
 "festival":"spring24","npcs":["Abigail","Sebastian","Lewis"],
 "dance":"Abigail","santa":null,"contest":null,"grange":null,"soup":null,
 "date":{"year":1,"season":"spring","day":24,"time":2200}}
```

| 字段 | 值 |
|---|---|
| `festival` | `spring13`、`spring24`、`summer11`、`fall16`、`winter8`、`winter25` 之一 |
| `npcs` | 节日里出现过的 34 位里的人，游戏名，最多 64 个 |
| `dance` | 舞伴的游戏名，没跳就是 `null` |
| `santa` | `{"recipient":"Penny","giver":"Lewis"}`，没送成就是 `null` |
| `contest` | `player` 或 `npc`（阿比盖尔/威利赢），别的玩家赢或没比就是 `null` |
| `grange` | 1–4（4 是没名次）或 `"shorts"`，没摆展台或没评就是 `null` |
| `soup` | 0–6，没尝汤就是 `null` |

七个字段都要有，值为 `null` 或在范围里，否则整条消息被拒。后端只认和 `festival` 对得上的字段（比如 `dance` 只在 `spring24` 有效）；名字不在 34 位里的忽略，秘密礼物两边有一个不认识就整项不记；日期不是当天的只回 `ack` 不写。所有人的记忆作为一个事件写进当天事务，日志里每人一行“节日：阿比盖尔记下了：……”。

## 8. 真实模型抽测

`deepseek-flash`，推理 `high`，把一条节日记忆以“（3 天前）”放进对话 prompt，问一句相关的话。原始输出在本机 `.runtime/festival-probes/`。

**第一轮**（旁观者模板还没有“我看到”）6 题各 2 次，输入 20,998（缓存 15,616）、输出 1,644 token，1.7–3.2 秒：

| 题 | 结果 |
|---|---|
| 塞巴斯蒂安，旁观跳舞 | 2/2 “去了。站在边上看了会儿”，看到玩家和阿比盖尔跳舞 |

## 9. Windows 游戏内测试清单（用户来做）

先跑 C# 流程检查，应为 21/21。用存档副本，在 SMAPI 控制台用 `world_setseason`、`world_setday` 把日期改到节日当天，9 点后进会场；SMAPI 日志（Trace）里有“节日 … 结束，… 位在场，结果已交给后端记住”，后端日志有“节日：……记下了：……”：
1. 花舞节：请一位候选人跳舞并看完舞蹈。第二天问舞伴和旁边的人都记得；只约舞伴就离场时不记。
2. 冬日星盛宴：把礼物交给抽到的人，看完对方送礼。两人都记得；后端日志里送礼人和场面里给你礼物的是同一人。
3. 复活节、冰雪节：各赢一次、输一次（输时原版是阿比盖尔、威利领奖），在场的人记得结果，赢的 NPC 说“我赢了”。
4. 展览会：摆展台等刘易斯评完；再试一次在展台里放紫色短裤；再试一次一样都不摆（不记）。
5. 夏威夷宴会：分别放好东西和不放东西，看州长的反应和记忆的档位是否一致。
6. 节日当天不睡觉读档，记忆消失。
7. 想关掉：`config.json` 里把 `FestivalMemories` 改成 `false`，节日后后端没有“节日：”日志。

## 10. 和设计稿不一样的地方

- **旁观者写明“我看到”**：第一轮真实模型里塞巴斯蒂安 2/2 说自己没去花舞节（§8）。每条旁观者记忆 +2 token。比赛那几句顺带把语序改成“复活节上我看到农场主赢了彩蛋大寻宝”，赢的 NPC 也用同样的语序。
- **“刘易斯镇长”改成“镇长”，汤里短裤那句改成“汤里有……”**：意思不变，最长从 36 降到 30（加“我看到”后 32）。
- **秘密礼物的送礼人在送礼场面开始后再读**：设计稿写节日一开始就记下两人。原版搭场面时抽到的人不在会场会换成刘易斯，早读会记错人。
- **结果说的就是他的人总会记**：设计稿只说“节日里出现的人”。舞伴、送礼两人、赢的 NPC、刘易斯即使 Mod 没在演员里看到也记，因为原版脚本就是让他们做了这件事。
- **没有结果就不发消息**：设计稿没写。只到场、中途离开前什么都没发生时，Mod 不发 `festival.ended`。
- **秘密礼物有一边名字不认识就整项不记**：避免只记一半。
- **正在“继续聊”时先不发**：和 `town.hour` 一样，聊完再发。
- **秘密礼物送了什么仍然不写**：原版 `chooseSecretSantaGift` 不把物品存下来，模型被问起时可能自己补一样东西（第一轮潘妮补了“摆在床头”）。
