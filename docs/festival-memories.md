# 节日记忆

> 状态：设计稿，等用户确认后再写代码（2026-10-21）。分支 `festival-memories`，建在 `group-events` 上，目录 `/Users/a11/Documents/ChatGPT/stardew-agent-gifts`。对应 `design.md` §6.6 “节日本身作为世界事件记入观察”。

## 1. 效果

花舞节上玩家请阿比盖尔跳了舞。第二天找她聊天，她可能会说“昨天跳舞的时候你踩了我一脚没？”；塞巴斯蒂安也记得“农场主和阿比盖尔跳了舞”。冬日星盛宴上玩家抽到给潘妮送礼，潘妮记得是农场主送的。复活节的彩蛋大寻宝阿比盖尔又赢了，在场的人都记得农场主没赢。

和送礼记忆（`npc-gifts.md`）一样：Mod 发一条可靠消息，后端按模板给在场的 NPC 各记一条，不调用模型，跟当天保存或回滚。

## 2. 决定

| 问题 | 决定 | 来源 |
|---|---|---|
| 记哪些 | 花舞节舞伴；冬日星盛宴秘密礼物；比赛结果（复活节彩蛋大寻宝、冰雪节钓鱼比赛、星露谷展览会展台名次）；夏威夷宴会州长对汤的评价 | 用户 2026-10-21 选择 |
| 谁记 | 只有节日里实际出现的 NPC（节日事件里的演员） | 用户选择 |
| 记不记到场 | 不记。月光水母之舞、万灵节这种没有结果的节日不写记忆 | 用户选择 |
| 什么时候发 | 节日结束、玩家离开会场的那一刻发 `festival.ended`；结果在节日进行中边看边记下来。中途离场就只发已经发生的结果 | 推荐：节日结束后原版的事件对象就没了，有的结果只能在进行中读 |
| 写法 | 按模板，用 NPC 自己的视角，不写相对日期（回忆时自动加“3 天前”）；赢了比赛的 NPC 自己写“我赢了” | 和送礼记忆一样 |
| 不知道是谁干的 | 汤难喝到州长晕倒、汤里有镇长的紫色短裤，原版刘易斯也不知道是谁放的，所以只写“有人” | 不把没确定的事算到玩家头上 |
| 种类 | `observation`，可见性 `normal`（节日上大家都看得见）；夜间整合原样保留，和送礼记忆一样 | — |
| 协议版本 | 不变：旧后端不认识就忽略（Mod 的可靠队列会一直补发，所以 Mod 和后端要一起更新，和 `town.hour` 一样） | — |
| 关掉 | Mod 配置 `FestivalMemories` | — |

## 3. 每项结果怎么读、记什么

所有结果都从原版的 `Game1.CurrentEvent`（`isFestival` 为真）和玩家对象上读，不改游戏代码，不用 Harmony。位置都在游戏 1.6.15 的 `Event`、`Farmer` 里核对过。

### 3.1 花舞节（`spring24`）舞伴

- **怎么读**：原版答应跳舞时设 `Game1.player.dancePartner`，当天一直保留。正式跳舞要等玩家找刘易斯开始主活动，所以 Mod 看到主活动的脚本（含 `playMusic FlowerDance`）开始播放，才算真跳了；只约了舞伴就离场不算。
- **记什么**：

| 谁 | 记忆 | 重要度 |
|---|---|---:|
| 舞伴 | 花舞节上农场主邀请我跳舞，我们一起跳了。 | 4 |
| 其他在场的人 | 花舞节上农场主和阿比盖尔跳了舞。 | 2 |

### 3.2 冬日星盛宴（`winter25`）秘密礼物

- **怎么读**：节日开始时原版抽好 `secretSantaRecipient`（玩家要送给谁）和 `mySecretSanta`（谁送玩家）。玩家把礼物交给对方后，原版把 `secretSantaRecipient` 清空，紧接着播放送礼人给玩家礼物的场面（`doingSecretSanta`）。Mod 在节日一开始记下这两个名字，看到前者被清空就算两边都送了。这份礼物不走原版的每日送礼计数，现在的送礼记忆抓不到。
- **记什么**（送的什么东西读不到，不写）：

| 谁 | 记忆 | 重要度 |
|---|---|---:|
| 收到玩家礼物的人 | 冬日星盛宴上农场主抽到给我送礼，送了我礼物。 | 3 |
| 给玩家送礼的人 | 冬日星盛宴上我抽到给农场主送礼，礼物送到了。 | 3 |

### 3.3 比赛结果

- **复活节（`spring13`）彩蛋大寻宝**、**冰雪节（`winter8`）钓鱼比赛**：原版宣布名次时把分数最高的玩家放进 `festivalWinners`（私有字段，用 SMAPI 反射读），没人达到门槛（单人彩蛋 9 个、钓鱼 5 条）时设 `specialEventVariable1`，接着分别播放阿比盖尔、威利领奖的脚本。Mod 在 `festivalWinners` 第一次有内容的那一刻读这两个值。

| 结果 | 在场的人记 | 赢的 NPC 自己记 | 重要度 |
|---|---|---|---:|
| 玩家赢 | 复活节的彩蛋大寻宝农场主赢了。 | — | 2 |
| 玩家输 | 复活节的彩蛋大寻宝阿比盖尔赢了，农场主没赢。 | 复活节的彩蛋大寻宝我赢了，农场主没赢。 | 2 |
| 玩家赢 | 冰雪节的钓鱼比赛农场主赢了。 | — | 2 |
| 玩家输 | 冰雪节的钓鱼比赛威利赢了，农场主没赢。 | 冰雪节的钓鱼比赛我赢了，农场主没赢。 | 2 |

  多人游戏里别的玩家赢了的情况不记。

- **星露谷展览会（`fall16`）展台**：刘易斯评完后原版设 `grangeJudged`，分数在 `grangeScore`：90 以上第一、75 以上第二、60 以上第三，其余没名次；展台里摆了刘易斯的紫色短裤时是 −666。玩家没摆展台（`grangeDisplay` 为空）就不记。

| 结果 | 在场的人记 | 刘易斯自己记 | 重要度 |
|---|---|---|---:|
| 第一到第三 | 星露谷展览会上农场主的展台得了第一名。 | — | 2 |
| 没名次 | 星露谷展览会上农场主的展台没评上名次。 | — | 2 |
| 紫色短裤 | 星露谷展览会上农场主在展台里摆了刘易斯镇长的紫色短裤。 | 星露谷展览会上农场主在展台里摆了我的紫色短裤。 | 3 |

### 3.4 夏威夷宴会（`summer11`）汤的评价

- **怎么读**：原版尝汤后跳到 `governorReaction0`–`6` 中的一段脚本，结果不存下来。Mod 把正在播放的脚本和节日数据里这 7 段（`Event.ParseCommands` 解析后）逐条比对，对上哪段就是哪档。
- **记什么**（在场的人记，刘易斯自己视角的那句用“我的”）：

| 档 | 原版 | 记忆 | 重要度 |
|---:|---|---|---:|
| 0 | 有人放了脏东西，州长晕倒 | 夏威夷宴会上州长喝了汤，说太难喝，当场晕了过去。 | 3 |
| 1 | 很恶心 | 夏威夷宴会上州长喝了汤，嫌味道恶心。 | 2 |
| 2 | 很普通 | 夏威夷宴会上州长喝了汤，说味道很普通。 | 2 |
| 3 | 好喝 | 夏威夷宴会上州长喝了汤，夸汤很好喝。 | 2 |
| 4 | 最好 | 夏威夷宴会上州长喝了汤，说从没喝过这么好喝的汤。 | 2 |
| 5 | 有人没放材料 | 夏威夷宴会上州长喝了汤，说味道淡了，好像少了一个人的材料。 | 2 |
| 6 | 汤里有紫色短裤 | 夏威夷宴会上有人把刘易斯镇长的紫色短裤放进了汤里，州长气坏了。 | 3 |

## 4. token

写入时不调用模型，固定成本 0。被想起时每条（含“（3 天前）”）o200k 18–29 token。按现在的回忆规则，重要度 2 的要 5 心以上、28 天内才想得起；3 的 2 心以上、7 天内；4 的 0 心也能在 3 天内想起。

## 5. 消息

Mod → 后端，可靠消息，后端回 `ack`：

```json
{"type":"festival.ended","lineageId":"…","loadNonce":"…","seq":57,
 "festival":"spring24","npcs":["Abigail","Sebastian","Lewis"],
 "dance":"Abigail","santa":null,"contest":null,"grange":null,"soup":null,
 "date":{"year":1,"season":"spring","day":24,"time":2200}}
```

| 字段 | 值 |
|---|---|
| `festival` | `spring13`、`spring24`、`summer11`、`fall16`、`winter8`、`winter25` 之一 |
| `npcs` | 节日里出现过的 34 位里的人，游戏名 |
| `dance` | 舞伴的游戏名，没跳就是 `null` |
| `santa` | `{"recipient":"Penny","giver":"Lewis"}`，没送成就是 `null` |
| `contest` | `player` 或 `npc`（阿比盖尔/威利赢），别的玩家赢或没比就是 `null` |
| `grange` | 1–4（4 是没名次）或 `"shorts"`，没摆展台或没评就是 `null` |
| `soup` | 0–6，没尝汤就是 `null` |

后端只认和 `festival` 对得上的字段（比如 `dance` 只在 `spring24` 有效），名字不在 34 位里的忽略，日期不是当天的只回 `ack` 不写。

## 7. 测试

用假模型和临时数据库：
- 模板：每个节日每种结果的文字和重要度；赢的 NPC 用“我”；刘易斯的短裤用“我的”。
- 后端：只给消息里在场的人写；和节日对不上的字段、不认识的名字忽略；日期不对不写；重复的消息只写一次；没保存就读档，记忆跟着回滚。
- 协议：缺字段、值不在范围里的消息被拒。

C# 流程检查：结果快照在节日结束时打包成消息，换天清空。读游戏状态的部分只能在 Windows 上测。

## 8. Windows 游戏内测试清单（用户来做）

用存档副本，在 SMAPI 控制台用 `world_setseason`、`world_setday` 把日期改到节日当天，9 点后进会场：
1. 花舞节：请一位候选人跳舞并看完舞蹈。后端日志有“节日：……记下了”，第二天问舞伴和旁边的人都记得；只约舞伴就离场时不记“一起跳了”。
2. 冬日星盛宴：把礼物交给抽到的人，看完对方送礼。两人都记得。
3. 复活节、冰雪节：各赢一次、输一次（输时原版是阿比盖尔、威利领奖），在场的人记得结果。
4. 展览会：摆展台等刘易斯评完；再试一次在展台里放紫色短裤。
5. 夏威夷宴会：分别放好东西和不放东西，看州长的反应和记忆是否一致。
6. 节日当天不睡觉读档，记忆消失。
7. 想关掉：`config.json` 里把 `FestivalMemories` 改成 `false`。
