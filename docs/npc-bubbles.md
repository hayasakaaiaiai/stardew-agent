# M2b 第二步：头顶气泡和表情

> 状态：已实现，Windows 脚本验收及三处修复完成（2026-10-20）。上游分支 `m2b-bubbles`；Windows 验收分支 `codex/bubbles-windows-tests`，目录 `E:\stardew-agent`。未合入 `main`。对应 `design.md` §8 的 `bubble`、`emote`，结果见 [Windows 报告](test-results/2026-10-20-bubbles-windows.md)。

## 1. 效果

第二天，玩家在镇上走到某个 NPC 附近时，NPC 头顶冒出一句自言自语，同时做一个原版表情。比如前一晚约好做风筝，阿比盖尔会嘀咕“得把材料凑齐才行。”，头上冒个感叹号；邀请还没被答应，她嘀咕“矿洞的事，他会答应吗？”，头上冒个问号。

这是自主行动里风险最小、又能看见效果的一步：只显示，不改好感、物品、日程等存档状态，也不写进任何人的记忆。

## 2. 决定

用户在 Windows 上测 M3a，要求“继续做”，并且此前授权“全部按推荐来、不再问”。以下按推荐方案定，用户随时可以改。

| 问题 | 决定 | 其他方案和不选的原因 |
|---|---|---|
| 台词在哪生成 | 夜间整合时顺带写，和计划放在一起 | 白天按游戏小时实时调用模型：每小时一次场景调用约 2000–3500 token，一天约 5 万，比当天的对话还贵 |
| 谁有气泡 | 前一晚整合过的 NPC，也就是前一天和玩家聊过的 | 所有 NPC 都要写的话，没聊过的也得调一次模型 |
| 每人几句 | 0–2 句，每句不超过 20 字 | 头顶气泡一屏只显示一行多，长了看不完 |
| 有效期 | 只在计划的第二天用（`state.day + 1 === 今天`），和次日开场一样 | — |
| 什么时候显示 | 玩家和 NPC 在同一张地图、相距 5 格以内，玩家可以自由行动（没在对话、菜单、剧情里）；同一个 NPC 两句之间至少隔 1 个游戏小时；每句一天只出现一次 | — |
| 表情 | 每句配一个：happy、heart、question、exclamation、sad、music、none，对应原版表情 | — |
| 写不写记忆 | 不写。气泡只是显示，NPC 之后不会“记得自己嘀咕过” | 记下来会进入当天日志和第二晚的整合，等于让 NPC 把自己的猜测当事实 |
| 隐私 | 不限制提到玩家私下说的事 | 气泡只有玩家自己看得见，也不进任何 NPC 的记忆，不存在传话。等以后 NPC 之间能“听见”气泡，再加限制 |
| 安全 | 规则要求不写已经做了什么、东西备好之类的进展，不写相对日期，没约好不说约好；代码再过滤一遍，不合格的句子直接丢掉 | 只靠规则：次日开场的实测里，模型偶尔仍会写出“已经带来” |
| 读档和回滚 | 台词存在提交的 NPC 状态里，跟着存档点走；读旧档就是那个存档点的台词 | — |
| 协议 | 后端多一种消息 `day.bubbles`；Mod 不认识时直接忽略，协议版本不变 | — |

## 3. 给模型的规则

在夜间整合规则的 `plan` 后面加一条，输出示例里加上 `bubbles`：

```
- bubbles：明天农场主在镇上走近你时，可能会听见你随口嘀咕。写 0–2 句，每句不超过 20 字，是自言自语，不对谁说话；只说心情、打算或想弄清的事。不写已经做了什么、东西已经备好之类的进展，不写“今天、明天、昨天”这类日子；没约好的事不说成约好了。emote 从 happy、heart、question、exclamation、sad、music、none 里选一个配合这句话。没什么可说就写 []。
```

代码过滤：去掉原版文字会当作指令的字符（`^ # $ @ % { } * [ ] |`）和表情符号；超过 24 字的、含“已/已经/昨晚/昨夜/刚才”或相对日期（大前天到大后天）的句子丢掉。Windows 反例测试发现“竹条扛来了”会绕过原完成词规则，现保守丢弃含“了”的句子，愿望句“就好了”除外；表情不在列表里按 none。此规则可能丢掉正常句子，也不能覆盖所有无“了”的完成说法，不是完整事实校验。

## 4. 实测

`deepseek-flash`，整合 `low`，用 `tools/nightly/facts-fixtures.ts` 的 5 组样例（就是夜间整合修复说话人错误时用的那 5 组：原失败案例、未答应的邀请、拒绝和未完成、已答应的约定、引文里的伪标签），每组 2 次。

| | 不加气泡 | 加气泡 | 差 |
|---|---:|---:|---:|
| 输入 token（DeepSeek 计费） | 769–800 | 903–934 | 每组都是 +134 |
| 输出 token，10 次平均（含推理） | 319 | 428 | +109，主要是推理，波动大 |
| 规则本身（o200k） | — | 141 | — |

规则在 system 里，同一晚第二个 NPC 起能命中前缀缓存。每晚只有和玩家聊过的 NPC 才整合，所以按一晚 3 个 NPC 算，大约多 400 输入、330 输出 token；白天显示不花 token。

10 次输出逐条看过，都可以用：

| 样例 | 输出 |
|---|---|
| 原失败案例 | “紫色的猫……会是什么样子呢”；“要是我爸不过敏就好了” |
| 未答应的邀请 | “矿洞的事，他会答应吗？” |
| 拒绝和未完成 | “一个人去墓地也不坏。”；“纸船，慢慢来就好。” |
| 已答应的约定 | “紫色风筝该用什么纸才好？”；“得把材料凑齐才行。” |
| 引文伪标签 | “矿洞一个人去会不会太冒险？”；“要不要找个伴呢……” |

没有出现已经做了什么的说法、相对日期，也没有把没答应的事说成约好。表情都在列表里。第一版规则里写了“不说出农场主私下告诉你的事”，有一次仍写了猫名“星糖”；按 §2 的理由去掉了这条，第二版就是上面的规则。

## 5. 改哪些文件

| 文件 | 改动 |
|---|---|
| `src/agent/bubbles.ts`（新） | 气泡的类型、表情列表、过滤、按日期取当天的气泡 |
| `src/agent/nightly.ts` | 规则加 `bubbles`；解析、过滤后写进 NPC 状态 |
| `src/bridge/protocol.ts` | `day.bubbles` 消息 |
| `src/bridge/memory.ts`、`src/bridge/server.ts` | 读档就绪、新的一天开始、当晚整合完成时，把当天的气泡发给 Mod |
| `mod/.../Bubbles.cs`（新）、`ModEntry.cs`、`SaveSync.cs`、`config.json` | 收气泡；玩家走近时显示文字和表情；可以在配置里关掉 |

- 不改记忆内核、数据库表、对话 prompt。
- 整合完成通常比第二天开始晚几秒，所以整合完成时会再发一次；Mod 收到新的一份就替换，已经显示过的不再显示。
- Windows 修复：异步读取固定提交、日期和发送版本，较旧的空结果不能覆盖较新的整合结果；Mod 跳过异常行和错误类型的字段，保留同包有效台词。

## 6. 测试

用假模型和临时数据库：

- 解析：合格的句子保留；超过 2 句截掉；进展说法、相对日期、超长的句子丢掉；表情不对按 none；没有 `bubbles` 字段时当作没有，不影响记忆和计划。
- 整合后 NPC 状态里有气泡；读档就绪和新的一天开始时，Mod 收到当天有效的气泡，过期的不发。
- 整合晚于新的一天开始：整合完成后 Mod 再收到一次。

Mod 端在 Mac 上只能编译（Release 0 警告、0 错误，用到的原版表情常量、`showTextAboveHead`、`Utility.CalculateMinutesBetweenTimes` 都编译通过）；显示效果要在 Windows 上看（§7）。C# 流程检查不调用新增的方法，应仍是 13/13。

结果：86 个测试（原 84 个 + 气泡解析过滤 1 个 + 发送时机 1 个）、类型检查、构建通过。

## 7. Windows 游戏内测试

用户明确要求自行写脚本测，已按此覆盖游戏内显示和真实保存链路。复现命令：

```powershell
# 两句固定数据，实际启动游戏；验证显示、距离、阻塞、冷却与读档，不调用模型。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test-game-memory.ps1 -BubblesOnly
# 真实模型 + 三次睡觉保存，同时检查 Mod 收到当前提交的气泡。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test-game-memory.ps1 -MorningPlans
```

均先创建随机命名副本、备份并检查原档哈希。最终 90/90 Node、16/16 C#、Release 0 警告 0 错误。固定数据游戏验收 16.86 秒，12 项行为及 3 项画面捕获通过，2 次读档、0 次保存、0 次调用；真实模型验收 97.46 秒、17 次调用、3 次真实保存，5 个 Mod 接收节点与当前分支状态一致。原档 6 文件前后相同，详见 [报告与失败证据](test-results/2026-10-20-bubbles-windows.md)。

与原清单的区别：脚本直接控制游戏时钟，在测试模式下显式调用正式气泡方法验证 50/60 分钟边界；不是等待一个自然游戏小时。文字通过游戏渲染截图核对，表情通过实际游戏编号校验。实际游玩仍可按下面的清单观察：

1. 切到 `m2b-bubbles` 分支，重新编译安装 Mod（`dotnet build mod/StardewAgentBridge`），`npm run bridge`。
2. 和阿比盖尔“继续聊”，约一件第二天的事，比如一起去山上放风筝。睡觉存档，等后端日志出现“夜间整合完成”。
3. 第二天走到阿比盖尔附近（5 格以内）：她头顶应该冒出一句和约定有关的话，同时有一个表情。走开再过一个游戏小时回来，可能会冒第二句。
4. 同一句一天只出现一次；对话、菜单、剧情进行中不出现。
5. 前一天没聊过的 NPC 没有气泡。
6. 不保存退出、重新读档：前一晚的气泡还在（跟着存档点走）。
7. 想关掉：Mod 目录的 `config.json` 里把 `ShowBubbles` 改成 `false`。
