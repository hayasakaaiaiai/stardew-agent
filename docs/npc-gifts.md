# M2b 第五步：NPC 记得玩家送的礼物

> 状态：已实现，等 Windows 游戏内验收（2026-10-20）。分支 `m2b-gifts`，建在 `m2b-npc-chat` 上，目录 `/Users/a11/Documents/ChatGPT/stardew-agent-gifts`。验收前不合入 `main`。对应 `design.md` §10 的 `gift.given`。

## 1. 效果

玩家照原版送礼：原版照常加好感、显示原版反应。同时这位 NPC 当天记下一条“农场主送我紫水晶，我特别喜欢。”之后：
- 当天或以后点“继续聊”，NPC 记得这件事；玩家问“喜欢我送你的东西吗”，回答和原版喜好一致。
- 当晚夜间整合能看到这条，写信时可以顺带道谢。
- 记忆跟着存档走：睡觉保存才留下，不保存退出就和那天一起丢掉。

不调用模型，不增加固定 token；只有这条记忆被想起时才占 prompt。

## 2. 决定

用户说“所有事情你自己决策”，以下按推荐定，用户随时可以改。

| 问题 | 决定 | 原因 |
|---|---|---|
| 记什么 | 送了什么、原版喜好（最爱/喜欢/一般/不喜欢/讨厌）、是不是生日 | 喜好用游戏自己算的，记忆和原版反应不会矛盾 |
| 谁写记忆 | 代码按模板写，不调用模型 | 零调用、零编造 |
| 写法 | `农场主送我{物品}{当生日礼物}，{感受}。`，不写“今天”这类相对日期 | §4 实测最短；“今天/3 天前”由回忆时加 |
| 重要度 | 最爱、讨厌 4；喜欢、不喜欢 3；一般 2；生日 +1，最多 5 | 配合现有按心数的回忆门槛：0–1 心只记得最爱、讨厌和生日礼物，2–4 心再加喜欢和不喜欢 |
| 可见性 | `private`，类别 `observation` | 玩家私下给的，按 `design.md` §7.5 默认私密 |
| Mod 怎么发现 | 每帧对比原版的 `GiftsToday` 计数，变大时，上一帧手里拿的东西就是礼物 | 不改游戏代码，不用 Harmony；任务交付、节日礼物不改这个计数，所以不算 |
| 特殊物品 | 花束、枯萎的花束、美人鱼吊坠、虚空幽灵吊坠、电影票不记 | 它们在原版里走确定恋爱、求婚、室友、看电影的专门流程，不是普通礼物 |
| 怎么送到后端 | `gift.given` 和存档生命周期消息一样：收到确认才移出队列，重连补发；后端按序号去重，崩溃后从当天日志恢复回执 | 已有机制，不会重复记 |
| 不合适的消息 | 日期不是当前这天、不是 34 位之一、物品名清理后为空：确认但不记，不停用 AI | 送礼是小事，不值得让整个读档停掉 |
| 夜间整合 | 以前会用当天对话的原话替换“今天当场记下的”全部记忆，送礼记忆也会被换掉；现在只替换对话记下的那些 | 送礼没有原话可引用 |
| 只送礼、没聊天 | 夜间不为这位 NPC 调用模型，送礼记忆原样留下 | 不加调用；所以只送礼不会触发道谢信 |
| 物品名 | Mod 发游戏里的显示名；后端去掉原版指令字符和引号，最多 30 字 | 跟着游戏语言走 |

## 3. 改了哪些文件

| 文件 | 改动 |
|---|---|
| `src/agent/gifts.ts`（新） | 喜好、物品名清理、记忆模板 |
| `src/bridge/protocol.ts` | `gift.given`（Mod → 后端） |
| `src/bridge/memory.ts` | `GameSave.gift()`：写进这位 NPC 的当天事务，带回执 |
| `src/bridge/server.ts` | 收到后记下、回 `ack`，日志“阿比盖尔记下了：……” |
| `src/agent/nightly.ts` | 只替换类别为 `conversation` 的当天记忆 |
| `mod/.../Gifts.cs`（新）、`ModEntry.cs`、`SaveSync.cs` | 对比计数、发消息；`gift.given` 走可靠队列 |

不改记忆内核、数据库表和任何 prompt 的固定部分。协议版本从 2 升到 3（`BridgeClient.cs`、`protocol.ts`）：`gift.given` 要等确认，旧后端不认识它、不回 `ack`，这条会一直留在 Mod 的可靠队列里挡住“继续聊”。升版本后，不配套的 Mod 和后端在握手时就报“Mod 与后端协议不一致，请一同更新”，不会悄悄卡住。

## 4. 实测

o200k 分词，作为 DeepSeek 分词的近似：

| 写法（回忆里的一行） | token |
|---|---:|
| `- （今天）农场主送了我礼物：「紫水晶」。我特别喜欢。`（初稿） | 21 |
| `- （今天）收到农场主送的紫水晶（最爱）。` | 17 |
| **`- （今天）农场主送我紫水晶，我特别喜欢。`**（采用） | **16** |
| `- （3 天前）农场主送我紫水晶当生日礼物，我特别喜欢。` | 22 |
| `- （今天）农场主送我传送图腾：农场，说不上喜欢不喜欢。` | 22 |
| 夜间 `- （重要度 4）农场主送我紫水晶，我特别喜欢。` | 19 |

固定成本 0：不加调用，不改 system。只有被想起时，每条占 16–22 token，和别的记忆共用现有的条数和 600 字预算。

真实模型（`deepseek-flash`，对话 `high`）各 2 次：
- 开场白（玩家走过来）：6 次里 1 次主动提起（海莉：“今天别再拿粘土出来了”），其余照常寒暄。
- 玩家问“你喜欢我送你的东西吗？”：6 次都和原版喜好一致。阿比盖尔（6 心，紫水晶，最爱）说放在床头；海莉（2 心，粘土，讨厌）嫌恶心；刘易斯（4 心，3 天前生日收到防风草，一般）说不是最爱但领了心意。

## 5. 测试

`tests/gifts.test.ts` 5 项，完整 `npm test` 111/111，类型检查和构建通过；Mod Release 编译 0 警告、0 错误。
- 模板：文字、重要度、生日、物品名清理和截断。
- 协议：喜好、生日、日期不合法时拒绝。
- 后端：当天和第二天都记得；同一序号重发只记一次；不保存退出后丢掉。
- 不合适的消息：确认、不记、不发 `sync.error`。
- 夜间整合：对话记忆换成原话，送礼记忆保留（撤掉这次的修改，这项会失败）。

Mod 端在 Mac 上只能编译；C# 流程检查在 Mac 上加载不了游戏程序集，效果在 Windows 上看（§6）。

## 6. Windows 游戏内测试清单（用户来做）

1. 切到 `m2b-gifts`，重新编译安装 Mod，`npm run bridge`。
2. 送阿比盖尔一块紫水晶：原版反应照常；后端日志有“阿比盖尔记下了：农场主送我紫水晶，我特别喜欢。”
3. 接着点“继续聊”，问她喜不喜欢你送的东西：回答和原版反应一致。
4. 睡觉保存，第二天再问：还记得（“昨天”）。
5. 再送一样她讨厌的东西，不保存直接回标题、重新读档：她不记得这件。
6. 交任务物品（比如告示板上的送货任务）不会被当成礼物记下。
7. 后端日志里不该出现“处理 gift.given 出错”。
