# 硬件陪伴：把 NPC 带进现实

> 状态：设计已确认（2026-10-18）；H1 已实现（2026-10-19），实现说明和实测见 §12；H4 设计已确认（2026-10-20），见 §13，等夜间整合合并进 `main` 后实现；H3 的电脑端已实现（2026-10-20），见 §14，等真机验证；H2 的接线、烧录和配网步骤见附录 A。分支 `hardware-companion`，基于 `main`。

## 1. 已确认的决定

| 问题 | 决定 |
|---|---|
| 目标 | 在电脑上选一个存档和一个 NPC，这个 NPC 的 agent 就在小机器人上和真人语音聊天。它读得到这个存档里的记忆，以及最近一次在游戏里和玩家的对话 |
| 硬件 | 小智 DIY 板（ESP32-S3），不装舵机 |
| 互动方式 | 语音对话、屏幕上显示 NPC 的头像和表情 |
| 角色设定 | NPC 知道自己来到了现实，对面就是农场主，也就是玩家本人 |
| 记忆回写 | 写回存档，回到游戏里 NPC 也记得 |
| 回退 | 机器人上的聊天挂在当时的存档点后面。读更早的存档时，NPC 不记得 |
| 和游戏同时用 | 游戏开着同一个存档时机器人不能用，要先退回标题画面 |
| 语音服务 | 阿里云百炼：实时语音识别 + CosyVoice 语音合成 |

下文用"海莉"举例，34 位 NPC 都适用。

## 2. 整体结构

```
机器人（小智固件）
   │  WebSocket：Opus 音频 + JSON 消息（小智协议）
   ▼
电脑后端（和 npm run bridge 同一个进程）
   ├─ 设备服务：小智协议、Opus 编解码
   ├─ 语音：百炼实时识别 → 文字；文字 → CosyVoice → 音频
   ├─ 对话：现有的 runTurn，加一套语音模式的规则（§6）
   └─ 记忆：同一个记忆数据库；每次机器人聊天提交一次（§5）
```

- **固件用小智（xiaozhi-esp32，MIT 许可）**，电脑后端实现它的通信协议。语音识别、模型和语音合成都在电脑上跑，机器人只负责收音、放音和显示。
- **和游戏用的后端是同一个进程。**这样后端知道游戏现在开着哪个存档（§5.4），两边也共用一个记忆数据库。
- **机器人通过局域网连电脑**，所以设备服务要监听局域网地址，不像游戏用的服务只监听本机。连接要校验令牌，令牌在电脑上生成，配置时下发给机器人。Windows 第一次运行时会弹防火墙提示，要允许。

### 2.1 小智协议里用到的部分

| 方向 | 消息 | 用途 |
|---|---|---|
| 机器人 → 电脑 | `hello` | 连上时报告音频参数（Opus、16 kHz、单声道、每帧 60 ms） |
| 机器人 → 电脑 | `listen` start / stop | 开始或停止收音 |
| 机器人 → 电脑 | `abort` | 海莉说话时用户插话，打断 |
| 机器人 → 电脑 | 二进制帧 | 麦克风的 Opus 音频 |
| 电脑 → 机器人 | `stt` | 识别出的文字，显示在屏幕上 |
| 电脑 → 机器人 | `llm` emotion | 切换表情，也就是头像 |
| 电脑 → 机器人 | `tts` start / sentence_start / stop | 开始说话、显示当前这句、说完 |
| 电脑 → 机器人 | 二进制帧 | 语音合成的 Opus 音频 |
| 电脑 → 机器人 | `mcp` tools/call | 换头像包（§3.3） |

机器人第一次联网时会先访问一个 HTTP 配置地址，从返回的内容里拿到 WebSocket 地址和令牌。这个配置地址也由后端提供。机器人上要填的配置地址可以在小智配网页面里设置，不用改代码。

## 3. 硬件

### 3.1 推荐配置

按小智官方的"面包板"方案（`bread-compact-wifi-lcd`）接线：

| 部件 | 推荐型号 | 说明 |
|---|---|---|
| 主控 | ESP32-S3-N16R8 开发板 | 16 MB Flash、8 MB PSRAM，小智推荐配置 |
| 麦克风 | INMP441 | I2S 数字麦克风 |
| 功放 + 喇叭 | MAX98357A + 小喇叭 | I2S 功放 |
| 屏幕 | 2 寸 ST7789（240×320） | 显示头像。游戏头像是 64×64 像素画，放大 3 倍是 192×192，正好放得下 |
| 供电 | USB 5 V | 开发板的 USB 口供电就够 |

材料一共大约一百元，外壳可以先不做。接线和焊接要你来做，我按小智的引脚定义写一份接线表。

### 3.2 固件

**不改固件**，直接用小智官方给面包板方案编译好的固件：
- 小智每个版本都会发布 `bread-compact-wifi-lcd` 的固件包，下载后用 USB 烧录，不需要装乐鑫的 ESP-IDF 开发环境。
- 按项目约定，选一个发布超过两周的版本。现在最新的 v2.5.2 是 10 月 11 日发布的，还不满两周。
- 机器人第一次开机会进入配网模式。在配网页面填好 Wi-Fi，再把配置地址填成电脑后端的地址。
- 头像用小智的自定义表情包，由后端给的下载地址下载（§3.3），也不用改固件。

### 3.3 头像

| 项 | 做法 |
|---|---|
| 来源 | 从本机游戏里导出 `Portraits/<NPC>.xnb`，沿用 `tools/reference/extract_game.mjs` 用的 XNB 库。每张 64×64，顺序是 普通、开心、难过、特别、害羞、生气，正好对应对话里的 6 种表情 |
| 加工 | 用最近邻插值放大 3 倍，保持像素风格，再打包成小智的表情包格式 |
| 版权 | 和 `reference/game/` 一样：只在本机生成，放在 `.runtime/` 下，不进仓库 |
| 换角色 | 后端调用 `self.assets.set_download_url`，让机器人重启，然后从电脑下载这个 NPC 的表情包。只在换 NPC 时发生，大约要等十几秒 |

如果小智的表情包允许任意名字，比如 `haley_happy`，可以把 34 人的头像打进一个包，换角色就不用重启。这一点要实际验证。

## 4. 一次会话的流程

1. **在电脑上选择。**在后端终端输入 `/robot`，列出存档：存档名、农场主名字、存档时的游戏日期。选一个存档，再选 NPC。
   - 游戏开着这个存档时拒绝，提示先退回标题画面。
   - 如果 NPC 和上次不同，先给机器人换头像包。
2. **开场。**机器人连上后，海莉先开口。模型收到的开场提示是"农场主打开了桌上的小机器人"。
3. **一轮对话。**
   1. 机器人一直收音，Opus 音频转发给语音识别。
   2. 识别服务判定一句话说完后，把文字发给机器人显示（`stt`），同时开始生成回答。
   3. 模型先给表情，电脑马上切头像。
   4. 台词流式返回，每凑够一句就送去合成。合成出的音频边收边编码成 Opus，发给机器人播放。
4. **打断。**海莉说话时用户插话，机器人发 `abort`。电脑停止合成，丢掉这一轮还没播的部分，按用户的新话继续。被打断的那句台词只记录已经播出的部分。
5. **结束。**下面几种情况都会结束会话：
   - 用户道别，或者模型给出 `end`。
   - 2 分钟没人说话。
   - 机器人断电或断网。
   - 在终端里结束。

   结束时提交这次会话的记忆（§5.2）。

## 5. 记忆

### 5.1 读什么

| 内容 | 来源 |
|---|---|
| 心数、关系、看过的事件、世界状态、游戏日期、农场主名字 | 存档快照（见下） |
| 召回的记忆 | 现有的 `AgentMemory`，按心数分档召回，召回时用的查询词是用户这句话 |
| 最近一次在游戏里的对话（sessionA） | 从存档点往前找，最近一天里和这个 NPC 的原始对话，最多 10 轮 |
| 以前在机器人上聊过的 | 它们本来就在这条存档线上，作为记忆正常召回 |

**存档快照**：游戏关着时，后端拿不到心数、看过的事件这些游戏状态，所以每次存档时把它们存一份。
- 游戏这边是 M3b 做存档同步时，确认存档后把 34 位 NPC 的心数和关系、看过的事件、世界标记、日期、农场主名字写成 `.runtime/saves/<lineageId>/<commitId>.json`。
- 命令行聊天的存档在 `/sleep` 时写同样的文件。
- 这部分放在对话这一层，不改记忆内核。

### 5.2 写什么、挂在哪

- 每次机器人会话结束时生成一个**陪伴提交** R：
  - 父提交是这条存档线当前的头，也就是存档点 C，或者上一次的陪伴提交。
  - `dayEnded` 和 C 相同。记忆内核本来就支持同一天几个首尾相连的提交，设计文档 §6.6 里"随时存档"那一行就是这种情况。
- 每轮对话照常写成日志，`remember` 写成只有这个 NPC 能召回的私密记忆。记忆文字前面自动加上现实日期，比如"（现实里 10 月 18 日）农场主说他下周要考试"。
- 游戏时间记为存档那一天的末尾。
- 用的都是记忆系统已有的接口：读档、记录、存档准备和确认。会话过程中后端崩溃，靠现有的临时日志恢复。

### 5.3 游戏读档时接上陪伴提交

存档文件里记的仍然是 C，所以游戏读档时，后端要知道 C 后面接了哪些陪伴提交：
- 后端维护一份登记表 `.runtime/companion/<lineageId>.json`，记录"存档点 C → 最新的陪伴提交 R"。
- 游戏读到 C 时，记忆从 R 开始。下次游戏存档生成的 D，父提交就是 R。
- 读更早的存档 B 时，B 到根的路径上没有 R，所以海莉不记得机器人上聊过的，符合你选的"读更早的存档时不记得"。
- 复制出来的存档如果也指向 C，同样会接上 R。

**风险**：登记表和数据库是两份数据，写入时崩溃可能对不上，导致陪伴提交没人引用，海莉就"忘了"那次聊天。写入顺序是先在登记表记下"准备中"，再提交到数据库，最后标记完成，启动时检查一遍。长期看，这个查询放进记忆内核更稳，比如加一个"按父提交查陪伴提交"的命令。这要改你的记忆分支，所以先不做，以后再和你商量。

### 5.4 和游戏互斥

- 后端用一个按存档线加锁的表：游戏开着某个存档时，机器人不能选它。
- 机器人正在聊某个存档时，游戏读了同一个存档：后端先让机器人道别（"农场主回镇上了"）并提交陪伴提交，再让游戏读档，这样游戏能接上刚才的聊天。

### 5.5 回到游戏里

- 游戏里的海莉会召回带"现实里"的私密记忆。游戏里的规则加一条：这些是她在农场主的世界里、通过桌上的小机器人经历的事，只在和农场主单独聊天时提起，不对别人说。
- 这一步依赖 M3b，因为现在游戏里的对话还不读写记忆。在那之前，用命令行聊天验证：命令行也按登记表接上陪伴提交。

## 6. 语音模式的对话

对话仍然用现有的 `runTurn`，换一套语音模式的规则和输出格式：

| 和游戏里不同的地方 | 语音模式 |
|---|---|
| 选项 | 不要选项 |
| 台词长度 | 一两句、40 字以内，口语。不写括号里的动作描写，因为合成时会被念出来；数字写成汉字 |
| 输出顺序 | `{"emotion","reply","remember","end"}`：表情放在台词前面，开口前就能切好头像 |
| 当前情况 | 换成现实里的情况（见下） |

当前情况示例：

```
你现在在现实世界里，在农场主桌上的一个小机器人里。你能说话，屏幕上会显示你的样子；你看不见东西，也不能动。
现实里现在是 2026 年 10 月 18 日，星期日，晚上 9 点半。
鹈鹕镇那边停在第一年春季 12 日，也就是农场主上次存档的时候。
你对现实世界不熟，觉得新鲜；不懂的东西就问农场主，不要装懂。
```

- 角色卡、心数解锁的话题和禁忌照常生效，按存档快照里看过的事件筛选，所以不会剧透。
- 推理强度：游戏里用的 `high` 会增加延迟。语音模式先试 `disabled` 和 `low`，按实测选（§9）。

## 7. 语音服务

| 环节 | 选型 | 说明 |
|---|---|---|
| 识别 | `paraformer-realtime-v2` | 0.00024 元/秒，按音频时长计费，支持任意采样率。机器人传来的 Opus 先在电脑上解码成 16 kHz PCM 再送去识别，不依赖识别服务支不支持 Opus。NPC 名字和地名加成热词，比如 鹈鹕镇、皮埃尔 |
| 合成 | `cosyvoice-v3-flash` | 可以分段输入文字、分段返回音频。要 PCM 输出，在电脑上编码成 60 ms 的 Opus 帧。价格有二手资料说是 1 元/万字符，以控制台为准 |
| 音色 | 每个 NPC 配一个系统音色 | 写在配置文件里。先给海莉挑几个音色合成同一句话，你听了再定 |
| Opus 编解码 | `opusscript` | libopus 的 WebAssembly 版本，MIT 许可，Windows 上不用编译。版本发布已超过两周 |
| 密钥 | `.env` 加 `DASHSCOPE_API_KEY` | 北京地域的 key。请你直接填进 `.env`，不要发在对话里 |

**粗略估算**：聊一分钟，按用户说 20 秒、海莉说 150 字算，识别约 0.005 元，合成约 0.015 元，加上 DeepSeek 一共几分钱。

## 9. 风险和要先验证的

| 风险 | 应对 |
|---|---|
| 延迟：从说完话到听见回答，目标 3 秒以内 | 先在电脑上实测每一段的耗时：识别判定说完、模型首字、凑够一句、合成首包。推理强度按实测选 |
| 识别听错名字 | 热词；屏幕上会显示识别结果，听错了用户能看到 |
| 表情包能不能用任意名字、多大 | 先用原版小智固件，把海莉的 6 张头像打包烧进去试 |
| 机器人找不到电脑（换网络、IP 变了） | 配置地址可以随时在配网页面里改；后端启动时打印本机局域网地址 |
| 登记表和数据库对不上 | §5.3 的写入顺序和启动检查 |
| 网络不让设备互连：校园网、公司网常常隔离同一 Wi-Fi 下的设备 | 机器人连不上电脑时，电脑和机器人都连手机热点 |
| 依赖 M3b | H1–H3 不依赖 M3b，H4 要等 M3b |

## 12. H1 实现说明（2026-10-19）

### 12.1 怎么试

```sh
npm run bridge     # 后端：游戏用的服务，加上机器人用的设备服务
npm run device     # 另开一个终端：模拟机器人
```

1. 先用命令行和某个 NPC 聊几句，`/sleep` 存一次档。存过档的存档才会出现在 `/robot` 的列表里。
2. 在后端终端输入 `/robot pair`，再启动模拟机器人，它会自动配对。真机也是这样配对。
3. 在后端输入 `/robot`，选存档和角色。NPC 先开口。在模拟机器人里打字就是说话，`/wav <文件>` 可以送一段 16 kHz 单声道录音去识别。每句回答都存成 `.runtime/companion/replies/*.wav`。
4. 下面几种情况会结束会话并写回存档：道别、两分钟没说话、在后端输入 `/robot stop`、游戏读了这个存档。之后用命令行聊天打开同一个存档，NPC 记得在机器人上聊过的事。

没填百炼 key 时，语音服务是"静音"：只能打字，回答是一段静音，其余流程完全一样。

| 配置 | 默认 | 说明 |
|---|---|---|
| `DASHSCOPE_API_KEY` | 无 | 百炼北京地域的 key |
| `DASHSCOPE_WS_URL` | `wss://dashscope.aliyuncs.com/api-ws/v1/inference` | 百炼文档里也有按业务空间区分的地址，默认地址连不上时改成那个 |
| `DASHSCOPE_ASR_MODEL` / `DASHSCOPE_TTS_MODEL` | `paraformer-realtime-v2` / `cosyvoice-v3-flash` | |
| `DASHSCOPE_VOCABULARY_ID` | 无 | 在百炼控制台建的热词表，比如 NPC 名字、地名 |
| `NPC_VOICE_SILENCE_MS` | 700 | 停顿多久算一句话说完。服务默认 1300，对话里显得慢 |
| `NPC_VOICE_THINKING` | `low` | 机器人用的推理强度，游戏里仍按 `NPC_MODEL_THINKING` |
| `NPC_DEVICE_PORT` | 47712 | 设备服务端口，监听局域网 |
| `data/voices.json` | `longanyang` | 每个 NPC 的音色，等你听过再定 |

### 12.2 和设计不一样的地方

| 设计 | 实际 | 原因 |
|---|---|---|
| 记忆数据库由后端一直打开 | 只在机器人会话期间打开，会话结束就关 | 命令行聊天也要用这个库。两个进程同时写会出问题，所以加了一把进程锁（`memory.lock`）：一边在用时，另一边会提示先退出 |
| 令牌校验 | 再加配对：只给配过对的设备发令牌，新设备要先 `/robot pair` | 配置地址在局域网里谁都能访问，直接发令牌等于谁都能连 |
| 机器人断电或断网就结束会话 | 断开后不马上结束，等两分钟没说话再结束 | 小智固件空闲时会自己断开，唤醒后再连，不能把断开当成结束 |
| — | 农场主一开口（识别服务出第一个中间结果，或者唤醒词），就先和模型建好连接 | 见 §12.3：空闲几秒后重新建连接要多花 1.5–3.5 秒 |
| — | 被打断时，按播放时长估算听到了多少，只记那一部分，后面加"……" | 合成服务返回的音频不标是哪一句，没法精确对应 |
| — | 模拟机器人的打字输入，用了小智协议之外的一条 `{"type":"text"}` 消息 | 真机不会发这条消息 |
| 存档快照由游戏写 | 现在由命令行 `/sleep` 写，只记录当时聊天的那个 NPC 的心数，其余 NPC 沿用上一份快照 | M3b 之前游戏不存记忆 |

后端打印的配置地址会排除代理和 VPN 的虚拟网卡，并标出网卡名。比如这台 Mac 上的 198.18.0.1 是代理软件的虚拟网卡，机器人连不上它。

### 12.3 实测

模型是 `deepseek-flash`，推理强度 `low`；这台 Mac 的 HTTPS 流量走本机代理。

**首字延迟**：从说完话到模型的第一个输出。

| 情况 | 首个输出 |
|---|---|
| 上一个请求刚结束就接着发 | 1.6–1.9 秒 |
| 隔 10 秒再发（实际对话里的常态） | 2.6–3.6 秒，其中等响应头就要 1.7–2.5 秒 |
| 隔 10 秒，开口时预热，说了 1.5 秒 | 1.7–2.2 秒 |
| 隔 10 秒，开口时预热，说了 3 秒 | 1.2–1.9 秒 |

- 推理强度 `disabled`、`low`、`high` 在连续发送时差别不大，推理都只有五六十个 token，所以默认用 `low`。
- 多出来的时间来自重新建连接：连接空闲几秒就会被关掉，经过代理重新建立要 1.5–2.5 秒。
- 偶尔有 7–9 秒的波动，是网络原因。
- 模拟机器人是打字输入，没有中间结果可以触发预热，所以它测出来的是不预热的情况，大约 3–4 秒。

**整条链路**（用模拟机器人，语音是静音）：
- 存档里在镇上聊过"下周要去城里考试"。机器人上问"你还记得我跟你说过什么吗？"，海莉答"记得啊，你下周要去城里考试，还说有点紧张"。
- 道别后写回存档。再用命令行打开同一个存档，提示词里有"（现实里 10 月 19 日）……"这条记忆，以及"标着现实里的只和农场主聊"的说明。
- 第一版规则只写了"看不见东西"，海莉还是会说"这么暗""屋里好些东西我都看不出名堂"。改成"只能听见声音，不要描述看到的光线、房间或物品"之后：
  - 问房间怎么样，她答"哪看得见房间，说给我听听"。
  - 让她猜手里拿着什么，她答"我又没长眼睛到那边"。
  - 开场那句"这就是你那边的样子？"仍然有点像看得见，先不处理。

**测试**：新增 12 个离线测试，包括完整一轮、配对和令牌、打断、读更早的存档、和游戏互斥、和命令行互斥、崩溃后补写、超时结束、麦克风识别和预热、百炼协议格式。现在一共 56 个，全部通过。

### 12.4 还没验证的

- 百炼的真实识别和合成：协议格式只对着模拟的服务测过，等有了 key 再实测延迟、挑音色。
- 真机：H2。

## 13. H4：接回游戏（设计已确认，2026-10-20）

> 等 `nightly-consolidation` 合并进 `main`、这个分支变基之后再写代码，避免两边同时改 `src/bridge/memory.ts` 和 `server.ts`。

M3b 做完后，游戏里的对话也读写记忆了。H4 让机器人用游戏的存档：机器人上聊的写回游戏存档，游戏里的 NPC 也记得；反过来，机器人也知道游戏里发生过什么。

### 13.1 已确认的决定

| 问题 | 决定 |
|---|---|
| 机器人用哪个记忆库 | 只用游戏的库（`.runtime/game`），和游戏共用后端里已经打开的那一个，只有一个写入方。命令行的存档不再给机器人用 |
| 心数、看过的事件、世界状态从哪来 | 睡觉存档时 Mod 发一份快照 |
| 机器人聊的内容参加夜间整合吗 | 不参加，保持逐条带“现实里”的记忆 |
| 游戏断线期间机器人用了同一个存档 | 游戏连回来时，这次读档停用 AI，提示回标题重读 |

### 13.2 流程

1. **游戏存档时带上快照。**Mod 在 `save.saving` 里加一个可选的 `snapshot`：存档文件夹名（比如 `测试_436774213`），34 人的心数和关系，看过的事件，世界状态。后端准备提交之前，把它写成 `.runtime/game/saves/<存档线>/<提交>.json`，格式和 H1 的存档快照一样，世界标记按 `world.ts` 转成世界事实。
   - 协议版本还是 2。`snapshot` 是可选字段，没更新的 Mod 照常能用，只是机器人列不出这个存档。
   - 快照每次几 KB，不进 prompt。
2. **选存档。**`/robot` 列出每个游戏存档最近一次保存的那个点，只列已确认的提交。显示成“测试_436774213 · 测试，测试农场 · 第 1 年夏季 3 日”。
3. **机器人会话。**用游戏那边已经打开的记忆运行时，不再自己开库，也不再用 `memory.lock`。结束时照旧生成陪伴提交 R，挂在存档点 C 后面，登记表记下 C → R（放在 `.runtime/game/companion/`）。
4. **游戏读档时接上。**新的一次读档读到存档点 C：如果登记表里 C 后面有陪伴提交，记忆从最新的 R 开始；下次存档的 D 以 R 为父。存档文件里的指针仍然是 C，读更早的存档 B 时，B 到根的路径上没有 R，NPC 不记得机器人上聊的。
5. **游戏里提起。**游戏里的对话召回到“现实里”的记忆时，H1 已经加了一行说明：这些是在农场主的世界里经历的，只和农场主单独聊时提起。只在召回到这类记忆时才出现，实测 39 token；每条这样的记忆比普通记忆多约 5 token（“现实里 10 月 19 日”比“3 天前”长）。

### 13.3 和游戏互斥

记忆内核同一条存档线同一时间只能开一个读档。机器人一打开，游戏那边当天没存档的内容会被丢掉，所以必须互斥：

| 情况 | 处理 |
|---|---|
| 游戏开着这个存档（连着后端，还没回标题） | 机器人不能选它 |
| 机器人正在聊，游戏读了同一个存档 | 先让机器人结束并写回，再读档，游戏接上刚才的聊天（H1 已有） |
| 游戏回到标题 | 放开。H1 只在断开连接时放开，现在回标题也放开 |
| 游戏开着这个存档时和后端断了连接，机器人这时选了它 | 允许。后端把游戏那次读档标成“已被机器人接管”，丢掉它当天还没存的内容。游戏用同一次读档连回来时，后端回 `sync.error`：“机器人在这期间用过这个存档，回到标题重新读档后 AI 才能继续”，Mod 停用这次读档的 AI，原版游戏不受影响 |

最后一种只在断线时发生，比如后端重启的那几秒，或者游戏崩了没回标题。

### 13.4 夜间整合

陪伴提交不整合：`Nightly` 多了一个 `skip` 选项，传入 `isCompanionCommit`，`companion-` 开头的提交既不会被整合，也不占读档补跑“往回看 3 个提交”的名额（2026-10-20 已实现，有测试：连续 3 次机器人会话后补跑，只整合前面的存档）。

### 13.5 改动

| 位置 | 改动 |
|---|---|
| `mod/.../GameState.cs`、`SaveSync.cs` | 生成快照，放进 `save.saving` |
| `src/bridge/protocol.ts` | 校验可选的 `snapshot` |
| `src/bridge/memory.ts` | 准备提交前写快照；新读档时按登记表接上陪伴提交；“被机器人接管”的读档拒绝重连 |
| `src/bridge/server.ts` | 回标题时通知机器人放开 |
| `src/companion/service.ts`、`session.ts` | 用游戏的运行时；去掉 `memory.lock`；接管断线的游戏读档 |
| `tools/bridge.ts` | 机器人的数据目录改成 `.runtime/game` |
| `tools/chat.ts`、`tools/chat/session.ts` | 去掉 H1 为机器人加的快照、登记表和锁，回到 `main` 的样子 |

- 记忆内核不改。
- Mod 要重新编译。游戏内验证由你在 Windows 上做：没有硬件时，可以用模拟机器人（`npm run device`）打字代替说话。

### 13.6 测试

用模拟 Mod、模拟机器人、假模型和临时数据库：

- 游戏存档后机器人能列出这个存档，心数、看过的事件、世界事实和快照一致。
- 机器人聊完写回；游戏新读档后，对话 prompt 里有“现实里”的记忆和那行说明；再存档，新提交以陪伴提交为父。
- 读更早的存档，没有机器人聊过的内容。
- 游戏开着时机器人被拒绝；回标题后可以选；机器人在聊时游戏读档，先写回再读档。
- 游戏断线期间机器人接管：同一次读档重连收到 `sync.error`；回标题重读后接上机器人聊的。

## 14. H3：头像（电脑端已实现，2026-10-20）

### 14.1 怎么做的

- **资源包整个替换。**小智把字体、唤醒词模型和表情放在同一个 8 MB 的资源分区里，下载新资源包时整个分区都会被覆盖。所以每个 NPC 的包都以固件自带的默认资源为底，保留字体和唤醒词模型，只把表情图换成这个 NPC 的头像。格式按 v2.5.0 的 `main/assets.cc` 实现：12 字节文件头，每个文件 44 字节的索引，文件内容前面加 `ZZ`，校验和是文件头之后所有字节之和的低 16 位。
- **一个 NPC 一个包，不能 34 人合成一个。**§3.3 留了这个问题。表情名其实可以随便起，但固件在待机、连接和每次开始听用户说话时，都会自己把表情设成 `neutral`。如果 34 人合成一个包，`neutral` 只能是某一张固定的图，用户每说一句话，屏幕都会闪成那张图。所以每个包里，固件认识的 21 个表情名全都指向这个 NPC 的头像：会话用到的 6 种对应自己的那张，其余（`thinking`、`sleepy`……）都用普通表情。
- **换角色。**会话开始时，如果机器人上装的不是这个 NPC 的头像，后端用 MCP 调用固件的 `self.assets.set_download_url` 和 `self.reboot`。机器人重启、下载约 1.2 MB 的包、换上头像，之后用户说唤醒词，NPC 再开口。后端在 `devices.json` 里记下每台机器人装的是谁，同一个 NPC 不会重复下载。
- **下载地址**是 `http://<电脑>:47712/xiaozhi/assets/<npc>.bin?token=<配对令牌>`。没有令牌拿不到，因为包里是游戏头像。
- 没导出头像时不换，机器人用小智自带的表情，后端提示一次。下载失败的话，在后端输入 `/robot face` 重新下发。

### 14.2 导出头像

在跑后端的那台电脑上做一次，结果放在 `.runtime/companion/assets/`，不进仓库：

```sh
node tools/companion/portraits.ts --xnb <临时目录>/xnb-patched \
  --content "E:\games\steamapps\common\Stardew Valley\Content" \
  --firmware <烧录用的 merged-binary.bin>
```

- 头像是 64×64 的像素画，默认放大 3 倍成 192×192，不做平滑，保持像素风格。`--scale 2` 可以改成 128×128。
- 原版头像不到 6 张的 NPC，缺的表情用普通表情代替。这台 Mac 上缺的有：卡洛琳、艾芙琳、乔治、格斯、雷欧、桑迪、文森特、威利的害羞和生气；矮人只有一张；法师只有普通和开心。

### 14.3 实测（这台 Mac）

- 用本机游戏文件和下载的 v2.5.0 固件跑通：34 人 × 6 张共 447 KB；固件默认资源 1186 KB（字体 886 KB、唤醒词模型 291 KB、21 张表情）。

## 附录 A：H2 接线、烧录和配网

引脚、屏幕型号和配网页面都按小智固件 v2.5.0 的源码核对过（`main/boards/bread-compact-wifi-lcd/config.h`、`config.json`、`main/boards/common/wifi_board.cc`）。

### A.1 买什么

在 §3.1 的基础上补几点：

- **开发板**：ESP32-S3 **N16R8**，也就是 16 MB Flash、8 MB PSRAM。固件包解开后有 9.6 MB，8 MB Flash 的板子装不下。带 BOOT 按键和 USB 口的就行，比如 ESP32-S3-DevKitC-1 的仿制板。
- **屏幕**：2.0 寸 **IPS** ST7789，240×320，SPI 接口，有 BLK 背光脚的 8 针模块。官方固件按 IPS 屏做了颜色反转，买成非 IPS 屏颜色会反。
- **麦克风** INMP441、**功放** MAX98357A：模块版本都行。喇叭 4 Ω 或 8 Ω，3 W 左右。
- 另外要一块面包板、一包杜邦线（公对母、公对公都要），以及一根能传数据的 USB 线。有些线只能充电，接上电脑认不出板子。

### A.2 接线

电源先接好：开发板的 3V3 和 GND 分别拉到面包板两条电源轨上。

| 模块 | 模块上的脚 | 接到开发板 |
|---|---|---|
| 麦克风 INMP441 | VDD | 3V3 |
| | GND | GND |
| | L/R | GND（用左声道） |
| | WS | GPIO 4 |
| | SCK | GPIO 5 |
| | SD | GPIO 6 |
| 功放 MAX98357A | VIN | 5V（开发板上标 5V 或 VBUS 的脚） |
| | GND | GND |
| | DIN | GPIO 7 |
| | BCLK | GPIO 15 |
| | LRC | GPIO 16 |
| | SD、GAIN | 不接 |
| | 输出 + / − | 喇叭两根线 |
| 屏幕 ST7789 | VCC | 3V3 |
| | GND | GND |
| | SCL | GPIO 21 |
| | SDA | GPIO 47 |
| | RES | GPIO 45 |
| | DC | GPIO 40 |
| | CS | GPIO 41 |
| | BLK | GPIO 42 |

- 开发板自带的 BOOT 键是 GPIO 0：开机过程中按一下进入配网，平时按一下开始或结束对话。
- 固件还用到 GPIO 48（板载指示灯）和 GPIO 18（小智示例里的“灯”）。GPIO 18 不用接。
- 麦克风和屏幕都只能接 3V3，接 5V 会烧坏。只有功放的 VIN 接 5V。

### A.3 烧录

1. 下载固件：[小智 v2.5.0 发布页](https://github.com/78/xiaozhi-esp32/releases/tag/v2.5.0)里的 `v2.5.0_bread-compact-wifi-lcd.zip`，解压得到 `merged-binary.bin`。v2.5.0 发布于 9 月 10 日，满足“发布超过两周”。10 月 25 日之后也可以换成 v2.5.2。
   - 我下载核对过，zip 的 SHA-256 是 `ec2e9e427e9acf116f7e35556c5e1c418429b0be4941c93c414767aba7c81cf4`。
2. 用 USB 线把开发板接到电脑。认不出来时，按住 BOOT 键再插线。
3. 用浏览器烧录，不用装开发环境：用 Chrome 或 Edge 打开乐鑫官方的 [ESP 网页烧录工具](https://espressif.github.io/esptool-js/)，点 Connect 选开发板的串口。Flash Address 填 `0x0`，文件选 `merged-binary.bin`，点 Program，等进度条走完。
   - 用命令行也可以：`esptool.py --chip esp32s3 write_flash 0x0 merged-binary.bin`。
4. 烧完按一下开发板的 RST 键重启。屏幕亮起来、显示小智的界面，就说明屏幕接对了。

### A.4 配网和连到电脑

1. 在电脑上启动后端：`npm run bridge`。启动日志里会列出机器人可以用的配置地址，形如 `http://192.168.1.23:47712/xiaozhi/ota/`。Windows 第一次运行时会弹防火墙提示，要允许“专用网络”。
2. 在后端输入 `/robot pair`，两分钟内第一台来连的新机器人会被允许。
3. 机器人第一次开机没配过 Wi-Fi，会自己进入配网模式，并在屏幕上提示。配过的，开机过程中按一下 BOOT 键也能进入。
4. 用手机连机器人开的热点 `Xiaozhi-XXXX`，浏览器打开 `http://192.168.4.1`：
   - 第一页选家里的 Wi-Fi，填密码。机器人和电脑要在同一个网络里。
   - 切到 **Advanced** 页，在“自定义 OTA 地址”里填第 1 步打印的地址，保存。
5. 机器人重启后，会去访问这个地址拿 WebSocket 地址和令牌。后端日志出现“设备 … 已配对”“机器人已连接”，就连上了。
6. 在后端输入 `/robot`，选存档和角色，NPC 会先开口。

### A.5 常见问题

| 现象 | 先查 |
|---|---|
| 屏幕不亮 | VCC、GND、BLK 三根线；BLK 必须接 GPIO 42 |
| 屏幕颜色反了 | 买成了非 IPS 屏，换 IPS 屏 |
| 屏幕花屏、白屏 | SCL、SDA、DC、CS、RES 有没有接错位 |
| 听不到声音 | 功放 VIN 要接 5V；BCLK、LRC 有没有接反 |
| 说话没反应 | 麦克风 L/R 要接 GND；WS、SCK 有没有接反 |
| 后端日志里有“新设备请求连接” | 还没配对：在后端输入 `/robot pair`，再重启机器人 |
| 一直连不上电脑 | 配置地址里的 IP 是否是电脑现在的 IP；防火墙；校园网、公司网常常隔离同一个 Wi-Fi 下的设备，这时让电脑和机器人都连手机热点 |
