# M2b 第七步：关系好的 NPC 当面送东西

> 状态：已实现，Windows 统一脚本验收通过（2026-10-20），测试在 `codex/new-parts-windows-tests`，已合入 `main`。上游分支 `m2b-in-person-gifts` 建在 `m1-scratch-cleanup` 上，目录 `/Users/a11/Documents/ChatGPT/stardew-agent-gifts`。对应 `design.md` §8 的 `gift.give`。 当前分支归档与未解决问题以 [项目现状](status.md) 为准（2026-10-24）；下文旧分支名和“待验收”保留为阶段记录。

## 1. 效果

6 心以上（或在约会、订婚、结婚、室友）的 NPC，当天第一次和玩家“继续聊”时，可能顺手递过来一样东西：“欸，这个给你，虚空精华，够阴森吧？”。东西直接进背包（满了就掉在脚边），屏幕左下角出现原版的“获得物品”提示。NPC 之后记得自己送过。

送什么由代码从角色卡的“可送物品”里挑，模型只决定送不送。和寄信附赠共用冷却：同一位 NPC 不管当面还是随信，7 天最多送一次，所以送礼总频率不变。

## 2. 决定

用户说“所有事情你自己决策”，以下按推荐定，用户随时可以改。

| 问题 | 决定 | 原因 |
|---|---|---|
| 谁能送 | 和寄信附赠一样：6 心以上或亲密关系；婚后条目要结婚 | 沿用 `npc-mail.md` §8 |
| 送什么 | 代码按天轮换选一样，只从能当面给的条目里选：说明里带“随信”“寄”的不选，钱不选 | 34 张卡里 19 条写的是“随信寄来”，钱都是支票、退款，当面给不合情理 |
| 什么时候提供 | 只在当天第一次打开和这位 NPC 的对话时，在“当前情况”末尾加一行 | 开场时递东西最自然；每位 NPC 每天最多多一行，只在满足条件时才有 |
| 和次日计划开场的关系 | 那次开场不提供 | 计划开场的回复只保留问句，会把递东西的话删掉 |
| 冷却 | 7 天，和寄信共用。当面送出时 NPC 记一条“我当面送了农场主紫水晶。”，带固定 topic `当面送礼`；冷却从这类记忆和寄信留下的 `lastGiftDay` 里取较晚的 | 记忆跟着当天保存或回滚，不依赖夜间整合。白天不写 NPC 状态：状态是整对象快照，夜间整合晚于对话完成时会被盖掉 |
| 当晚的信 | 当面送过，当晚写信就不附东西 | 同一个冷却 |
| 防刷 | 一行里写“玩家开口讨要不算理由”；每天最多一次（后端只在开场提供，Mod 再按 NPC 记一次） | 加上 7 天冷却，讨要没有用 |
| Mod 怎么给 | 按中文名找物品，原价超过 500 金不给（和寄信一样）；`addItemToInventoryBool`，满了用 `createItemDebris` 掉在脚边；原版 `HUDMessage.ForItemGained` 提示 | 全部是原版机制 |
| 回滚 | 物品是游戏状态，跟存档走；记忆在当天事务里，也跟存档走 | 不保存退出后，下次读档这天又能送 |
| 关掉 | Mod 配置 `InPersonGifts` | — |

2026-10-21 Windows 组合验收发现：原来关掉时只有 Mod 拒绝给物品，后端仍可能记“已经送出”并消耗冷却。现在 `talk.open` 以可选布尔值 `inPersonGifts` 同步开关，后端关闭时不提供物品，模型的 `give:true` 也不会记赠礼或消耗冷却；正常开启的 prompt 不变，固定 token 增量 0。省略字段保持协议 3 老客户端行为。复现、回归与原生证据见 [后台传话组合报告](test-results/2026-10-21-offscreen-windows.md) §5。

## 3. 给模型的那一行

不改 `RULES` 和末尾的字段提示，只在提供时于“当前情况”末尾加：

```
- 可以当面送给玩家的东西：紫水晶（在山洞里捡到的，觉得颜色好看，想让玩家也看看。）觉得合适就在台词里自然地递给玩家，JSON 加 "give":true；玩家开口讨要不算理由。
```

`give` 只认 `true`；没有提供时就算模型写了也不理会。

## 4. 实测

o200k 分词：这一行 48–57 token（随物品说明长短）。固定成本 0：不改 system 规则，只在满足条件的 NPC 当天第一次开场时出现；送出后 7 天不再出现。

真实模型（`deepseek-flash`，对话 `high`，夏季 9 日广场开场，各 3 次）：

| NPC | 心数 | 提供 | 结果 |
|---|---:|---|---|
| 阿比盖尔 | 8 | 虚空精华 | 2/3 送出：“给你个东西，阴森得很，我猜你会喜欢。”“这个给你，虚空精华，够阴森吧？”；1 次只寒暄 |
| 莉亚 | 7 | 普通蘑菇 | 3/3 送出：“这个蘑菇给你吧，炖汤很鲜。”“采到个蘑菇，拿着吧” |
| 塞巴斯蒂安、威利 | 6 | — | 卡里只有随信的条目，不提供 |

送出时台词里都有递东西的话，但只有 1 次说出了物品名；具体是什么由原版提示显示。字段齐全 6/6。

## 6. 测试

`tests/in-person-gifts.test.ts` 4 项，完整 `npm test` 120/120，类型检查和构建通过；Mod Release 编译 0 警告、0 错误。
- 条目过滤、记忆模板、冷却取较晚的一个；婚后和“同上”在过滤后仍然成立。
- 那一行的位置和文字；`give` 只认 `true`。
- 后端：开场提供并送出；同一场后面的轮次、当天第二次打开、5 心都不提供；不靠夜间整合，6 天后仍在冷却（这时 NPC 记得“6 天前我当面送了……”），7 天后又能送；不保存退出后那天的送礼作废。去掉从记忆取冷却的那一行，这项会失败。
- 夜间整合：当面送过的那晚，信里不再附东西。

## 7. Windows 游戏内测试清单（用户来做）

1. 切到 `m2b-in-person-gifts`（包含第四到六步和临时日志清理），重新编译安装 Mod，`npm run bridge`。
2. 找一位 6 心以上、卡里有能当面给的东西的 NPC（比如阿比盖尔、莉亚），当天第一次点“继续聊”：多数时候会递东西，背包里多了一样，左下角有原版提示；后端日志有“阿比盖尔当面送了：……”。
3. 同一天再聊不会再送；第二天、第三天也不会（7 天冷却）。
4. 背包满时东西掉在脚边。
5. 不保存回到标题、重新读档：东西没了，再聊又可能送。
6. 塞巴斯蒂安这类卡里只有“随信寄来”的 NPC 不会当面送。
7. `config.json` 里把 `InPersonGifts` 改成 `false`：不再给东西。
