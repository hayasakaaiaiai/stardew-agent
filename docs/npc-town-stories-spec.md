## 2. 共同规则

- 单人；无恋爱或 8 心门槛，沿用原版剧情／拒绝交谈限制；不碰 H 线。
- 新开关 `TownStories` 默认开启；NPC 原版台词后新增“镇上的事”。现场调查使用可配置快捷键（默认 F8）打开原版提问框；没有自绘界面。
- 每条故事每个存档分支只发生一次。原版菜单中的明确选择推动玩法，自由模型文字不能完成任务、生成物件、替玩家确认贡献。
- 只使用原版对话、选择、提示和已有物件图像。原创故事不写入原版角色卡、不假冒原版心事件和过去经历。
- 不新增金钱、物品或好感奖励，三条故事的成果是归还、可查看的成品与真实共同经历。正常不帮忙、取消菜单或晚来看没有新增惩罚。
- 新动作依赖后端同步完成；已发现的故事和物件不因关闭功能而删除。关闭时保留查看、归还现有包裹；自主工作暂停，重新开启后按实际工作继续。
- 玩家未在场时，NPC 可在游戏中真实存在的日程地点推进项目；仅仅跨日、后台写一句话、模型说“完成”都不是工作证据。

## 3. 三条故事

### 3.1 `gus_parcel`：错放的备货包裹

主人公格斯；证人艾米丽、皮埃尔。原版职业是内容依据，包裹和标记误会是本 Mod 新写的剧情，不编造偷窃者。

1. 当面询问格斯“镇上的事”，阅读开场并选择开始调查；原版菜单退出不创建半成品状态。
2. 可分别当面询问艾米丽的收货标记、皮埃尔的出货标记。两人只提供自己的那部分证词，不互相知道对方说过什么。
3. 玩家到配置中的镇广场搜索区域，用调查键检查附近。必须真实在该地图与半径内，才能找到故事包裹。没有包位时不进入已取得状态，整理背包后可再搜。
4. 包裹是独立 ID、带本故事标记的真实任务物件，借用游戏已有图像；不可食用、出售、赠送或丢弃。它可以随存档保存，归还时只消耗匹配的这一件，不接受外观相同的普通物品。
5. 拿到包裹后可当面直接归还，结局为 `returned`；也可收齐两个证词，选择核清标记混淆后归还，结局为 `explained`。两种结局有不同原版收尾和后续摘要；归还只消耗一次，不重复奖励。
6. 拾取本身不会让不在场的失主知道。玩家当面汇报线索或真正归还后，格斯才在自由聊天中知道相应进展。

可在原版菜单回看已有证词、目前调查状态和结局；不会提前显示未取得证词或所有谜底。包裹取得后不会因再次搜索重复生成，放在箱子中的物件需取回后归还。

### 3.2 `penny_field_notes`：给下一课的观察题

主人公潘妮；内容依据为家教、阅读和自然观察兴趣。产物是准备好的原创题目页，不意味着孩子已上课、已郊游或已触发原版 8 心事件。

1. 当面发现她正在考虑一页新的观察题，明确阅读开场后启动项目。玩家可以参与，也可以只了解；不参与仍会由她自己推进。
2. 玩家可去森林或镇上，在同一地图真实正常走时观察满 10 游戏分钟，再用调查键记录当时地点和天气。传送、菜单暂停或跳时不补算。
3. 回到潘妮身边，以该条观察为来源，选择 `observe`（先观察再提问）或 `read`（先阅读再提问）。选一次，不凭聊天随口建议替玩家确认。观察事实与选择一起当面交给她。
4. 工作阶段 1 最早在发现的次日，阶段 2 最早在阶段 1 的次日；各阶段需潘妮真实位于允许的工作地图、静止且不受其他活动／剧情控制，正常积累 30 游戏分钟。工作只按有效钟步累计。
5. 两阶段完成后产生可反复阅读的三题成品。没有贡献则是 `independent` 基础版；有有效观察和选择则为对应协作版，并保留源地点／天气和贡献记录。

### 3.3 `elliott_short_piece`：一页短文，两种余味

主人公艾利欧特；内容依据为写作和海／森林兴趣。产物是本轮原创短文，不表示原版小说完成、出版或举办朗读会。

玩家可在海滩或森林实地观察 10 游戏分钟，回到他身边选择 `open`（留白）或 `bright`（明朗）。采用与潘妮相同的两阶段、至少两个不同工作日规则，保留真实工作证据。未参与时也会形成 `independent` 版本；参与后可阅读对应完整短文与结尾。工作完成前只能看到打算、已有贡献和进度，不提前看到全文或结局。

## 4. 内容配置与原生证据

唯一配置 `data/town/stories.json`，形状为 `{version:1, stories:[...]}`，后端与 Mod 共用；构建复制到 `assets/town-stories.json`。每条包含 `id,kind,owner,title,opening,references`；调查再包含 `clues,site,endings`，项目再包含 `observationVenues,workVenues,choices,endings`。详细字段锁定在实现侧类型及内容测试中。

- `owner`、证人使用已有小写 NPC ID；仅三个固定故事和配置白名单。
- 调查线索 ID：`emily_mark`、`pierre_mark`、`parcel`。现场坐标沿用仓库已确认的原版地图位置，提示以实际地标表达，不要求玩家理解内部 ID。
- 潘妮观察地图 Forest／Town，工作地图 Trailer／Trailer_Big／ArchaeologyHouse／Town；博物馆内部地图名采用仓库已核对的 ArchaeologyHouse。艾利欧特观察地图 Beach／Forest，工作地图 ElliottHouse／Beach。每个工作区间必须在同一允许地图。
- 原生任务物件通过 Data/Objects 注册，引用已安装游戏资源，不提交游戏导出和图像。
- 工作资格核对人物本人、游戏日、普通走时、地图、静止及控制权；不抢走现有约定、农活、下矿、生活或恋爱控制器。
- 每阶段在同一个游戏日、同一允许地图累计到 30 分钟后保存工作记录；跨日或换工作地图会清空未满阶段的分钟，已完成的阶段保留。第二阶段完成后生成持久结局。若结局日志写入失败，保留已验证阶段并在恢复可写时补结局，不重复工作或虚构玩家贡献。

## 5. 事件与日志契约

继续使用 `life.sync`、全局递增 `life-N`、最多 32 条混合批次。新握手为 `storiesProtocol:1`；持有故事日志的存档遇到旧后端时明确要求升级，不能跳过故事历史后假装同步完成。

所有故事事件：`id,npc,day,kind,storyId`，`npc` 固定为该故事 owner。

| kind | 允许的额外字段及前置 |
|---|---|
| `story.started` | 无；固定故事此前未启动／结束 |
| `story.clue` | `clueId`；证词额外 `other` 为配置中的实际证人；现场 parcel 没有 other，必须已真实入包；每线索一次 |
| `story.observed` | `venue,weather,minutes`；项目、允许地图、真实有效观察至少 10 分钟；每项目一条，可先选择去哪个地点 |
| `story.choice` | `choiceId,sourceId`；项目尚未结束、source 为本项目 observation；当面提交明确选择与该观察，只选择一次 |
| `story.worked` | `step,venue,minutes`；项目阶段 1／2，指定工作地点至少 30 分钟；阶段 1 晚于 start 日，阶段 2 晚于阶段 1 日 |
| `story.resolved` | `outcome`；调查已持有 parcel，explained 还须两证词；原生已当面扣包裹。项目须阶段 2，并按已发生选择计算 outcome |
| `story.told` | `sourceId`；只允许当面向 owner 汇报本项目尚未汇报的 clue／observed 来源，不允许转述链或虚构未来结局 |

天气只用现有 `sunny/rain/storm/snow/windy`；事件不带模型自由文本、任意参与者或奖励。严格拒绝错字段、未来日期、错 NPC、错阶段、错来源和重复更改内容。

后端新增 `src/agent/town-stories.ts`，纯解析／投影／上下文，权威进度放 `log.storyState`。普通生活、恋爱、故事三域先整体校验，最后在现有事务中原子写入；不改记忆内核，不写整个 NPC state。夜间印象与计划继续保留。

## 6. 知识边界与保存

权威剧情进度不是每个 NPC 的知识。现场发现只改玩家玩法记录；证人口述只给该证人生成“我告诉农场主”的记忆；当面汇报／选择才让 owner 得知玩家的调查或观察。项目本人的打算、工作与成品属于本人知识。自由聊天只附当前 NPC 可知的短摘要，不常驻三故事全文、未发现线索和分支答案。

故事原生状态、物件和已完成工作阶段随游戏保存回滚。未完成工作计时绑定游戏日和地图；实地观察的连续计时在换日、换图或读档时清空，已确认的观察记录保留。菜单回调复核 nonce、day、距离、开关、阶段和物件。变更包裹与写事件采用可回退流程，失败不消耗物件、不给完成回忆。读档不继承上一会话的控制器或连续观察时间。所有来源随当前保存分支恢复，旧分支的物件事件不跨分支重放。

## 7. 验证计划

自动检查覆盖三故事全部成功路径与不同结局、NPC独立完成、玩家贡献来源、未发现线索隔离、错证人、地图与计时、物件标记与满包／扣除失败、日志容量、两工作日限制、原生旧菜单、协议门禁、混合批次原子回滚、保存／重启／分叉、晚到 nightly 与旧生活／恋爱回归。

prompt 使用仓库外 o200k tokenizer 测实际生产函数；分别记录未开始、已发现、证人、未汇报现场、贡献、两工作阶段、独立／协作结局的增量，不凭字数估算，不新增项目依赖或模型调用。

## 8. 实现结果与设计收敛

S0–S4 已完成代码与离线验证。三故事共八种结局使用同一份配置；真实任务包裹、原版调查菜单、两个自主项目、可阅读成品、对应角色的知情摘要和混合日志均已接入。完整证据见 [验证报告](test-results/2026-11-09-npc-town-stories.md)，真人游戏部分交由用户按 [Windows 全量清单](npc-town-stories-game-checklist.md) 验收，当前均未填写通过。

| 阶段 | 实际结果 |
|---|---|
| S0 | 三条原创故事、八个完整结局、内容来源、严格配置及事件字段；共用 JSON 随 Mod 打包 |
| S1 | 两证人、现场定位、带本次故事标记的任务包裹、满包处理、精确扣物与失败恢复、直接／解释归还 |
| S2 | 两种实地观察、每项目两种明确贡献、两个不同工作日、独立／协作成品；有效分钟绑定日和地图 |
| S3 | `log.storyState` 独立投影、NPC 知情来源、`storiesProtocol:1` 门禁、混合事务、重复同步、保存／重启／分叉及晚到夜间更新 |
| S4 | 全仓 Node 416/416、类型检查、构建、两个 demo、独立 C# 167/167 和 Mod Release；实际分词及 72 项待执行游戏清单 |

实现时将原先较宽的“长期目标”具体收敛为每存档分支一次的两个跨日作品。首次明确了解项目后才开始推进，玩家无需承诺帮忙；没有强制移动、独立工作动画或新的日程系统。每阶段允许在同一日、同一地图的多个有效区间累计，走路、聊天等无效区间不增加分钟；跨日或换图清空未完成阶段。暂停功能保留历史和成品，物件定义始终注册，避免关开关后丢失任务物件身份。

观察贡献会隐式向本人汇报同一来源，后续不再生成重复汇报；直接归还只披露包裹事实，解释归还披露所需两份证词。证人引用明确标注说话人。成品全文可在游戏菜单反复阅读，但不常驻模型提示；提示只给已知进度、选择、工作日和结局标题，并限制补写未提供的正文。

分词使用生产 `storyChanges → storyContext → buildMessages`，34 张卡成功加载，21 个固定场景：尚未启动增加 **0** token，已启动及有知识的摘要增加 **94–273** o200k token；未汇报的现场发现对主人公不增加任何新信息。把全部故事资料常驻还会额外增加 **1647** token，并暴露未发现剧情，因此未采用。o200k 是 DeepSeek 成本的近似，数字不含 API 封装、检索增长或输出，详见 [实测 JSON](test-results/2026-11-09-town-stories-prompt.json)。没有新增项目依赖、真实模型调用或 H 线改动。
