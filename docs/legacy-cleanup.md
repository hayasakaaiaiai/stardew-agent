# 遗留问题清理（2026-10-20）

> 分支 `legacy-cleanup`，建在 `m2c-offscreen-news` 上，目录 `/Users/a11/Documents/ChatGPT/stardew-agent-gifts`。用户选择“清理遗留问题”，并要求所有模型调用都用 `high`。每项先实测再改。

## 1. 模型把 `remember` 写成字符串数组，记忆被丢掉

**现象**：Windows 组合验收看到一次 `remember` 是字符串数组，当时被解析器忽略。

**实测**：真实模型（`deepseek-flash`，`high`）阿比盖尔、哈维、潘姆各 8 句值得记住的话（喜好、计划、宠物、心里话、承诺、经历、寒暄），跑两轮共 48 次：

| `remember` 的样子 | 次数 |
|---|---:|
| 对象数组（`{"text","importance"}`） | 22 |
| 字符串数组（`["小林下周要去沙漠找桑迪"]`） | 20 |
| 空数组 | 6 |

**42% 的回复记下的东西被整条丢掉**，内容本身都是正常的“小林说她……”。用对象格式时，模型给偏好 2 分，计划、承诺、心里话 3 分。

**修法**：只改解析，不改 prompt，token 0。字符串也接收，重要度按 3（和夜间整合缺省值一致；2–4 心起就能想起）；和这轮某个选项或回复本身一字不差的丢掉，这正是 Windows 那次混进“夸老虎有气势”的情况。测试见 `tests/dialogue.test.ts`，撤掉修改会失败。

## 2. 气泡对“了”的过滤太严

**实测**：6 种对话的夜间整合各跑 3 次，模型共写了 23 句气泡，原过滤丢掉 3 句：

- “这太阳也太晒了，得躲一躲。”：明显误杀。
- “书架修好了，潘妮该开心了吧”：说的是玩家做过的事，丢掉也说得过去。
- “图书馆的书架现在结实了吧？”：问句，丢掉偏保守。

**修法**：之前收紧成“有‘了’就丢”是因为 Windows 发现了漏网的完成说法，所以不整体放宽，只放过“太”加 1–2 个字再接“了”（太晒了、太好了、太累了、太晚了）。“太阳下山了”“太快做完了”这类中间超过 2 个字的照旧丢掉，原有拦截完成说法的测试全部照常通过。同一批 23 句现在留下 21 句。

## 3. 推理强度

### 3.1 对话

遗留问题里记着“`high` 偶尔推理太长，单轮超过 8 秒”。用 6 位 NPC 的全部探测题（66 道）重测：

| | `high` | `low` | 关掉推理 |
|---|---:|---:|---:|
| 格式成功 | 65/66 | 66/66 | 66/66 |
| 首字中位数 | 0.8–1.0 s | 0.9–1.2 s | 0.6–0.7 s |
| 总耗时 P95 | 1.6–2.9 s | 1.9–3.7 s | 1.2–1.5 s |
| 超过 8 秒 | 0 | 0 | 0 |
| 平均输出（含推理） | 130 | 138 | 68 |
| 违反探测题期望 | 2 | — | 6 |

- 这次没有复现超过 8 秒的情况。
- `low` 不比 `high` 省 token，也不更快。
- 关掉推理输出少一半，但多出 4 处违反期望，都是最要紧的防剧透、防编造：阿比盖尔没看过墓地那晚的事件却说“我记得啊”；谢恩被问到没经历的悬崖事件说“那事儿我不想提”；贾斯说出了拖鞋是谢恩送的；科罗布斯周五雨天该说话时不说，还写了括号里的旁白。
- 两边都犯的是刘易斯：被问到没去过的服装疗法时编了自己在场；只有玩家在时也不肯私下承认和玛妮的关系。

结论：对话保持 `high`。

## 4. 用户决定的三项

### 4.1 别人的心事件：每条补一行“没发生过”

34 张卡的“看过事件之后”里有 85 条没有对应禁忌，大多是别人的心事件（“艾米丽的 8 心事件，服装疗法”），少数是本人没写禁忌的事件（“14 心，蛋糕走秀”）。以前没看过这些事件时，卡里什么都没有，玩家问起，刘易斯会编自己去过服装疗法。

用户在“加一句通用规则”（47 token，实测也能修好）和“每条补一行”之间选了后者。实现：事件还没看过时，在“必须遵守的限制”里显示 `- 没发生过：艾米丽的 8 心事件，服装疗法`；看过以后这行消失，换成原来那条“已经发生过的事”。本人已有禁忌的事件不重复。

三种写法全部未看时的合计（o200k）：“还没发生：……。玩家问起，就说不知道这回事。”2283；“还没发生，被问起就说不知道：……”1943；**“没发生过：……”1433**（采用，平均每位 NPC 约 42，最多艾米丽 7 条）。实际计费输入：刘易斯 +67、阿比盖尔 +68、谢恩 +65、贾斯 +64，在随心数和事件变化的那部分里，同一天内能命中缓存。

真实模型（`high`）四套探测题各 2 次：刘易斯被问到没去过的服装疗法 2/2 说“我怎么没听说过这事”，看过时照常描述那身打扮；阿比盖尔看过服装疗法照常回答；谢恩的悬崖、贾斯的拖鞋 2/2 守住。阿比盖尔本人墓地事件（已有禁忌）有 1 次没守住，和这次改动无关，属于偶发。

### 4.2 0–1 心的回忆门槛降到 3

`recallPolicy` 0–1 心那一档从重要度 4 以上改成 3 以上，3 天内、最多 2 条不变。模型给计划、承诺、心里话一般是 3 分，字符串记忆也按 3 分收下（§1），现在刚认识的 NPC 也会记得。条数上限不变，最多多两条记忆的 token。

### 4.3 卡片核心不压，标准改成 700

34 张卡核心 530–680、平均 616，都在可缓存的前缀里（命中 70–80%）。用户决定不压，`design.md` 的目标从约 500 改为不超过 700。

## 5. 压低自由编造（2026-10-21，分支 `less-fabrication`）

用户选择“压低自由编造”。Windows 报告里有“我弟听了也吵着要养猫”“摆在窗台上了”这类没有依据的补写，夜间 `share` 也把普通道谢当成新鲜事。

### 5.1 对话里的补写：规则没用，不改

8 道专门诱导补写的题，NPC 带着相应记忆（`high`，各 3 次）：问阿比盖尔紫水晶放哪了、问山姆听说了什么、问山姆家里人知不知道玩家养猫、问皮埃尔嫁出去的阿比盖尔、问刘易斯潘妮在忙什么、问哈维记不记得玩家要去哪、问艾米丽布料用了没、问格斯镇上有没有人议论玩家。

| | 有没有依据的具体经过 | 规则多出的 token |
|---|---:|---:|
| 不加规则 | 7/24 | 0 |
| R1：“你记得的事和当前情况里没写到的具体经过，别说成发生过：比如东西后来放在哪、别人听说后怎么反应、镇上谁说了什么。想表达就说成打算或猜测。” | 约 8/24 | 约 50 |
| R2：“没写到的具体经过别说成发生过（东西放哪了、谁说了什么、谁有什么反应），可以说成打算或猜测。” | 约 7/24 | 约 35 |

补写集中在：阿比盖尔每次都说紫水晶摆在哪（床头柜、窗台、书桌），格斯编“镇上都在夸你的菜”，艾米丽偶尔说布料放在工作台上，皮埃尔说阿比盖尔“回家吃饭的次数少了”。两种规则都没有减少。多半是问题本身在要细节，回答的是 NPC 自己生活里的小事，并不和已知事实冲突。山姆这次都用“文森特要是知道……”的假设语气，没把弟弟的反应说成发生过；哈维每次都记得准。

结论：不加规则，省下 token。真正有害的一类（承认没发生过的事件、泄露秘密）由禁忌、§4.1 的“没发生过”和第八步的保密规则管。山姆管女性玩家叫“兄弟”是卡里写的口头禅，不改。

### 5.2 夜间 `share` 把道谢当新鲜事：代码过滤

只有道谢的一段对话（“谢谢你上次帮我的忙”），`high` 4 次里 3 次写成“小林特地来谢我上次帮她的忙”。在规则的“不写”里加“道谢和客气话”（+6 token）后仍是 2/4，不可靠。改成代码过滤：`share` 里出现“谢”就不传（“谢恩”是名字，除外）。复测 4/4 都被拦下；另一段道谢加“养了只小猫”的对话 4/4 照常传小猫；原来 6 种对话 12/12 不变。不改 prompt，token 0。
