# 游戏对话桥接（M3a / M3b）

> 更新于 2026-10-24。M3a / M3b 已实现并合入 main；Windows 阿比盖尔三轮、跨天、回滚、重启和旧档分叉已验收，中文输入、原版台词保留和 Esc 取消由用户在 10 月 20 日手测确认。本轮补上原生桥接的 Origin 校验；协议与恢复见 [game-memory.md](game-memory.md)。

## 1. 已确认的决定

| 问题 | 决定 |
|---|---|
| 范围 | M3a 做对话和游戏状态读取；M3b 接入现有记忆内核，随真实游戏存档提交或回滚 |
| 入口 | 原版台词说完后，弹出“继续聊 / 离开”。原版每天 +20 好感和剧情台词都保留 |
| 编译环境 | .NET 8 SDK，装在 `~/.dotnet`，不需要管理员权限 |
| 部署 | 编译后复制到 `Mods/StardewAgentBridge`；运行时用 SMAPI save data 附加记忆提交指针，不改其他 Mod |

## 2. 一次对话的流程

```
玩家点 NPC → 原版台词（+20 好感）→ 台词框关闭
  → Mod 弹出“继续聊 / 离开”
  → 选“继续聊”：NPC 头顶冒“……”，Mod 发 talk.open（心数、事件、世界状态）
  → 后端用现有的 runTurn 生成回复，发 talk.reply（台词、表情、3 个选项）
  → Mod 用原版 NPC 对话框显示台词和选项：3 个选项、“自己说……”、“离开”
  → 玩家选了选项，或在原版输入窗口里打字：Mod 发 talk.say，NPC 再冒“……”
  → 玩家选“离开”或 NPC 想结束：Mod 发 talk.close
```

- 只对 34 位社交 NPC 弹“继续聊”。过场事件、节日进行中、玩家正在做别的菜单时不弹。
- 后端没连上时不弹“继续聊”，游戏完全是原版行为。

## 3. 协议（M3a 用到的部分）

本机 WebSocket，后端只监听 `127.0.0.1`，默认端口 47711，协议版本 3（2026-10-20 为 `gift.given` 从 2 升上来：它和生命周期消息一样等确认，旧后端不会确认，会一直挡住“继续聊”，所以握手时就拒绝不配套的版本）。游戏消息带 `lineageId`、`loadNonce`、`seq`；握手 `save.loaded` 固定为 0，其余事件在同一次读档递增。生命周期事件收到确认才移出 Mod 队列，重连后补发；后端校验序号与内容摘要，不重复调用模型或写入记忆。旧版本 Mod 和后端需要一起更新。

Mod → 后端：

| 消息 | 时机 | 主要字段 |
|---|---|---|
| `hello` | 连上时 | Mod 版本、协议版本 |
| `save.loaded` | 读档及重连握手 | 存档 ID、本次读档最初的日期、玩家信息和档内提交指针；后端恢复该 nonce 最新检查点 |
| `day.started` | 每天开始 | 日期、天气 |
| `save.saving` | 保存前 | 本次提交的 `commitId`、`parentId`、`dayEnded` |
| `save.saved` | 确认游戏保存成功 | `commitId`、实际保存后的日期 |
| `title.returned` | 不保存退出 / 回到标题 | 丢弃未保存工作区，保留已经准备或确认的数据库节点 |
| `talk.open` | 选了“继续聊” | npc、心数、关系、看过的事件、世界状态；可选布尔值 `inPersonGifts` 同步 Mod 当面赠礼开关，关闭时后端不提供物品、不记赠礼或冷却；省略保持原行为 |
| `talk.say` | 玩家说一句 | npc、文本（选项原文或自己打的字）、当前日期时间 |
| `talk.close` | 离开 | npc |
| `gift.given` | 原版送礼之后 | npc、物品显示名、原版喜好、是否生日、日期；可靠消息，等 `ack`（见 `npc-gifts.md`） |
| `scene.request` | 两个 NPC 站在一起、玩家在旁边 | 两人的游戏内名字、世界状态（见 `npc-chat.md`） |
| `scene.shown` | 一段碰面聊天的最后一句显示后，且不在“继续聊”中 | 对应的 `scene.request` 序号、日期；可靠消息，等 `ack`（见 `npc-news.md`） |
| `town.hour` | 每个游戏整点，有 NPC 在玩家看不到的地方待在一起时；不在“继续聊”中 | 几组游戏内名字、日期；可靠消息，等 `ack`（见 `offscreen-news.md`） |
| `festival.ended` | 离开节日会场，且节日里有结果时；不在“继续聊”中 | 节日、在场的人、舞伴/秘密礼物/比赛/展台/汤的结果、日期；可靠消息，等 `ack`（见 `festival-memories.md`） |

后端 → Mod：

| 消息 | 主要字段 |
|---|---|
| `save.ready` | 存档身份、已恢复到的绝对游戏日 |
| `ack` | 已落盘处理的生命周期事件身份与序号 |
| `sync.error` | 同步失败原因；本次读档停用 AI，原版游戏继续 |
| `day.bubbles` | 今天各 NPC 走近时嘀咕的话和表情，按 NPC id；读档就绪、新的一天开始、当晚整合完成时发，Mod 收到新的一份就替换（见 `npc-bubbles.md`） |
| `day.letters` | 今早最多一封信：信件键、npc、正文、附带物品；Mod 已有的信忽略（见 `npc-mail.md`） |
| `scene.lines` | 回应 `scene.request`，同一序号；2–4 句台词，不显示时为空（见 `npc-chat.md`） |
| `talk.delta` | npc、台词的一段（流式） |
| `talk.reply` | npc、完整台词、表情、3 个选项、是否想结束；好感变化点数 `friendship`（见 `npc-friendship.md`）；当面送的东西 `gift`（可选，见 `npc-in-person-gifts.md`） |
| `talk.error` | npc、原因（Mod 显示一句提示后关闭界面） |

对话回复同时带存档身份和请求序号。Mod 必须同时匹配当前读档、NPC 和等待中的那一轮，才显示回复。

世界状态由 Mod 收集成结构化的标记，后端负责转成给模型看的中文“世界事实”，这样文案都留在 TypeScript 这边：

| 标记 | 从游戏哪里读 | 转成的世界事实 |
|---|---|---|
| 年、季节、日期、时间 | `Game1.year` 等 | 当前情况里的时间 |
| 天气 | 下雨、下雪、打雷、刮风 | 当前情况里的天气 |
| 地点 | 当前地图的显示名 | 当前情况里的地点 |
| 社区中心 / Joja | 邮件标记 `ccIsComplete`、`JojaMember` | 社区中心修好了没有、Joja 还在不在 |
| 巴士 | 邮件标记 `ccVault` | 巴士修好了没有 |
| 矮人语 | 玩家能否听懂矮人语 | 玩家会不会矮人语 |
| 潘姆的新房子 | 邮件标记 `pamHouseUpgrade` | 盖了没有 |
| 姜岛 | 邮件标记 `willyBoatFixed` | 能不能去姜岛 |
| 雷欧 | 邮件标记 `leoMoved` | 搬到山谷了没有 |
| 肯特 | 年份 ≥ 2 | 回来了没有 |

心数用 `getFriendshipHeartLevelForNPC`；关系看好感数据里的约会、订婚、结婚、室友状态；看过的事件用 `Game1.player.eventsSeen`，整份发过去。

## 4. Mod（C#）

代码在 `mod/StardewAgentBridge/`，用 SMAPI 官方的 `Pathoschild.Stardew.ModBuildConfig` 构建。NuGet 官方源在开发机上连不上，`mod/nuget.config` 里配了华为云镜像，只对这个项目生效。

### 4.1 界面全部复用原版

按你的要求，界面尽量贴近原版：不自己画对话框，全部用游戏自带的界面。

| 环节 | 用的原版界面 | 说明 |
|---|---|---|
| “继续聊？” | 原版提问框（`createQuestionDialogue`） | 和原版问“要不要……”的样子一样 |
| 等待回复 | NPC 头顶冒原版的“……”表情，玩家原地站着；游戏时钟停住（§10） | 原版没有“加载中”，用表情最自然 |
| NPC 说话和选项 | 原版 NPC 对话框（`Dialogue` + `DialogueBox`） | 头像、名字、好感宝石、逐字打出、翻页都是原版的；选项用原版的 `$r` 写法和台词显示在同一个框里，跟原版 NPC 提问一模一样 |
| 表情 | 原版表情标记 `$h` `$s` `$u` `$l` `$a` | 由模型给的 emotion 换算 |
| 自己说 | 原版文字输入窗口（`TitleTextInputMenu`） | 原版改名、取名用的就是它；关掉脏话过滤，最多 60 字 |
| NPC 想结束 | 原版对话框，只有台词没有选项 | 点完就结束 |

和上一版相比的取舍：台词不再边生成边显示，而是整句到了以后，用原版对话框逐字打出来。实测首字延迟中位数 1.5 秒、总耗时多在 4 秒以内，等待期间 NPC 头顶冒“……”，看起来就是 NPC 在想怎么说。

### 4.2 要处理的细节

- **转义**：原版对话会把 `# $ @ % { } * ^ [ ] |` 当成指令，比如 `[184]` 会直接给玩家一个物品、`@` 会换成玩家名字。模型回复里的这些字符一律换成全角。
- **NPC 的原版台词队列**：原版对话框关闭时，会弹出 NPC 每日台词队列最上面的一条。所以我们的台词要先压进这个队列再显示；关闭后再检查一遍，没被弹出就手动移除，不影响 NPC 当天剩下的原版台词。
- **不重复弹“继续聊”**：原版台词说完才弹，我们自己的对话框关闭时不弹。
- **选项回调**：给 `Dialogue` 设置 `answerQuestionBehavior`，玩家选了第几项会回调到 Mod，而且不会触发原版选项自带的好感变化。
- **菜单关闭通知晚一帧**：SMAPI 先发送上一帧捕获的 `MenuChanged`，再运行游戏更新，最后触发 `UpdateTicked`。游戏更新里关闭对话框后，关闭通知会到下一帧才发。因此 `RunPending` 必须等 `Shown` 和 `Input` 都清空、且不在等待模型时，才能消费玩家选择；否则下一帧会把已经取走的选择误判为“没有选择就关闭”，结束聊天并丢掉第二轮回复。“自己说”提交文字也要等输入框的关闭通知处理完，避免误判为取消输入。
- **长台词**：原版对话框会自己把超出一屏的部分挪到下一页，不用额外处理。
- **等待超时**：默认 20 秒没有回复，NPC 不再等待，屏幕左下角提示“（某某好像走神了）”，对话结束。等待时按 Esc 也可以取消。
- **字体缺字**：原版对话框用位图字体，没有的字会跳过；另外先去掉表情符号这类字符。“自己说”的输入框用的是另一种字体，碰到没有的字会让游戏崩溃，所以每一帧都把输入框里字体没有的字换掉。

| 文件 | 职责 |
|---|---|
| `ModEntry.cs` | 挂事件：读档、每天开始、菜单变化、按键；串起整个对话流程 |
| `BridgeClient.cs` | WebSocket 连接、断线重连；收到的消息放进队列，在游戏线程里处理 |
| `SaveSync.cs` | 存档指针、保存/退出事件、生命周期队列、确认与重连、回复身份检查 |
| `GameState.cs` | 收集心数、关系、事件、世界标记 |
| `VanillaDialogue.cs` | 把回复拼成原版对话：转义、表情、分页、选项 |
| `SafeText.cs` | 把输入框字体里没有的字换掉 |
| `AbigailTest.cs` | 接收测试脚本的启动标记，加载指定测试档、传送并检查三轮原版对话框 |
| `config.json` | 后端地址、是否弹“继续聊”、等待超时 |

## 5. 后端（TypeScript）

| 文件 | 职责 |
|---|---|
| `src/bridge/protocol.ts` | 消息类型 |
| `src/bridge/world.ts` | 把 Mod 的标记转成 `WorldState` 和世界事实 |
| `src/bridge/server.ts` | WebSocket 服务、连接与请求隔离；生命周期有序，模型请求可被保存或退出取消 |
| `src/bridge/memory.ts` | 用 M1 接口对齐、提交、回滚、恢复和去重；不改记忆内核 |
| `tools/bridge.ts` | `npm run bridge` 启动：加载角色卡、模型客户端，开服务 |

- 新增依赖 `ws`，Node 只自带 WebSocket 客户端，没有服务端。设计文档 §12 已经预计了这个依赖。
- 对话用现有 `runTurn` 和 `AgentMemory` 召回，原话、模型的 `remember` 和去重结果作为同一当天事件落盘。保存确认前不会进入已提交历史。
- 数据在 `.runtime/game/`，与命令行及硬件分支的数据不自动共享。本轮没有增加依赖或改动提示词格式和好感度策略。
- 同一时间每个连接只处理一轮对话，界面在等回复时也不允许再发。

## 8. Windows 阿比盖尔自动测试

按用户指定的本机测试档运行：

```powershell
powershell -NoProfile -File .\tools\test-abigail.ps1
```

先正常退出当前游戏。脚本会编译并安装 Mod、启动或复用后端，然后启动 SMAPI。游戏路径默认 `E:\games\steamapps\common\Stardew Valley`，可用 `-GamePath` 覆盖。

只需传送后接手手测时，运行 `powershell -NoProfile -File .\tools\test-abigail.ps1 -Manual`。会加载指定测试档并传送到阿比盖尔旁边，停在原版提示框；关闭后由玩家点击 NPC，不自动进入 AI 对话。此入口由本地 `2260625` 复用，用户此前已报告拼音输入、原版台词及取消三项没有问题。

自动流程是：原版主菜单执行“加载” → 按存档标识精确选择 `测试_436774213` → 等待存档和后端就绪 → 查找阿比盖尔的当前地图 → 在她相邻的可通行空格落地 → 调用现有 `StartTalk` → 用原版选项回调连续对话三轮。三轮回复都进入原版对话框后停止自动选择，保留第三轮对话框供继续手测。

脚本只给新游戏进程设置 `STARDEW_AGENT_TEST_ABIGAIL` 请求标记。普通游戏启动保持原有流程。测试期间按 Esc 可取消，测试流程不调用睡觉存档。

脚本会探测现有后端的协议。在游戏尚未启动、且端口属于本项目时，自动重启旧协议的后端，避免更新 DLL 后仍连接旧模块。2026-10-20 网络恢复后，已在 Windows PowerShell 5 中重跑三轮真机流程，13.27 秒通过。失败且没有其他菜单时弹出原版提示框暂停，避免无人操作时游戏继续走时，见 [重测记录](test-results/2026-10-20-retest.md)。

依赖为本机 Node 24+、已执行 `npm ci`、配置好的 `.env`、可编译 Mod 的 .NET SDK，以及已安装 SMAPI 的游戏。测试存档不存在时会停止。

结果写入 `.runtime/abigail-test-result.json`，脚本日志为 `.runtime/abigail-test-launcher.log`；Mod 目录也保存一份本次请求的结果。2026-10-19 已完成一次真机自动回归，三轮回复均成功，详细数字和覆盖边界见 [测试报告](test-results/2026-10-19-abigail.md)。自动流程直接进入 AI 对话，原版每日台词到“继续聊”的入口仍按 §7 手动验证。

## 10. 等回复时停钟（2026-10-31）

用户提出“继续聊的时候时间暂停”。单人游戏里，原版只要有菜单开着就不走钟（`Game1.shouldTimePass`），所以对话框和“自己说”的输入框开着时，钟本来就是停的。剩下会走钟的只有等模型回复的那几秒：那时没有菜单，现实约 7 秒就是游戏里 10 分钟。命令行的对话记录里，首字中位数 1.6–2 秒，慢的 P95 到过 9.8 秒，超时上限是 20 秒。

| 问题 | 决定 | 谁定的 |
|---|---|---|
| 怎么停 | 用原版的 `Game1.isTimePaused`，只停钟，画面、NPC 和动物照常动；不用 `Game1.paused`（会冻住整个世界，连“……”都不动） | 用户 |
| 什么时候停 | 发出请求、NPC 头上冒“……”时停；回复到了、按 Esc 取消、超时、断线、对话出错、读档、回标题时恢复 | 自定 |
| 别人的暂停 | 只恢复自己停的：如果钟已经被控制台的 `pausetime` 停住，就不碰它 | 自定 |
| 联机 | 不停。联机时原版由房主的 `IsTimePaused` 控制，打开菜单也不停 | 自定 |
| 开关 | `PauseClockWhileWaiting`，默认开 | 自定 |
| 副作用 | 原版暂停时飞行物（弹弓、怪物的子弹）停在半空，恢复后接着飞；只有等回复的几秒 | 核对原版 |

不改后端和 prompt，token 增量 0。C# 流程检查新增一项：停钟、恢复、不碰别人的暂停、关掉开关不停。

Windows 上要看一眼的：

1. 记下右上角时间，选“继续聊”，等回复的时候钟不动；回复出来、读完、再选一个选项。整段对话结束后，时间和开始时一样。菜单切换的一两帧还会走钟，聊十轮加起来也不到 1 秒现实时间，所以最多碰巧跨过一格 10 分钟。
2. 等回复时按 Esc 取消，钟接着走。
3. 把 `ReplyTimeoutSeconds` 改成 1，等到“走神了”，钟接着走。
4. 控制台先输入 `debug pausetime` 停钟，再聊一轮：聊完钟仍然停着；再输入一次 `debug pausetime` 恢复。
5. `PauseClockWhileWaiting` 改成 `false`：等回复时钟照走。
