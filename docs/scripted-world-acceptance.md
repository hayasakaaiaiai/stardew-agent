# 节日、后台场景与行程的脚本验收

2026-10-22，用户明确要求“手测部分写脚本测”。本步骤在已有独立副本验收框架上自动执行此前交给用户的游戏内清单；发现的读取缺陷做最小修复，不修改玩法或 prompt。

- 入口 `tools/test-game-world.ps1`，`-Offline` 跑完整固定模型流程；`-Section content` 用真实模型复核晴雨日程、后台记忆和已保存节日召回。可按 `schedules`、`backstage`、`festivals` 分段调试。
- 每次从指定源档复制 `MemoryTest_<随机ID>`，记录原档全部文件 SHA256；仅修改副本。使用独立 Mod 目录、随机端口和独立后端数据库，正常安装与正常记忆库保持原状。
- Mod 的 `World` 场景只由已验证的 `STARDEW_AGENT_TEST_MEMORY` 配置开启。测试命令通过带 requestId 的本地控制文件进入游戏线程；正常启动不执行。
- 场景之间回到标题页，基于初始副本设置日期/天气后真实重新读档；保存用原版睡觉，回滚用真实退出和重新读档。
- 节日进入实际原版事件，操作原版对话/活动方法，经过真实监视器和可靠消息队列；比赛使用受控分数调用原版判定，和实际玩完整小游戏的覆盖区别单独报告。特殊中断、多人胜者条件若通过注入构造，明确标记，不冒充多人联机实测。
- 行程读取原版当天选择的日程，覆盖晴雨和空日程，记录下一站与实际路径控制器结果。对话经原版输入框；后台场景由真实 TimeChanged 事件发起，检查下一整点落库、重复/重连、额度、保存及回滚。
- 每次保留配置、命令及观察、模型输入/输出/用量、双向消息、保存事件、截图、SMAPI 日志和失败。仅对实际执行通过的覆盖作结论。

实现结果和覆盖边界见 [本轮报告](test-results/2026-10-22-world-windows.md) 和 `docs/status.md`。主组合记录 193 项技术断言通过、内容 4/5 后被旧测试退出 API 中断；修正后 `-Section fair-return` 收尾 16/16，两段共 51 次真实调用、5 次保存、33 次读档。最新完整 all 未重新一进程跑完，模型内容未全过。推送和合入 main 仍需用户另行授权。

## 中断语义修正

脚本发现冬日星收礼场面开始就被当成礼物送达。保留原版场面开始后读取实际送礼人的设计，新增“场面结束并恢复自由操作”的完成条件；中断交换整项不写，删除退出时拿原抽签人补齐的回退。新增 C# 回归在修复前 32/33、修复后 33/33；原版中断脚本额外检查背包尚未收到物品且没有交换记忆。固定 prompt、协议和模型次数不变，新增 token 为 0。
