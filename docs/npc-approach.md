# NPC 有话要说时主动走过来

> 状态：用户 2026-10-21 说“继续”，沿用“后续有需要决定的地方你自行定夺”，按推荐自行决定（§2）。已实现（§7），等 Windows 验收（§8）。分支 `m2c-approach`，建在 `m2c-schedules` 上，目录 `/Users/a11/Documents/ChatGPT/stardew-agent-gifts`。这一步是 `next-day-plans.md` §1 和 `npc-schedules.md` §9 推迟的“主动靠近”。

## 1. 为什么做

昨天和玩家聊过的 NPC，夜里会想好第二天要说的事（`next-day-plans.md`）。但只有玩家自己去点他、选“继续聊”，他才会说出来。玩家不去找他，这件事就没了下文，NPC 显得很被动。

这一步让真有事要找玩家的 NPC，看见玩家时自己走过来：头上冒“！”，喊一声玩家的名字，走到旁边等一会儿。玩家点他，就是原来的原版台词加“继续聊”，开场提起昨天想好的事。说完或者等不到，NPC 走回原来站的地方，接着走原版日程。

这也是以后让 NPC 帮忙种地、陪玩家下矿洞的第一块基础：NPC 离开原版日程去做一件事，再安全地回到日程上（顺序见 `status.md` §7）。

## 2. 决定

| 问题 | 决定 | 理由 |
|---|---|---|
| 谁会走过来 | 夜间整合时自己决定的：新增一个字段 `seek`；而且第二天第一次“继续聊”时开场确实会提起这件事（`next-day-plans.md` 的条件） | 实测 §3：只看 `plan` 里有没有“农场主”，该走过来的判对 6/9，不该走过来的误判 4/12；`seek` 判对 9/9、误判 0/12 |
| 好感门槛 | 不另设。按回忆门槛算出最少要几心：昨天的记忆重要度 ≥3 时 0 心、2 时 5 心、1 时 8 心（恋爱、订婚不看心数） | 心数不够时开场想不起这件事，走过来却什么都不提会很奇怪 |
| 什么时候走 | 玩家和 NPC 在同一张地图、8 格以内，玩家能自由行动；NPC 站着没事做（没在走路、没在做结尾动作、没在来回踱步、没有排队的日程），离下一站出发至少 90 分钟；早上 6 点到晚上 8 点 | 走过去、等候、走回去要在下一站出发前做完 |
| 哪里不走 | 节日、剧情、玩家的农场和农舍、电影院、姜岛 | 这些地方原版有专门的走路逻辑 |
| 谁不走 | 配偶、室友；疏远期的六位（`ColdShoulder`）；当天已经和玩家说过话的 | 配偶有专门的回家逻辑；说过话就已经提过了 |
| 次数 | 每位 NPC 每天 1 次；全部 NPC 一天最多 3 次，两次之间至少隔 1 游戏小时 | 少而有事，才像是特地来找 |
| 怎么招呼 | 头上一个“！”表情，气泡写玩家的名字加“！”，比如“小林！” | 固定写法，0 token；名字照原版对话转义 |
| 怎么走 | 原版寻路 `PathFindController.findPath`，走到玩家旁边一格，最多 16 步；找不到路或已经挨着，就在原地招呼、面向玩家 | 不自己写寻路 |
| 等多久 | 走到后面向玩家，最多等 30 游戏分钟（现实约 21 秒） | |
| 什么时候走回去 | 等够了；玩家走到 6 格以外；离下一站不到 20 分钟；和他说完话（原版对话、“继续聊”都结束） | |
| 怎么走回去 | 寻路回原来的位置，再转回原来的朝向。走不回去（卡住超过 5 秒、找不到路）或者玩家离开了这张地图，直接放回原位。回到原位时如果原版日程该出发了，马上出发 | 原版日程的路线是早上从上一站算好的，NPC 不回到原位就会沿着错的路线走，卡在墙边 |
| 日程怎么办 | 整个过程用原版的 `temporaryController`；它不为空时，原版日程到点只排队，不会从半路出发（§4.1） | 用原版已有的机制，不改日程 |
| 气泡、小动作、碰面 | 这位 NPC 走过来到走回去之间，不冒夜间气泡，不参加同图小动作和碰面聊天 | 避免头上同时两句话 |
| 不踩坏东西 | 走过来到走回去之间关掉原版 NPC“踩坏挡路物件”的设定（`willDestroyObjectsUnderfoot`），寻路把物件当障碍，结束时恢复（2026-10-21 随 `m2c-farm-help` 加上） | 原版这个设定会让 NPC 寻路无视并毁掉玩家放的物件 |
| 配置 | Mod 新开关 `NpcApproach`，默认开 | 会改 NPC 的位置，要能关掉 |
| 后端 | 不调用模型；`day.approach` 和气泡、来信一起发（读档、新的一天、夜间整合晚到时补发），协议版本不变 | 和气泡一样，旧 Mod 不认识就忽略 |
| 记忆 | 不写 | 走过来本身不是谈话；真正说的话照常由“继续聊”记 |

## 3. 实测

### 3.1 谁该走过来

真实模型（`deepseek-flash`，夜间整合 `high`），8 种昨天的对话，每种 3 次。对比只看 `plan` 文字（有“农场主”或玩家名字就算要找）和新加的 `seek` 字段：

| 昨天的对话 | 应该 | 关键词 | `seek` |
|---|---|---|---|
| 阿比盖尔：玩家约明天下午海边钓鱼，她答应了 | 走 | 2/3 | 3/3 |
| 山姆：邀请来听排练，玩家说“我想想” | 走 | 3/3 | 3/3 |
| 潘妮：玩家说狗病了，她说明天再问问 | 走 | 1/3 | 3/3 |
| 皮埃尔：只聊了天气 | 不走 | 误判 1/3 | 0/3 |
| 威利：说自己明天修船 | 不走 | 误判 2/3 | 0/3 |
| 谢恩：玩家骂他酗酒，他让玩家离远点 | 不走 | 0/3 | 0/3 |
| 海莉：邀请当模特，玩家拒绝 | 不走 | 误判 1/3 | 0/3 |
| 格斯：玩家说明天送鲑鱼来 | 都行 | 3/3 | 1/3 |

- 关键词判断不准：模型常把玩家写成“她”（潘妮 2 次、阿比盖尔 1 次漏掉）；只是自己的事也常顺手加一句“见到小林跟她说说”（威利、皮埃尔）。
- `seek` 在应该和不应该的 21 次里全对。谢恩 3 次的 `plan` 都是“不想主动找她”。

加的规则（放在 `plan` 那条后面）：

```text
- seek：明天在镇上碰到农场主时，要不要主动走过去说 plan 里的事。只有想当面问农场主、提醒约好的事或再邀请一次时写 true；只是自己的打算、普通寒暄、生气或想躲开都写 false。
```

## 4. 做法

### 4.1 原版的依据（星露谷 1.6.15 反编译）

- `NPC.update`：`temporaryController` 不为空时只更新它和表情，不走普通的 `controller`。它的 `update` 返回 true 时清空；如果它是日程用的（`NPCSchedule`），清空后马上 `checkSchedule`。
- `NPC.checkSchedule`：到点先把这一站加进 `queuedSchedulePaths`；`temporaryController` 不为空时不出发，下次检查再说。
- `PathFindController.update`：不是日程用的寻路，玩家不在这张地图时直接把 NPC 放到终点；原地不动超过 5 秒就结束。`moveCharacter` 不处理门和传送点，NPC 不会走出这张地图。
- `NPC.checkAction` 不看 `temporaryController`，走路和等候时玩家照样能点他说话。
- 用 `findPath` 的静态方法 + 只带路线的构造函数，不用会清掉 NPC 位置台词（`removeOnNextMove`）的那个构造函数。

### 4.2 Mod

新文件 `Approach.cs`：

- `ApproachController`：继承 `PathFindController`，多一个 `Hold`。`Hold` 为真时 `update` 永远不报告结束，NPC 就一直由它接管，原版日程只排队。走过去和等候时 `Hold` 为真；走回去时用一个新的、`Hold` 为假的，到了原版自己清掉。
- 状态：走过去 → 等候 → 走回去。每帧检查：
  - NPC 被游戏挪去了别的地图：放手，不再管。
  - 玩家离开这张地图：直接放回原位和原朝向。
  - 剧情中：马上放手（剧情可能要让这位 NPC 走动，等候的控制器会挡住），剧情结束后放回原位。
  - 有菜单或对话框开着：先不动；打开的是和他的对话框（看对话框的说话人，不看 `Game1.currentSpeaker`，它关掉后不一定清空），或者正在和他“继续聊”，就记下“说过话了”。
  - 走过去：路走完、卡住超过 3 秒或者被玩家叫住，就停下转为等候。
  - 等候：每半秒面向玩家；满足 §2 的条件就走回去。
  - 走回去：路上又被玩家叫住，就停下转回等候，聊完再走；控制器被原版清掉后，没到原位就放回原位，转回原朝向；`queuedSchedulePaths` 里有到点的就 `checkSchedule`。
- 新的一天、读档、回标题时清空；正在走的 NPC 放回原位。
- `TickBubbles`、`AmbientDue`、碰面挑人时跳过正在走过来的 NPC。

### 4.3 后端

- `nightly.ts`：规则加 `seek`；解析时只有 `true` 算真，缺了或写错都当 `false`，不因此让整晚失败；存进 NPC 状态，每晚覆盖。
- `morning.ts`：把“昨天的计划今天能不能用”和“原话记忆”两个判断导出，开场和走过来共用。
- `approach.ts`（新）：`approachHearts(context, today)` 返回最少心数，不该走就返回空。
- `GameSave.today()` 多返回 `approach`；服务器在发 `day.bubbles`、`day.letters` 时一起发 `day.approach`：`{ npcs: { abigail: 0 } }`，`seq` 为 0。

## 5. 测试（假模型）

- 夜间：`seek` 为 true、false、缺失、写成字符串；存进状态；第二天之后不再算。
- `approachHearts`：日期不对、`seek` 为假、计划为空或过长、没有昨天的原话记忆、当天已经说过话；重要度 3、2、1 分别对应 0、5、8 心。
- 服务器：新的一天、夜间整合晚到、读档都发 `day.approach`；回到旧存档跟着旧存档走；当天说过话后再次发送时不再包含他。
- C# 流程检查（Windows 跑）：`ApproachController` 等候时不交还、放手后交还；`day.approach` 只认当前读档，跳过坏值；清空当天状态。

## 6. 真实模型怎么测

夜间整合用实现后的代码跑 §3.1 的 8 种对话，一直算到“谁走过来、几心起”，再和场景里的心数对照：该走过来的要走，不该的不能走，心数不够时开场想不起来的也不走。

- Mod：`Approach.cs`（新），`ModConfig.NpcApproach`；`ModEntry` 接收消息和每帧检查；读档、新的一天、回标题时清空；气泡、同图小动作、碰面聊天跳过正在走过来的 NPC。
- 顺手修了一个已有问题：开场提计划原来用“当天日志有没有记录”判断说没说过话，但送礼、听到传话、节日、后台场景也写在当天日志里。NPC 早上在后台听到一条传话，当天就不会再提昨天的计划。改成只看对话记录，开场和走过来共用。新测试在旧代码上失败。

## 8. Windows 游戏内测试清单（用户来做）

1. 第一天找一位 6 心以上的 NPC（比如阿比盖尔）“继续聊”，约第二天一起做件事，对方答应；睡觉保存。
2. 第二天后端日志出现“今天想主动找农场主的：abigail（0 心起）”（夜间整合晚到时会稍后出现）。
3. 走到她站着不动的地方，8 格以内：她头上冒“！”和“你的名字！”，走到你旁边一格，面向你。
4. 点她：原版台词后选“继续聊”，开场提起昨天约的事。聊完她走回原来的位置、转回原来的朝向；之后按原版日程准时去下一站，没有卡在墙边。
5. 不理她：约 21 秒后她自己走回去。走开 6 格以上，她也走回去。
6. 她走过来或等候时离开这张地图，再回来：她在原来的位置（或已经按日程去了下一站）。
7. 店员在柜台后面（皮埃尔、格斯）：只在原地喊一声、面向你，不穿过柜台。
8. 不会走过来的情况：当天已经和她说过话；昨天只是寒暄；在农场、节日、剧情中；晚上 8 点以后；配偶、室友；`NpcApproach` 设为 `false`。
9. 一天最多 3 位，两位之间至少隔 1 游戏小时；同一位一天只来一次。
10. 不保存读档回到当天早上：她会再走过来一次。
11. 她走过来期间头上不冒夜间气泡，也不参加小动作和碰面聊天。
12. C# 流程检查全部通过（新增 2 项）。
