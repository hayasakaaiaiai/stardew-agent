# 碰面聊天、送礼记忆与聊天好感的 Windows 组合验收

用户要求“测试一下这些功能，你写脚本测”，并指定一个脚本覆盖三项。本次在 `codex/social-windows-tests`（基于 `m2b-friendship` / `6654433`）实现统一入口 `tools/test-game-social.ps1`。

## 验收方案

1. 运行完整 Node 测试、类型检查、构建、Mod Release 编译和 C# 流程检查。
2. 只在自动创建的 `MemoryTest_*` 独立存档和独立 SQLite 中测试，保存原测试档全部文件的 SHA256。
3. 同一游戏进程中，用固定模型检查碰面触发条件、轮流气泡、距离、菜单、每日频率；通过原版送礼函数验证计数监测、物品和喜好；通过原版对话输入检查好感增减、上下限、重复消息。
4. 真实睡觉保存后重新读档，验证礼物和好感留下；当天的第二份礼物和好感变化不保存退出，验证二者一起回滚。
5. 再切到真实模型，检查一段 NPC 闲聊、送礼回忆和正负聊天；原始请求、计费 token、游戏检查、数据包和结果统一留在本次运行目录。`-Offline` 可以只跑固定模型。

固定模型、真实模型及界面证据分别记账。游戏内的自然游玩体验不由固定脚本推断。

- 送礼：调用原版 `tryToReceiveActiveObject` 实际赠送紫水晶和粘土；Mod 自动检测 `GiftsToday` 的变化，发出游戏显示名和原版喜好。中继重发同一条紫水晶消息，记忆只出现一次。真实睡觉后原记忆仍在 prompt 和 SQLite；粘土未保存退出后不再出现在回忆 prompt，SQLite 也没有这条。
- 好感：固定输出通过真实原版输入框回调提交，八轮实际变化为 `+20,+10,0,-20,-20,-20,-10,0`，触及 `+30/-40`。关闭开关为零，向 Mod 直接传入超大变化也会被同样上限截断。每条回复经中继重复发送，Mod 只应用一次。开场零变化；睡觉后保存、未保存退出后恢复到 2040 点；新日和读档清空当天合计。
- 真实模型：格斯/潘姆输出 4 句，6.858 秒、542 输入/110 输出 token；阿比盖尔正确说出“紫水晶”。开场的模型 `mood=1` 被后端置零，询问礼物 `+10`、夸画 `+20`、冒犯 `-20`，实际原版点数依次为 `2040→2050→2070→2050`。

本次 5 次真实调用合计 8519 输入 token（其中缓存命中 7040）、597 输出 token，均以接口返回的 usage 为准。没有修改任何 prompt 固定内容，修复的正常调用 token 增量为 0。

## 发现与修复

新增 `node --test tests/social-regression.test.ts` 在修复前实际失败：6:00 第一段之后，6:50 换一对 NPC，后端仍给出 2 句并再次调用模型。上游只在 Mod 限制了间隔，未兑现后端也检查的设计。

后端现补上 60 游戏分钟和当前日期校验，拒绝的请求不消耗次数或调用；跨天才完成的旧请求也不再发送旧台词。原来的预算测试改为每小时一段，新增测试同时核对 6:50 拒绝、7:00 允许和错误日期拒绝。没有改记忆内核或数据库表。

测试设施新增显式 `Social` 模式，仅在独立存档配置启用。普通自动测试仍不启动 NPC 闲聊；组合模式调用提取出来的相同触发函数，显示与网络处理走正常 Mod 路径。Windows PowerShell 5 的 UTF-8 BOM/JSON 编码和 stderr 警告处理均已实际修正。开发期的固定模型流程曾在 48.24 秒完成 30 项检查，但外层 JSON 报告因默认编码读取失败；该轮留在 `.runtime/social-20261020-232327/`，最终完整通过以上述目录为准。

## 使用

先正常退出游戏，在项目目录运行同一个脚本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File E:\stardew-agent\tools\test-game-social.ps1
# Same checks without paid model calls or an API key:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File E:\stardew-agent\tools\test-game-social.ps1 -Offline
```

脚本自动测试、编译、备份安装 DLL、创建副本、启动独立后端与游戏、核对保存和回滚、结束自己启动的游戏；故障注入和模型原始内容只写本地 `.runtime/`。不删除测试副本或历史失败证据。`-Offline` 会跳过 5 项真实模型检查。

完整验收后，正常后端在 23:29:07 备份并从 PID 29688 更新为 PID 33020；普通端口 47711 的协议 3 握手通过，日志确认对话 high、夜间 low、碰面 disabled。安装 DLL 与本次编译 DLL 的 SHA256 相同，`561BCCB6F51394F519DB2B730F6628B39713E875FCEF90EFF2538A1CF3DA0E9F`。本地分支未推送、未合入 `main`。

## 覆盖边界与内容观察

这是独立副本、显式放置 NPC 的原生流程验收，不等同于镇上全部地图/时间/多人游戏的自然游玩测试。节日礼物和任务交付未通过实际任务场景重测，生日只由现有离线模板与协议检查覆盖；本次没有强制断网重连或重启后端。夜间整合使用固定模型，仅验证新礼物记忆不被抹掉。

真实模型仍补写了“把紫水晶摆在窗台上”“那只老虎”等无来源细节；夸画时 `remember` 还混入玩家未选择的选项“夸老虎有气势”。该字段当次输出为字符串数组，现有解析器已忽略，重新用 `parseOutput` 核对为空，不能据此宣称模型事实可靠或记忆格式总是正确。原始输出保留在 `game/model-calls.jsonl`。这些不影响本次三项机制断言，不扩展修改现有对话 prompt。
