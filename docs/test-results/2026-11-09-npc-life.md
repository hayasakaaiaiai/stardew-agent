### 桥接回归实际验证了什么

- 部分批次期间禁止带不完整状态聊天；最后一批之后才开放。
- 非法格式明确回 `sync.error`，错误源事件／未来日期全批不入库。
- 保存后进程重启、同 nonce 重连、新读档完整重放不重复信任或记忆。
- 不保存退出恢复旧阶段；旧存档分叉可以重新使用其本支的原生 serial。
- 离线保存的事件恢复后保留源日期，不挤占新一天好感额度。
- 好友发送者／接收者一次原子写入，未在场的 NPC 没有事实；接收者不是亲历者。
- 实际失约、道歉、后续行动完整链路；取消不算失约，道歉不刷好感。
- 活动与聊天的好感预算共用；逐事件检查，不能用批次净额掩盖中途超限。
- 活动进行中的原生进度会进入 prompt，但不会先写为已完成记忆。
- 夜间整合即使在次日生活已记录并保存之后才完成，新的印象仍可读取；重启重放不覆盖它。

## 3. 发现的问题及修复

1. **夜间状态竞态**：早期生活实现写 NPC 整体 state 快照，复现出次日生活覆盖稍后完成的昨夜印象。改成事务日志 `lifeState`，读取沿当前提交分支继承，不写整体 state。回归先在旧实现失败，修复后通过，包含保存之后才完成夜间整合的窗口。
2. **协议静默等待**：损坏生活批次原先被通用解析器忽略。当前存档 envelope 的错误生活批次改为明确同步错误；非法旧读档消息不能解除当前屏障。
3. **C# 可选字段**：普通 JSON 序列化会把 nullable 字段发成 `null`，与严格 TS 契约不符。生产和离线测试共用 `LifeEventWire`，省略 null 并保留真实 0。
4. **厨房及活动衔接**：原版厨房可能异步获取冰箱锁；改为有限等待原版烹饪页，不立即误判失败。农舍内可先结束散步，暂驻等待记录确认，再进入厨房；超时／取消释放演员。
5. **物品与额度回滚**：材料按真实物品身份跨堆扣除；写入失败恢复各堆。家庭餐失败恢复食物和好感／启动额度；已有活动结束失败也恢复实际好感。
6. **旧菜单与旧尝试**：菜单绑定 nonce／游戏日；目标绑定独立 attempt，旧回调不能扣新存档物品，也不能完成新尝试。
7. **日程控制与开关边界**：当前生活演员不被普通／节日约定、主动靠近等功能重复接管；延迟回程绑定 nonce／日，日终清空，新约定接管时删除旧回程。既有目标活动即使关闭独立活动开关仍保留结束路径；断线／等待 ACK 时只开放当前活动原生结束选项，新动作仍保持同步屏障。家庭餐与其他独立活动统一 09:00–19:00 开始。

首次全仓集成有一项夹具失败：测试里的 `goal.completed` 缺少严格协议要求的 `activity`，等待 `life.ready` 超时。按直接 `parseLifeEvents` 的错误定位补齐真实字段后通过；没有降低生产校验。另一次类型检查指出新工具的可选字段和日志回归 helper 类型，修正后重新通过。

## 4. 成本与限制

实际 `lifeContext` + `buildMessages` 的固定样例：消息正文基线 **1893 o200k token**；无生活记录增加 **0**，各生活阶段／关系样例增加 **39–110**；当前活动原生进度单独增加 **48**。详见 [实际分词 JSON](2026-11-09-life-prompt.json) 与 spec。旧莉亚草案的 65–70 不是当前实现的成本结论。

没有收费模型调用，没有新增项目依赖。分词器在仓库外临时安装；`o200k` 仅近似 DeepSeek，不含 API 消息封装、检索记忆增长及输出，不证明模型语义正确。

旧的 `tests/mod-flow` 本轮尝试运行，但在 macOS 加载 `Stardew Valley, Version=1.6.15.24356` 程序集时抛出 `System.IO.FileLoadException`（`Program.cs:23`），尚未执行其原有断言。日志在 `/private/tmp/stardew-life-old-mod-flow.log`。**本轮不能沿用历史 Windows 的 54/54 声称原生流程已通过。** 新增 73 项 C# 规则检查和 Release 编译只验证各自范围。

没有运行游戏、没有实际验证寻路、中文菜单布局、冰箱锁、真实钓获／采集识别、家庭互动或信箱呈现，也没有调用真实模型检查措辞。这些全部列入 Windows 清单。长期日志上限为 4096 条，达到时保留事实并暂停新动作，不静默截断；首次读取一个 NPC 的生活投影可能沿祖先提交扫描，之后按当前 head 缓存。
