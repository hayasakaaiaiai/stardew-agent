## 5. 实际修复：关闭当面赠礼仍写出赠礼记忆

`InPersonGifts=false` 原来只在 Mod 的 `GivePresent()` 生效，后端不知道开关；模型仍看到“可以当面送给玩家的东西”，输出 `give:true` 后，后端先记“我当面送了农场主能量滋补水。”并消耗 7 天冷却。Mod 没发物品，记忆和游戏状态就不一致。此次在保存后重读、向潘姆询问二手消息时实际触发，最终脚本没有放过交付对账失败。

修复：`talk.open` 带可选布尔值 `inPersonGifts`，Mod 使用当前配置，后端在本场对话里记住它；关闭时不给记忆包装器传入任何可送物品，模型即使输出 `give:true` 也不生成 `gift`、赠礼记忆或冷却。字段省略时保持协议 3 老客户端的行为，错误类型拒绝解析。正常开启时的 prompt 文字不变，不增加模型调用和输入 token；关闭时删除本不该出现的物品提示。

新增两项后端测试，修复前分别复现“返回蝙蝠翅膀而非 undefined”和“无效配置未拒绝”，证据为 `.runtime/offscreen-gift-switch-before-fix.log`；修复后本模块 6/6、类型检查和构建通过。覆盖强制 `give:true`、关闭时继续聊天、实际保存/后端重启后再次开启不受虚假冷却影响，以及可选字段兼容与类型校验。组合脚本还逐条核对原生关闭开关的开场没有 `gift`，并检查潘姆没有这类虚假记忆。

**未解决：remember 仍可能把未选选项改写成事实。** 最终运行里玩家只说“你画的那幅画真好看，我很喜欢。”，模型给出的尚未选择的选项有“老虎哪里凶了，很帅”，同一次 remember 却写“农场主说很喜欢我画的老虎，还说不觉得凶”。解析器会接收这个字符串；后面询问礼物、评价头发的两轮 system prompt 都出现了这条。当前仅剔除与选项/回复逐字相同的字符串，挡不住改写。这段后来按测试流程不保存退出，最终 SQLite 没有留下它，不能因此忽略当日上下文已被污染的事实。证据：`game/string-memory-content-audit.json`、`game/model-calls.jsonl`。

这是记忆来源约束仍不完整，和“能接收字符串”“0 心能回忆”技术链路通过是两回事。此次只记录，不擅自改变已确认的 remember 格式或增加新 prompt；后续需要单独设计来源校验。自由对白里也仍会添写父亲的口头禅、刚送文森特回家等经历，不能当作真实事件。

性能方面，41 次真实调用有 2 次超过 8 秒，最长 10.775 秒，P95 7.348 秒；high 的慢回复仍会偶发。不能用本次不同内容、不同缓存的汇总直接推断相对 low/disabled 的成本变化。
