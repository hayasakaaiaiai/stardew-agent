## 2. 发现并修复

1. **日终生活记录落在保存封口之后。** 活动和目标完成会连续产生两条事实，旧实现只允许一批等待 ACK，第二条可能晚于 `save.saving` 到达。真实 WebSocket 复现后端拒绝生活同步并停用同步。改为保存封口前按最多 32 条把尚未发送的事实放进现有可靠队列，保存窗口阻止额外重放，保留严格后端封口检查。新增旧顺序失败边界、正确顺序保存重读、多个在途 ACK、追加事件和分批游标回归。
2. **目标同行绕过当天成功活动限制。** 普通森林散步完成后，目标散步仍能同日再开，与 spec 的共同限制不符。统一普通、目标、接续做饭和家庭餐的成功活动检查；取消仍可以重试，其他人、其他类型与次日不受误拦。
3. **主动靠近的旧控制器可能抢回生活演员。** 新活动开始后旧靠近状态仍存活，下一帧可能恢复旧位置和破坏物体标记。成功取得活动额度后先释放同一 NPC 的旧靠近控制，再捕获新活动原始状态。原生 NPC/控制对象回归检查原值恢复与其他 NPC 隔离。

上述生产修复不新增模型调用或 prompt 文本，不增加项目依赖。

## 6. 保护与覆盖边界

环境：Windows 10 19045、Node 24.14.1、.NET SDK 9.0.202、游戏 1.6.15 build 24356、SMAPI 4.5.2。13 轮均仅使用独立存档、独立 Mods 与数据库；每轮原档六文件 SHA256 前后一致，汇总为 `.runtime/life-windows-20261109/all-run-integrity.json`。正常安装 DLL 最终哈希与起始相同，记录在 `installed-dll-after.json`；正常主工作树仍在干净 `main / 789b911`，未改正常记忆目录，收尾时没有遗留游戏进程。全部模型为固定回复，真实模型调用数为 0。

`life*` 验收显式最小化游戏窗口，同时保持失焦继续运行；正常游戏不调用该功能。实测初始窗口标志为已最小化。验收放开 SDL 息屏请求；`power-requests-live-proof.json` 在同一游戏 PID 运行前后确认 `DISPLAY` 为空。`SYSTEM` 项曾有 Realtek 音频流请求，不把“允许息屏”扩大成“系统一定会休眠”。

仍不等于用户清单全覆盖：自由模型内容、全部自然剧情／日程与地图回程、多人、完整自然抛竿、烹饪接续及超时组合、全部配置开关与好感上限组合、离线睡觉后退出重载、旧后端能力降级、不同存档／分叉路径、故事信与普通信竞争及全部新旧玩法组合尚未逐项在游戏执行。后端幂等、分叉、NPC 隔离和规则边界的离线证据与本节原生证据分别报告。
