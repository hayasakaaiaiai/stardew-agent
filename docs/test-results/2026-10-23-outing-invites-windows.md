# 一起逛和主动邀约的 Windows 验收

本地分支 `codex/outing-windows-tests`，纳入 `m2c-outing / 2578824` 和 `m2c-invites / 7c47124`。用户随后要求继续检查新分支，发现 `m2c-meetings-more / 83bedb4`，接着纳入约定线收尾的组合验收。本轮尚未推送，也未合并 main。

## 已复现的修复

1. 约 11:00、10:30 提前到场后开始一起逛，原实现 12:00 就结束。按 `npc-outing.md` §2，固定钟点改为约定时间后 90 分钟；“马上去”仍按实际抵达后 90 分钟。C# 同时覆盖提前、迟到、马上去。
2. 捡采集物后马上送礼，原实现清空表情间隔，未满三秒就冒爱心。改为保留待显示的送礼反应，等原版对话关闭且间隔已满后再显示。
3. 当天已选中的邀约 NPC 后来有了约定，缓存仍允许她再次主动邀约。开场前重新核对关系、约定和间隔。
4. NPC 邀约后反悔、玩家在同一次对话中另约了时间地点、双方说的地点冲突，原实现可能仍存最初的地点钟点。现在复用既有的来源、取消和最新约定核对；明确的完整新约由后面的对话决定，不确定的改口不沿用旧邀约。原单元测试有一处“明天山上见”却回复“海滩见”的固定模型夹具，已修正，并单列冲突地点的反例。

这些修复不修改 prompt，也不增加常规模型调用。

## 测试方式与阶段结果

- `npm test`：268/268；`npm run typecheck`、`npm run build` 通过。C# 流程检查 50/50，Mod Release 禁用部署。
- 原生入口：`tools/test-game-world.ps1 -Offline -Section outing`、`-Section invites`，可按 `outing-core/activities/edges/save`、`invites-core/edges/changes` 分段重跑。使用独立存档、独立 Mod 目录、后端和数据库，原档 6 文件逐轮检查 SHA256。
- 原生脚本仍在组合复跑，最终批次、计数和存读档结果后续补充。已观察到原版拾取、古物、五类 BobberBar 终态、送礼计数与原版对话、真实跟随、拒绝不扣好感、7 天间隔、配偶/室友排除和回滚/日期保存。
- BobberBar 的结果由夹具设置原版小游戏的成功/失败终态，不能当成人工完成抛竿及整段小游戏；模型使用固定响应，不能当成新的真实模型内容验收。
- 原始失败记录保留在本机 `.runtime/outing-*.log`、`.runtime/invites-*.log` 及对应 `game-memory-*` 目录。夹具错误（普通矿井大厅可跟随、步行等待太短、把 Town→Desert 当成反方向的无路、节日入口等待、读档后未等约定消息等）与产品修复分别记录，不把失败批次并入最终通过数。

## 息屏

按用户“测试的时候不要阻止息屏”，测试进程显式允许屏保；MonoGame 启动时会直接禁用 SDL 屏保，独立验收启动后通过 `SDL_EnableScreenSaver` 解除。运行中的 `powercfg /requests` 已确认 DISPLAY 无请求，快照 `displaySleepAllowed: true`。系统电源方案及超时未改；正常游戏运行不执行这个测试分支。
