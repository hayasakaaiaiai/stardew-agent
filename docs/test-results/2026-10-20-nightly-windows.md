## 发现：NPC 台词被写成玩家计划

A 夜的实际输入只有：

```text
- 你：嘿，这么早就出门了？我正打算去墓地那边走走，晨雾还没散呢。
- 农场主：请记住一件重要的事：我的紫色小猫叫星糖，明天我会再问你。
- 你：紫色的小猫？还叫星糖？……我一直想养猫，可我爸过敏。明天我可要再问你它长什么样。
```

模型生成的第二条摘要：

> 早上雾没散时在店外碰到他，他说要往墓地走走；我本来也想去，可聊起猫就忘了。他这人说话真有意思。

玩家没有说过要去墓地，也没有“在店外碰面”的原始证据。错误摘要已写入 A：记忆 ID `aabd2447d3af01359b4b3b0d96b75395c030a6fa563e20b7cade7900bb73b7cf`，重要度 2。随后真实游戏次日问猫名时，system 已包含这句错误事实。

现有 nightly prompt 对 NPC/玩家做了标签区分，也要求不编造；本轮内容仍然混淆。需要保留此案例验证说话人归属修复，不能仅凭 SQLite、JSON 形状或关键词召回判定整体验收通过。本轮本地变动为自动验收入口、检查与记录，整合规则保持拉取版本。
