## 发现并修复的七类问题

| 问题 | 失败证据及修复后行为 |
|---|---|
| 后天“晚上八点”漏约 | 玩家明确晚上八点、NPC 只回“八点”时，未来约定把两者当成 20:00 和 08:00。现在裸钟点继承同次约定的明确时段；后天上午八点仍为 08:00，不使用今天已经过了八点的推晚规则。 |
| 下个月日期误读成本月 | 春 26 日“下个月28号”原先误约到春 28 日。现在按 28 日季节日历换算，超过后天不预约，并给当轮婉拒提示；春 27 日“下个月1号”正确为夏 1 日，跨年同样换算。 |
| 数字日期不能指今天 | 夏 11 日“11号”被当成未知过去日期。现在指夏 11 日，当天下午两点的约定可以成立。 |
| 别的日子的取消误伤今天 | “今天说一下，后天不去海边了”因含“今天”误取消今天的约定。现在要求同一分句确实取消今天；“今天不去海边了，后天再约”仍能取消今天。 |
| 转存地面动物产品丢失堆叠 | 注入一叠 2 个金星鸡蛋后，原先 `getOne()` 只存 1 个便删除整叠。现在转存完整数量，品质保留；只能叠入部分时，剩余数量留在原地，提示和原版捡拾统计只计实际入箱的数量。 |
| 赴约好感用预计迟到判断 | 预计 15:00、实际 16:00 到，玩家没来仍扣 5；预计 17:40、实际 15:00 到则错误免扣。现在以实际 `ArrivedAt` 判断，两个方向分别为 0 和 −5；立刻邀请与隔天约定的原规则保留。 |
| 好感报告和每日合计不等于实际变化 | 好感为 0，原版不能再扣，却报告 −20；原版心数上限、友谊之书加成也会造成差异。现在读取原版变化前后的点数，报告实际变化并记入每日合计，同时约束实际每天 −40～+30。原生验证 0 分时报告 0、2248 到 2249 只记 +1、友谊之书奖励按实际数记录并和聊天共享上限。 |

日期判断共用原有解析，不增加模型调用；没有新增依赖，没有改变 prompt 格式或增加固定 prompt token。

## 待确认规则和覆盖边界

`npc-meeting-friendship.md` §2 写“配偶不加也不扣”，实现则在已碰面时给奖励、未碰面时免扣。结婚状态的 NPC 测试夹具到矿洞门口碰面后观察到 +20；这项业务含义已询问用户，本轮保留现有行为，不把文档歧义直接改成新规则。该夹具设置友谊关系状态，没有建立完整原版婚姻存档，不能把它作为所有配偶、室友的原版加分倍率证明。

本轮不覆盖全 NPC 自然日程、剧情中断、节日、真实多人、第三方动物及自定义物品，也不重复宣称上一轮随机矿层之外的场景通过。跨季上午约定检查的是日期、钟点和普通约定发布；严格原版日程是否赶得上仍由 Mod 判断。已验证的实际到场路径是餐吧和本轮其他明确列出的场景。
