## 3. 新增的后端恢复检查

入口：`tests/festival-recovery.test.ts`。所有存储使用临时目录，模型使用假实现，WebSocket 使用本地随机端口。

1. **进程被强制结束及检查点落后**：收到节日 `ack` 后强制结束独立后端进程，把检查点恢复到节日前的内容，以模拟“当天日志已落盘、收据检查点尚未替换”的状态。重启同一次读档、重发原消息后，日志逐字不变，三个 NPC 仍共用一个事件，并能继续对话及保存。强制结束是真实进程操作；检查点落后用文件回退注入，不冒充恰好杀在文件系统调用边界。
2. **重发内容冲突**：用同一序号换掉舞伴时返回同步错误，原舞伴与旁观者记忆不被覆盖；重发原内容仍正常确认。
3. **保存、重启和旧档分叉**：保存跳舞，次日又保存汤评价，再从跳舞保存点另开分支；三位 NPC 都恰好记住一条跳舞，旧档及其后续保存没有未来分支的汤评价。
4. **保存期间迟到**：当天事务冻结后送来的节日消息及其重发只确认、不修改已冻结内容，保存及次日记忆继续正常。
5. **换读档与回滚**：新 nonce 拒绝上一读档的节日包，未保存的全体旁观者记忆消失；新读档仍可正常接收新的节日结果。
6. **演员去重和重连**：同一 NPC 的大小写变体只写一次，未知 NPC 不加入；断线重连再重发不增加记忆。

这些检查通过后又并入完整 `npm test` 重跑。没有更改记忆内核。

入口：`tests/mod-flow/FestivalReadChecks.cs`，由现有 `Program.cs` 调用。通过反射执行编译后 Mod 的 `ReadFestival`，注入原版 `Event` / `NPC` 对象；不调用绘制、地图加载或真实节日事件。

## 5. 用户的游戏内测试清单

按 [节日记忆 §9](../festival-memories.md#9-windows-游戏内测试清单用户来做) 使用存档副本测试。本轮按 `AGENTS.md` 的“游戏内验证要用户来做”执行，只做编译、假模型、模拟客户端和原版对象检查；没有启动游戏、没有调用真实付费模型。

- 花舞节：只约舞伴就离开不记；看完舞蹈后舞伴和实际在场的旁观者记得。
- 冬日星：正常交礼、实际送礼人为刘易斯的替换场景，以及送礼场面中断；核对是否只记录确实发生的结果和实际人物，不编物品。
- 复活节、冰雪节：分别赢/输一次；多人情况下另一位玩家胜出时，不把胜利记给本机玩家。
- 展览会：正常名次、空展台、紫色短裤、钓鱼小游戏往返；确认小游戏切图不会提前结束节日监视。
- 夏威夷宴会：好汤、未放材料、紫色短裤及不同年份脚本；记录的评价与画面一致，不推断未知的投料人。
- 不睡觉重读当天、睡觉后重启后端、断线补发、`FestivalMemories=false`；检查回滚、保留、去重和关闭效果。

自动检查不能证明实际事件切换和画面中的舞蹈、送礼、领奖均已通过，也不能保证模型被追问时不会自由补写。`docs/scheduler.md` 仍是待确认设计，本轮没有调度器游戏清单的通过记录。
