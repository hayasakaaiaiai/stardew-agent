## 2. 本轮新增覆盖

- 11 种原生好感状态：0、1、2、4、5、7、8 心，以及 3 心时的约会、订婚、结婚、室友。每项通过原版输入框提交 `mood=+1/-1`，核对实际 `Friendship.Points`，共 33 个检查；日上限另用上游的 11 轮动态预期覆盖。重复 `talk.reply` 全程注入。
- 当天与阿比盖尔说公开事实“我养的小猫叫星糖，你可以跟朋友们说”，与未参加好感用例的哈维说“这是秘密，别告诉别人：我其实很怕黑”。真实睡觉后直接检查已整合的 SQLite 状态。
- 次日触发真实头顶聊天；听者中途离场、玩家中途换地图均不能确认。正常聊天中途打开另一位 NPC 的“继续聊”，先等这轮对话关闭，再发送 `scene.shown`，避免后端事件序号倒序。
- 每个 `scene.shown` 都重发一遍：收到确认才生成带说话人来源的 `heard` 记忆，重复不多记。问山姆能进入当天 prompt；不保存退出、同连接新 nonce 读档后消失。
- 回滚后再向塞巴斯蒂安传话，实际睡觉保存，再读档仍能回忆。SQLite 最终只保留塞巴斯蒂安的一条 `heard`，来源为阿比盖尔原始 `share`，可见性 `normal`。第三天阿比盖尔的旧 `share` 不再进入碰面 prompt。
- 新增双向传话的独立后端测试：没确认、未知请求均不记；双方确认各记一条；重复确认、保存和后端重启后，文字、归属和数量均保持。

## 3. 失败证据与修复

### NPC 离场仍被记成听到了

`.runtime/social-20261021-000413/` 在 121.46 秒、第 90 个检查失败：`news-departed-listener-not-confirmed`。塞巴斯蒂安在第一句之后已被原版 `warpCharacter` 移到农场，Mod 跳过他不在场的台词，但仍发 `scene.shown`；后端日志实际写出“塞巴斯蒂安记下了：阿比盖尔跟我说……”。

现在记录请求所在地图和两位参与者；显示过程中或延后确认期间，地图改变、任一参与者离场，就清空待显示内容并取消确认。采用保守规则：中途打断的整段都不落传话记忆，保留原来每对每天一次与四段预算，不自动补聊。不改协议或模型 prompt，正常 token 增量 0。

### 同日新读档继承上次碰面的次数和冷却

`.runtime/social-20261021-001126/` 已通过离场、对话延后和换地图检查，138.47 秒时在 `news-reload-scene-confirmed` 失败。包日志确认新 nonce 请求同一对 NPC，后端直接返回空台词，没有调用模型。原因为 `Session.scenes` 只按游戏日重置，同一个 WebSocket 上回标题再读同一天仍保留旧的四段预算及 9:00 冷却。

`tests/social-regression.test.ts` 撤掉修复得到 `0 !== 2`，证据在 `.runtime/news-reload-before-fix.log`。现在成功创建新的读档对象后才重置场景预算；同 nonce 的重宣告保留预算，无效读档不先清空旧预算。不改 prompt，正常 token 增量 0。

### 验收报告的临时文件访问错误

`.runtime/social-20261021-000706/` 在 134.91 秒、第 96 个检查后遇到 `Access to the path is denied.`，不算通过。当时只保留了异常消息，未捕获完整堆栈，不能确定占用来源。测试模式现在为报告原子写入增加最多四次、每次 20 ms 的 IO/权限错误重试，保留完整异常堆栈，并在结束后保存 SMAPI 日志；持续错误仍使验收失败。

早期脚本开发和移到最新基线时的类型检查失败也有日志，本报告仅将最后完整跑通的目录计为通过。

### 换地图夹具触发原版剧情

`.runtime/social-20261021-001656/` 已通过 33 项分档与离场/换地图检查，137.29 秒、第 101 个检查后读档时检测到 `剧情=True`，按独立副本保护条件停止，不算通过。此前换地图选的是农场，可能触发此旧存档尚未完成的原版剧情；改用没有原版事件资源的 `FarmCave`，保留对剧情、节日、玩家身份和存档 ID 的全部检查，没有强行关闭剧情绕过断言。

### 真实模型把同日的感谢台词当成新鲜事

`.runtime/social-20261021-002121/` 的首次真实夜间整合中，阿比盖尔成功生成小猫星糖的公开信息；潘妮没有传出“怕黑”，但 `share` 写了“农场主还特地谢过我帮他的忙呢。”，导致保密样例要求空字符串的断言失败，185.06 秒后停止，不算通过。当天她也参与了好感用例，确实收到过“好感1 谢谢你的帮助”。保密输入因此混有其他公开台词，最后改用未参与好感用例的哈维进行隔离测试；未修改 prompt 或把这个失败样本删掉。

这同时留下一个内容质量边界：虽然规则要求普通寒暄不写，真实模型仍可能把普通感谢选为 `share`。这个样本来自后面校正前的 `high` 夜间验收配置，不能直接当作生产 `low` 的复现；本轮没有新增关键词过滤或声称这个问题已彻底解决。

### 真实对话缺少附加字段时回退为零变化

`.runtime/social-20261021-002618/` 的夸画回复只有 `reply`，缺少情绪、选项、`mood` 等字段。现有解析器按设计回退为 0，原生好感保持 2060，没有凭空加分；但首个真实正面样本断言失败，75.07 秒后停止，不算通过。“拿战斧的兽人”画作确实在阿比盖尔卡片的 6+ 话题中，不作为事实错误样本。

验收脚本现在先采正面样本，再问礼物，避免礼物回忆先用完加分上限；若样本得到零变化，会明确留下 `...-no-change-*` 记录，并最多追加两条真实台词寻找正/负样本。若发生相反方向变化或三条都无法取得目标样本，仍使验收失败。保留全部调用、原始输出和失败目录，没有改产品解析器或隐藏零变化样本。

### 校正验收驱动的夜间推理配置

扩展真实夜间调用时，驱动最初复用了对话的 `high` 客户端，和正常后端的 `low` 不一致。已改为使用 `NIGHTLY_THINKING` 创建专用客户端：对话 `high`、碰面 `disabled`、夜间 `low`，每条调用记录和最终结果均写出 `thinking`。`.runtime/social-20261021-003006/` 在 139.88 秒时主动停止，以重新完整验证配置一致的链路，不计通过；最终只以校正后的完整目录为准。

## 5. 覆盖边界

好感关系、NPC 位置和公开/保密台词均为独立副本里的受控夹具，不代表自然约会、婚礼或全镇日程已经遍历。原版输入、显示、保存和加载实际执行；模型是否守住其他秘密仍受生成质量影响，本轮样本不能保证任意内容。`heard` 记忆引用夜间 `share`，没有新增对任意 `share` 的逐字原话核验。夜间除指定公开/保密样本外继续用固定输出隔离旧功能；未改变上游的推理强度或 prompt，也未增加运行时依赖。

## 6. 用户指出的家庭关系与截图说话人

用户指出“塞巴斯只有妹妹，没有弟弟”。已核对卡片：塞巴斯蒂安的妹妹为同母异父的玛鲁；山姆的弟弟为文森特。`news-scene.png` 是阿比盖尔与塞巴斯蒂安的碰面，`news-listener.png` 则是后续山姆的回忆，两张图不是同一位听者。

原始包里“哈哈，说过！星糖对吧？……我弟听了也吵着要养猫。”的 `npc` 明确为 `Sam`，序号 61；本轮塞巴斯蒂安的回复没有声称自己有弟弟。因此没有修改正确的角色卡。`speaker-audit.json` 保存本轮包的说话人核对，另复制带人名的图片以便区分。

山姆有弟弟这一关系是正确的，但本轮没有发生向文森特传话，“我弟听了也吵着要养猫”属于未经事件支持的扩写；阿比盖尔“我摆在窗台上了”也没有对应摆放动作。功能链路通过不等于这些自由生成细节都已获事实验证，不能把这些台词描述成游戏里实际发生的事。
