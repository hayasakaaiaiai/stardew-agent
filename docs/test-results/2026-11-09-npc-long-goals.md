## 3. 实施中的修正和兼容

1. **全局事件编号**：复核发现原共享日志只在各功能内部检查重复序号，同一个 `life-1` 可能在下一请求从材料委托改成长期目标，甚至换成另一角色。本轮在桥接层检查当前分支所有角色、四类日志的 ID 与完整规范化内容，先校验再原子写入；保存后按 head 增量缓存，分叉重建当前祖先索引，当天记录不污染历史缓存。新增同日、跨角色、跨域和保存后重启反例通过，合法回滚后复用序号仍通过。不改记忆内核。
2. **前作依赖**：先投影本批故事，再核对续篇明确引用的前作结局 ID、序号和更早日期，避免同批顺序问题。旧三故事 JSON／投影不迁移，`storiesProtocol:1` 保留，新增 `goalsProtocol:1`。
3. **存档降级保护**：首条成功的长线事件将原生生活记录升级到版本2，失败回退版本；新版仍接受无长线历史的版本1。旧 Mod 读取版本2会拒绝写生活记录，避免忽略新字段后覆盖。含长线历史的旧后端不能跳过日志推进同步游标。
4. **实际工作**：仅08:00–20:00正常完整钟步，清醒静止且无活动控制。罗宾有未完成建造时暂停本项目工作；玛鲁诊所不算工作地点。农舍额外工作地点同时核对本人名字与实际 married 状态，订婚或室友不能代替。
5. **F8 与旧功能**：一个入口合并旧调查和新章节观察，选项分页，每个动作仍分别校验各自开关和能力。菜单回调复核原存档、日期、角色距离及当前章节，防止旧选项跨章执行。
6. **实测前的小问题**：新增桥接反例和分词脚本各有一次可选字段类型检查错误，按 `exactOptionalPropertyTypes` 改为省略字段后通过。未改编译配置、降低断言或增加依赖。最终全仓测试一次通过 463/463。

## 4. 实测 prompt 成本

使用仓库外 `gpt-tokenizer@3.4.0 / o200k_base`，直接调用 `longGoalChanges → longGoalContext → buildMessages`；前作使用真实 `storyChanges` 投影。加载34卡，74样本；[原始结果](2026-11-09-long-goals-prompt.json) 保存输入、提示、比较数字和12份源SHA256。

采用只保留当前章节及完成数量的方案；全部完成后保留合册标题与真实贡献概要。新摘要增加 **0 或97–226 o200k token**，其中七人全默认完成为97–104，有贡献完成为217–226。保留已完成各章摘要的比较方案在有旧章时还会额外增加89–184 token；这两种信息量不同，不能称语义等价。玩家仍能在原版菜单阅读全部真实稿页，模型不会凭短摘要逐字重述作品。

没有增加真实模型请求。分词数字是 DeepSeek 的近似，不包含旧生活／恋爱／故事摘要、API 封装、输出和新记忆被检索召回的额外成本。
