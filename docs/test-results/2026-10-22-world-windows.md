## 执行方式

```powershell
# 完整固定模型游戏流程，无付费调用
./tools/test-game-world.ps1 -Offline
# 真实模型：晴雨日程、后台聊天、跨保存用量及已保存花舞节召回
./tools/test-game-world.ps1 -Section content
# 单项调试
./tools/test-game-world.ps1 -Offline -Section festivals
# 仅复测小游戏返回和未保存节日回滚
./tools/test-game-world.ps1 -Section fair-return
```

脚本启动真实 SMAPI 游戏进程，通过原版读档菜单进入专用 `MemoryTest_<ID>` 副本；对话使用原版对话框和输入框，睡觉、标题页、重新读档均走游戏流程。使用独立 Mod 目录、随机端口、独立 SQLite 和日志，不覆盖正常安装。原测试档先备份，结束后逐文件核对 SHA256。

`checks.json` 区分 `technical` 和 `content`：地点词的内容检查失败后继续独立游戏流程，最后仍记失败并返回非零退出码；不重复调用到“刷绿”。`result.json` 的 `technicalSuccess` 表示原版流程是否全部跑完，`success` 同时要求本轮内容检查通过。地点词命中仍只是有限抽测，不能代替对整段表述的复核。

章节切换时只在标题页修改副本的日期和天气。副本补齐原版 1.6 的地图天气字段，并预先标记玛妮宠物领养剧情已看过，避免跳日期触发与本次目标无关的提问。没有修改原档或产品 prompt，没有新增依赖。

## 已保留的调试失败

- Windows PowerShell 5 把无 BOM 的中文脚本报错文本误读；日期夹具脚本改为 ASCII 文本。
- 直接跳到哈维第二段路线会漏掉第一段路线的起点；现在按原版日程顺序执行。
- 只改存档根天气字段，原版地图天气仍晴，四人雨天日程未变；现在同时设置 Default 地图天气。
- 既有验收模式默认屏蔽真实整点消息；世界脚本显式开启该测试通道。
- SQLite 查询误用不存在的列，持久化断言在查询阶段失败；修正为实际 schema 的查询。
- 保存后的自然 NPC 分组又发起了一个后台调用，干扰“本窗口零次、只有迟到 token”夹具；现在先隔离新一天的人物，再触发下一整点，保留原用量断言。
- 连续跳日期遇到原版玛妮宠物领养剧情；副本预置已看状态。兼容源档旧式 `eventsSeen/int` 序列化。
- 仅调用 `judgeGrange` 只计算分数，并未完成评审，正确地没有节日记忆；改为原版刘易斯完整评审后再断言。
- 初始截图只抓世界缓冲，未含独立 UI 图层；对话改抓原版 UI 渲染目标，世界截图修正 OpenGL 上下方向，并等待画面稳定。
- 主组合在小游戏返回前的 193 项技术断言通过后，旧测试使用原版始终返回 `false` 的 `FishingGame.forceQuit()`，在退出步骤失败。当前源码改为原版 Esc 处理并等待自然结算/卸载。第一轮局部复测已返回节日，但在淡入未结束时立即离场卡住，证据 `.runtime/game-memory-20261022-011237` 保留；增加淡入完成并稳定一秒的条件后，`.runtime/game-memory-20261022-011602` 收尾 16/16 通过。没有强设退出成功、伪造结果或直接清掉小游戏对象。

以上是测试框架和夹具修正。失败目录和最终通过目录都保留在本机 `.runtime`，提交不含游戏原文、存档或模型密钥。

## 冬日星中断缺陷与修复

原版收礼场面一开始，Mod 就知道实际送礼人，但这不等于物品已经交付。完整固定流程的强制中断用例中，交换动画未完成，后端仍写了“我抽到给农场主送礼，礼物送到了。”初版脚本只核对刘易斯替换正确，漏掉交付事实；现增加“背包尚无收到物品”和“不产生交换记忆”的断言。

产品现在保留实际送礼人的读取时机，并额外等待原版交换场面结束、回到玩家自由操作后，才确认整项交换；删除离场时拿原抽签人物补齐的回退。不完整交换整项不记，沿用原设计不写一半的保守规则。没有新增 prompt、协议字段、模型调用或依赖，token 增量 0。

新增 C# 读取回归修复前 **32/33**，失败信息明确为“Opening the receive scene counted as a completed gift exchange”；修复后 **33/33**。期间两轮夹具反射误把原版属性当字段、再触发未初始化玩家的 setter，已改为仅设置对应状态字段，失败日志均保留。修复后的原版主组合已通过正常收礼、原版刘易斯替换和中断：中断时原版脚本命令号 6、实际送礼人 Lewis、菜单为空、收到物品数 0，没有交换消息。

## 模型内容的单独复核

首轮真实模型在潘姆雨天回答“上格斯那儿坐坐”时被过窄的地点正则拦下；这指的是酒吧，已补上别名，保留失败轮 20 次真实调用。地点断言只证明提到了目标或已知别名，不能证明整段回答没有编出额外行程。

首轮原始回答已发现额外行程：14:00 潘姆本应下一站 16:00 酒吧，却说先去 Joja 再去酒吧；雨天哈维的下一站是 17:30 酒吧，却说下午先回诊所处理杂事。阿比盖尔雨天被问晚上安排时又补了“要是天晴，也许会溜去墓地”。这些内容不能算实际游戏安排，也不能因目的地词检查通过就算事实准确性通过。原版 `HarveyRoom` 本身缺显示名时仍会回退为内部地图名，本轮没有另加地点翻译表。

本轮只修复已确定的节日完成条件；产品行程 prompt 保持原样。真实调用的输入、输出、思考档位、用量和耗时全部留档，节日、后台和保存链路的技术结果与模型内容质量分开报告。

第二轮真实组合在阿比盖尔雨天回答“星之果实酒吧，周五我常去那边窝着打游戏”时正确失败；原版当天是周一、雨天日程留在店里。此轮 17 次真实调用和失败保留。随后将内容检查改为收集失败并继续其余独立场景；既不删除该断言，也不修改模型输出或日程数据来通过。

最终轮同样捕获阿比盖尔雨天想去湖边和山洞，而日程仍留店的失败。后台回忆中，潘姆当天与保存后次日都能正确复述格斯赊账/倒酒，哈维未保存前能复述玛鲁调显微镜；回滚后 prompt 的那条观察确实消失，但模型又泛写“诊所的排班和整理药品”。后者不证明记忆没有回滚，也不能算模型正确承认没有记录。本轮没有把这些自由补写当成真实发生过的玩家行为。
