# 四条小镇调查扩展

2026-11-09。用户再次要求“推送，之后继续”。成果实践验收版已推送至 `codex/npc-project-practice / a1389a4`，本轮从该提交隔离至 `codex/npc-town-cases`。延续已授权的“事件＋NPC长期目标”，新增四条完整调查；不包含摆摊、团体活动、公共改造、H线或新的恋爱规则。

## 1. 完整体验

四案均为本Mod新写的生活小事，旧三故事保留。本人“镇上的事”明确开案后，玩家可当面询问两名证人、进行两项真实现场核验、回看个人调查笔记、选择逐条汇报，最后当面选择两种处理方案之一。结案要求四份来源齐全，两方案是对相同事实的不同处理，不是猜互斥真相。

无好感门槛、期限、物品消耗或额外奖励；不控制或传送NPC，不占用同行次数。自由聊天不能替代采访、实地核验或结案。关闭新开关 `TownCases` 后保留笔记和结案阅读，停止新推进。全程使用原版分页对话／提问框及共用F8现场菜单。

地点提示由开场和笔记直接给出，玩家不必猜未披露条件。镇广场、森林河边锚点采用已有Meetings.cs核定站点；三种室内只核实际地图及当前位置，不猜固定坐标。Blacksmith、AnimalShop、ScienceHouse对应的本机原版Maps资产已确认存在；不复制资产进仓库。

所有核验从开案后计时，绑定本案、证据ID、游戏日和地图。只计完整正常10分钟钟步，菜单／暂停不增加；离开规定地图／区域、目标NPC离开有效距离、换日或读档清掉未记录现场计时。已积满10分钟可在同一合格现场打开菜单确认，菜单暂停不会凭空加时或使刚取得的候选失效；提交时重新核对位置、时段、物品或人物在场。

样品数量字段固定为本次明确核对的一份，不表示拥有总量、消耗或提交给NPC；确认时检查真实背包仍有匹配QualifiedItemId。室内核验不记录全局天气。存在性核验记录subject及其坐标，以校验≤8格；不借用同行系统或安排玛妮走到目的地。跨日复查不要求随机天气变化。

## 3. 配置契约

新增唯一内容配置 `data/town/cases.json`，`{version:1,cases:[四项]}`，构建复制 `assets/town-cases.json`。每项：

`{id,kind:'case',owner,title,opening,references,clues,inspections,endings}`。

- `clues`恰好两项：`{id:'witness_a'|'witness_b',witness,label,text}`，证人按上表顺序；本人不担任自己案的证人。
- `inspections`恰好上表两个ID；共同字段 `{id,mode,venue,label,hint,minutes:10}`。mode是site/sample/presence。
- site额外 `site:{x,y,radius}`，仅上表固定坐标；Evelyn.return再有 `after:'first',laterDay:true`。
- sample额外 `itemId,itemLabel,count:1`，仅上述两种矿石。
- presence额外 `subject:'marnie',from,to`，只允许上表两个时窗。
- `endings`恰好a/b两项：`{id,label,title,text}`，完整原创可阅读结案页。标题／台词禁止原版控制字符；references覆盖owner和两位证人的角色卡及wiki，原创案情不假冒原版剧情事实。

## 4. 日志、知识和结案

复用已有story域、全局life-N、32条混合批次、`log.storyState/storyEvents`及跨NPC原子写入。旧三故事JSON、事件、包裹与长期目标依赖ID原样保留。新内容与配置验证放独立town-cases模块；旧STORY_DEFINITIONS仍代表旧三条，内部合并新四案供查询和投影。

新案复用 `story.started/clue/told/resolved`：

- base仍 `{id,npc,day,kind,storyId}`，npc为本案owner。
- started无额外字段。
- clue仅 `{clueId,other}`，指定证人及其witness_a/b；不能拿旧parcel线索或缺other伪造新现场。
- told仅 `{sourceId}`，必须引用本案早于当前事件的未汇报证词或inspected来源。
- resolved仅 `{outcome:'a'|'b'}`，必须已取得本案两证词与两现场，日期及序号自洽。结案等于明确当面提交四条来源，原子披露给owner；不要求额外逐条汇报。重复结案、新增结案后线索均拒绝。

唯一新kind为 `story.inspected`。除base，必需字段 `{clueId,venue,x,y,time,minutes:10}`；x/y为0..500整数，time合法06:00–22:00的10分钟刻度：

| 模式 | 额外且仅允许的字段 |
|---|---|
| site | weather：sunny/rain/storm/snow/windy；Evelyn.return另需sourceId精确引用first，day严格更后 |
| sample | itemId为配置的准确ID，count=1 |
| presence | subject='marnie',subjectX,subjectY，坐标同0..500并与玩家欧氏距离≤8格；当前time落在对应from/to内，且能在时窗内完成此前10分钟 |

现场只写玩家调查进度，不给owner添加已知信息；证词只让实际证人知道自己说过的那条。owner通过told或明确结案才获知相关来源，其他证人不会自动知道结局。NPC可同时是自己案主人公及别案证人，不混淆角色。结局正文只写已核事实和选定建议，不改变营业、家庭关系、日程、原版事件或世界设施。

## 5. 原生与兼容

原生新建TownCases.cs／TownCaseRules.cs与LifeSave.Cases，旧TownStories专用逻辑不泛化。入口共用“镇上的事”、F8和原版分页；读取笔记是给玩家查看，不能因此生成当面汇报。就绪判定同时覆盖新案能力，关闭旧TownStories不删除或误禁用独立TownCases入口。

保持storiesProtocol:1，新增casesProtocol:1。有新案历史而后端缺能力时停止混合同步和新聊天，不跳未知事件后假装就绪。第一次新案事件成功写入才升级LifeSave至4；新版接受1–4，缺Cases默认为空，所有旧域版本更新只能升不能降。写失败恢复版本／序号／状态，原始旧档不重写；旧Mod遇4拒写并保留原JSON。Native的旧故事校验只跳过固定四案ID且交新案验证，不放过任意未知故事。

Case保存状态必须依完整日志重放校验实际来源和选定结局正文。临时观察时钟不跨读档；已记录证据和结局随存档与后端分支保存、重启和回滚。新域无需新记忆内核API。

## 7. 实现与实测记录

四案按上述契约实现，8 证词、8 核验和8份原创完整结案均已写入共享 JSON；11位实际参与居民仍沿用34张原角色卡，没有新增角色事实。原生在开启、采访、笔记、结案和回读时显示真实正文；结案全文依所选方案存入本案状态，并与原始事件重放核对。地图、样品和人物核验分别保留自己的字段，不记录室内天气，也不引入世界变化或物品结算。

生产实测使用34张角色卡及54个场景，见 [分词结果](test-results/2026-11-09-town-cases-prompt.json)：无案件或无关居民8场景增量0，其余46场景增加71–380 o200k token；乔迪同时知道两案自己的证词为211，皮埃尔已有旧包裹证词后新增路线证词再增加71。附完整案件资料的反例另增650–1323，且含未选内容，不用于生产。实际摘要列出已汇报的证词和现场事实，不只显示进度数字；没有自动透露尚未汇报的来源或结案全文。gpt-tokenizer 3.4.0仅在外置工具目录运行，未增加依赖，未调用模型；42份源码／角色卡哈希可复核。该数字不含API封装、输出、历史和检索增长。

实现没有新增第六个日志域，保留原storyState版本1，使用固定新案ID区分；旧的STORY_*导出仍为三故事，新增ALL_STORY_*供内部装载，避免旧调用误收新案。这是原生单独Cases、后端共用故事投影的具体实现方式，行为与设计一致。已满10分钟的现场候选在打开菜单时保留，未完成区间的暂停则不计时；确认会重新核实位置、样品／本人和时窗。玛妮除记录格点距离外，还以原版实际浮点位置核对八格及同一地点对象。
