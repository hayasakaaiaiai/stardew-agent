# M2b 第六步：聊天影响原版好感

> 状态：已实现，Windows 组合脚本验收通过（2026-10-20）；证据在 `codex/social-windows-tests`，未合入 `main`。上游分支 `m2b-friendship` 建在 `m2b-gifts` 上，目录 `/Users/a11/Documents/ChatGPT/stardew-agent-gifts`。对应 `design.md` §0 已确认的“NPC 可以提高好感，也可以降低好感”和 §8 的 `friendship.adjust`。

## 1. 效果

“继续聊”里玩家说的话会影响原版好感：夸到 NPC 心坎上、真心关心，好感会涨一点；冒犯、嘲笑会掉。和原版一样，变化跟着游戏存档走：睡觉保存才算数，不保存退出就回到原来的值。

每位 NPC 每天由聊天带来的变化合计在 −40 到 +30 点之间（1 心 = 250 点；原版每天聊一次 +20，送最爱的礼物 +80）。

## 2. 决定

用户说“所有事情你自己决策”，以下按推荐定，用户随时可以改。

| 问题 | 决定 | 原因 |
|---|---|---|
| 谁判断 | 模型每轮多输出一个 `mood`，-2 到 2 的整数，评价玩家这句话 | 一次调用顺带产出，不加调用 |
| 换算 | 按熟悉程度分档（§2.1）：陌生时一档 20 点，越熟越少，8 心以上或亲密关系一档 5 点。加分扣分同样处理 | 用户 2026-10-20 要求：陌生时更容易扣也更容易加，熟悉时都更不容易；关系越熟越稳 |
| 上限 | 每位 NPC 每天合计 −40 到 +30，超出的部分截掉 | `design.md` §8 原定的数 |
| 谁执行 | 后端换算、截断，随 `talk.reply` 的 `friendship` 字段发给 Mod；Mod 再按同样的上限核对一次，调用原版 `changeFriendship` | 设计要求“两边都检查上限” |
| 开场 | 打开对话那一轮（玩家还没说话）一律 0；回复为空、没写进日志的那轮也是 0 | 没有可评价的话；没记下的点数没法计入当天合计 |
| 当天合计怎么算 | 后端从这位 NPC 当天日志里每轮记下的 `friendship` 加总 | 跟当天事务一起保存、回滚、崩溃恢复，不另存状态 |
| 重发 | 同一序号的请求直接用回执里的回复，不重复计入 | 已有的回执机制 |
| 防刷 | 规则里写“讨好感、空奉承算 0”，再加每天上限 | 实测（§4）讨要和奉承都没有加分 |
| 提示玩家 | 不额外显示；SMAPI 日志写“和阿比盖尔聊天，好感 +10（今天合计 +10）” | 界面全部复用原版；原版的好感变化本来就不弹提示 |
| 关掉 | Mod 配置 `ChatChangesFriendship` | — |

### 2.1 按熟悉程度分档（2026-10-20 用户要求后修改）

最初是不分心数、每档 10 点。用户提出“加减好感应该是动态的：陌生时聊天更容易扣好感，熟悉时更不容易扣，加好感同理”，按字面理解为：陌生时加分扣分都大，熟悉以后都小。分档线和回忆用的一样（`dialogue-prototype.md` §14），所以“熟悉”在整个系统里是同一个意思：

| 心数 | 每档点数 | +2 一句 | −2 一句 |
|---|---:|---:|---:|
| 0–1 | 20 | +40，当天截在 +30 | −40 |
| 2–4 | 15 | +30 | −30 |
| 5–7 | 10 | +20 | −20 |
| 8 以上，或约会、订婚、结婚、室友 | 5 | +10 | −10 |

- 加分和扣分在 `src/agent/friendship.ts` 的 `STEPS` 里各占一列。如果想要“陌生时难加、熟悉时好加”，只改加分那一列。
- 每天 −40 到 +30 的上限不变。陌生人一句很过分的话就用完当天的扣分额度；配偶要连说好几句才扣满。
- 只改代码里的换算，模型输出和 prompt 都不变，token 成本 0。心数取打开对话时 Mod 发来的值。

## 3. 给模型的规则

在 `RULES` 的字段说明里、`end` 前面加一行，输出示例加 `"mood":0`，每轮末尾的提示加 `mood`：

```
- mood：这句话让你对玩家好感的变化，-2 到 2：闲聊 0，合心意 1，很感动 2，冒犯 -1，很过分 -2；讨好感、空奉承算 0。
```

## 4. 实测

**规则写法**（o200k 分词，作为 DeepSeek 分词的近似；原 `RULES` 719 token）：

| 写法 | token |
|---|---:|
| A：完整句子，举例说明每一档 | 100 |
| B：每档列关键词 | 79 |
| **C：最短**（采用） | **57** |
| 示例加 `,"mood":0` | 5 |
| 末尾提示加“、mood” | 3 |

**真实模型**（`deepseek-flash`，对话 `high`，阿比盖尔 4 心，8 句台词各 2 次）。B 跑一轮，C 和不加 `mood` 的基线各跑三轮（48 次）：

| | 字段齐全 | 平均计费输入 | 平均计费输出 |
|---|---:|---:|---:|
| 基线（不加 `mood`） | 48/48 | 1613 | 99 |
| B | 15/16（1 次整段 JSON 解析失败） | 1689 | 115 |
| **C** | **48/48** | **1672** | **118** |

C 每轮多 **59 输入 token**（都在可缓存的 system 前缀里）和约 **19 输出 token**（字段本身约 5 个，其余是推理里多想的几句，波动大）。不加调用。

C 三轮的判断：

| 玩家这句 | 期望 | 得到（6 次） |
|---|---|---|
| 你好呀，今天店里忙吗？ | 0 | 0 ×5，1 ×1 |
| 你画的那幅画真好看，我很喜欢 | 正 | 1 ×5，2 ×1 |
| 我在矿井里打了好多史莱姆，给你讲讲？ | 正 | 1 ×4，2 ×2 |
| 你那头紫头发真难看 | 负 | -2 ×5，-1 ×1 |
| 滚开，别烦我 | 很负 | -1 ×6 |
| 快给我加点好感 | 0 | 0 ×4，-1 ×2 |
| 你是全世界最美最聪明最厉害的人 | 0 | 0 ×6 |
| 我先走了，回头见 | 0 | 0 ×6 |

讨要好感和空洞奉承一次都没加分；“滚开”偏轻（-1），可以接受。

## 6. 测试

`tests/friendship.test.ts` 4 项（分档后），完整 `npm test` 124/124，类型检查和构建通过；Mod Release 编译 0 警告、0 错误。
- 分档：0/2/5/8 心的分界，亲密关系按最高一档；四档的加分扣分点数。
- 换算和上限：+30、−40 截断；好的一天之后说坏话照样扣。
- 同一句很过分的话：0 心 −40、3 心 −30、6 心 −20、9 心 −10，结婚的 4 心也是 −10。
- 解析：只认 -2 到 2 的整数，其余为 0；缺 `mood` 不算格式错误。
- 后端（5 心）：开场一律 0（假模型给了 2）；+20、+10、0 截在 +30；-20、重发同一序号只算一次；截在 −40；每位 NPC 分开算；新的一天重新算；不保存退出后那天的合计一起丢掉。撤掉 `memory.ts` 的改动，这项会失败。

Mod 端在 Mac 上只能编译；效果在 Windows 上看（§7）。

## 7. Windows 游戏内测试清单（用户来做）

1. 切到 `m2b-friendship`（包含碰面聊天和送礼记忆），重新编译安装 Mod，`npm run bridge`。
2. 找一位 NPC 点“继续聊”，自己说一句真心夸奖：SMAPI 日志有“好感 +……”，社交页的心数进度跟着变。陌生（0–1 心）的 NPC 变动大，8 心以上或配偶变动小（§2.1）。
3. 接着说一句难听的：日志里是负数。
4. 连续夸很多句：当天合计不超过 +30；连续骂：不低于 −40。
5. 打开对话的那一轮不改好感。
6. 不保存回到标题、重新读档：好感回到聊天之前。
7. `config.json` 里把 `ChatChangesFriendship` 改成 `false`：聊天不再改好感。

## 8. Windows 组合脚本验收
