# 传送赴约：从入口赶去，争取准时

> 状态：用户 2026-10-22 说“继续做下一步 需要向我提问”。合并 Windows 的 `codex/call-off-windows-tests` 时问到“NPC 自己迟到算不算爽约”，用户答“想办法让 npc 不会迟到 可以考虑传送到指定位置”；再问传送方式，选“赶不上就趁你看不见时传送”。上游在 `m2c-farm-animals / c8e9821` 实现（§5）；Windows 修复与限定原生 263/263、用户选择的入口临时快走见 §8。旧清单保留在 §6。

## 1. 为什么做

以前走路赶不上约定时间时有两种结果：

- 当天约的（`npc-same-day-meetings.md`）：立刻出发、晚到。“现在陪我下矿吧”答应了以后，玩家先到矿洞门口，要等 NPC 从镇上走一两个游戏小时。
- 隔天约的、约到后天的（`npc-meetings.md`、`npc-later-meetings.md`）：干脆不去，只在 SMAPI 日志里写“来不及在约定时间到”（比如约在沙漠、姜岛，出发太晚）。

Windows 验收还发现，晚到时记忆和等待时间都容易算错（已由 Windows 修成按实际到达算）。用户要的是 NPC 不迟到。

## 2. 决定

| 问题 | 决定 | 谁定的 |
|---|---|---|
| 怎么尽量赶上约定 | 能按时走到的照常走路；走路赶不上的，以及“马上去”的，只要玩家不在他所在的地图，就直接出现在约定地点 | 用户；入口快走和例外见下文 |
| 玩家一直和他在同一张地图 | 不传送，免得当面消失（Windows 上一轮把“配偶当面消失”当成问题修掉了）；玩家一离开这张地图他就先到 | 用户（选项里写明） |
| 玩家已经在约定地点那张地图 | 不直接出现在等的位置，而是从这张地图的一个出入口进来（优先玩家看不到的出入口；都看得到时就从门口进来，像平常有人进门），再走过去 | 自定：“看不见时传送” |
| 入口步行也赶不上 | 固定钟点的约定按剩余路径和游戏钟速临时快走，最高步速 4，抵达／取消／到期／清理后恢复；“马上去”仍按原步速走 | 用户 2026-10-22 Windows 实测后选择“从入口进来，必要时临时快走，争取准时” |
| 什么时候开始可以传送 | 约定时间前半小时起；“马上去”的、或者已经过了那个时候的，从下一个十分钟起 | 自定：早到不超过半小时，免得在沙漠一等一上午 |
| 隔天约、约到后天的 | 也一样：以前赶不上就不去，现在也趁看不见时过去 | 用户（选项里写明） |
| 原日程 | 从可以传送的那一刻起到离开为止的原日程站先拿掉（和走路去时一样），离开时从约定地点回原日程；取消时放回（Windows 的 `Original`/`Origin` 照用） | 沿用 |
| 太晚 | 可以传送的时刻晚于 21:00 就不去（后端已经不接 21:00 以后说的“马上去”） | 沿用 |
| 赴约好感里“NPC 自己迟到不算爽约” | 按实际到达时间：说定了钟点的当天约定，实际到得比约定晚才不扣；有了传送基本不会出现 | 自定（问的时候用户选了不迟到，这条留作保险） |
| 配偶 | 不变（约在地牢门口的本来就是趁看不见时从家里出门） | 沿用 |
| 提示 | “马上去”的提示改成“和阿比盖尔约好马上在矿洞见”，定了钟点的仍是“约好 15:00 在海滩见” | 自定：传送以后不会再有推迟的时间 |

## 3. 成本

只改 Mod，后端和 prompt 不变：0 token、0 次调用。

## 4. 做法（Mod `Meetings.cs`）

- `PlanMeeting`：照旧先算走路的出发时间；走路赶不上（或算不准从哪出发、原版寻路找不到去的路）时，不再晚到或放弃，改成 `Warp`：`Depart = WarpDeparture(约定时间, 现在)`（约定前 30 分钟，最早下一个十分钟），从那一刻到离开的原站照样拿掉，只插回程那一站，不插去程。
- `WatchMeeting` 每次先看 `Warp` 的约定：到了 `Depart`、没有剧情、不在和玩家说话、没有被别的控制器占着，并且 NPC 不在玩家所在的地图，就：
  - 玩家不在约定地点那张地图：直接传到等的位置，面朝原定方向；
  - 玩家就在那张地图：传到这张地图某个出入口旁边能走到等的位置的空格（优先在屏幕外），再用原版寻路走过去。
- 之后和走路到的一样：到了记实际到达时间（Windows 的 `RecordArrival`）、招呼、等 90 分钟、回原日程；农场的从巴士站那一格照常进农场。
- 当天约定不再算“推迟后的时间”（`SoonestMeeting` 只剩配偶用）。

## 5. 实现结果（2026-10-22）

- C# 流程检查新增 1 项：`WarpDeparture` 是约定前 30 分钟、最早下一个十分钟。
- 合并后 Mac 上 252/252（连跑两次）、类型检查、构建、Mod Release 0 警告 0 错误；C# 流程检查共 45 项（Windows 的 43 项加赴约好感分档、传送时刻各 1 项）能编译，要在 Windows 跑。
- 游戏里的传送要在 Windows 上测。

## 6. Windows 游戏内测试清单（用户来做）

1. 上午在镇上和阿比盖尔说“现在陪我下矿吧？”，她答应后提示“和阿比盖尔约好马上在矿洞见”。你一直和她在镇上时她不消失；你离开镇子去山上，到矿洞门口时她已经在等，SMAPI 日志“直接到了矿洞”。
2. 你先跑到矿洞门口站着等：她从山上地图的出入口进来，走到门口（日志“直接到了矿洞的入口，走过去”），不是在你眼前凭空出现。
3. 14:30 在沙漠约“三点海边见”：以前会晚到，现在你离开沙漠后她在 15:00 前出现在海滩；SMAPI 日志不再有“来不及在约定时间到”。
4. 前一晚约好第二天上午在骷髅洞穴见、而她走路赶不上的：第二天她趁你不在时到沙漠门口，不再不去。
5. 走路来得及的约定（镇上约广场）照旧走过去，路上看得到她。
6. 已经传送过去等着的约定，你在她到之前说“今天不去了”：她回原日程该在的地方，原站照常（Windows 的取消归程）。
7. 赴约好感：传送到了、你来了加分，你没来扣分。

Windows 现有脚本里有两处断言要跟着改：`same-day-late-fixed-time-reschedules-native-route` 等“14:30 在沙漠约三点海边”一组原来期望推迟到达时间、真实走过去，现在应是传送准时到；`same-day-too-late-native-client-rejects-instead-of-walking`（20:30 说“现在去矿洞”）原来期望去不了，现在 20:40 可以传送过去。

## 7. 这次不做

- 玩家一直和 NPC 待在同一张地图时让他先走一步：仍然走路，赶不上就等你离开再到。
- 回程也传送：离开时照旧走原版日程回去。

## 8. Windows 验收与修复（2026-10-22）

`codex/meeting-warp-windows-tests` 从已推送的 `b1c34f4` 整合 `c8e9821`，保留日期判断、动物物品守恒、实际好感记账以及用户已确认的配偶／室友赴约豁免。两个实现里对“实际迟到”的判断保持为同一条规则；共用 `readClocks` 时保留跨季日期回归。

原生故障注入发现：2030 约好马上下矿，下一次可处理时已到 2200，原实现仍传到矿洞门口，再报告没等到玩家，实际扣 5 点。现在未抵达的传送约定到期即恢复完整原日程，不再传送，不报告赴约／失约，也不改好感。该判断同时覆盖传到入口但尚未走到等候点的情况。

脚本入口仍是 `tools/test-game-world.ps1`，新增 `meeting-warp`（同图保护、直接抵达、入口步行、归程、取消和实际好感）、`meeting-warp-places`（11 个地点及原版剧情中断）与 `meeting-warp-edges`（晚间和过期）。原本“马上去”必须走路、下午三点必然晚到、2030 必须拒绝的旧断言，按已经确认的传送设计改为检查原说定时间、真实抵达和归程；仍单独保留走得及的原版寻路对照。

杂货店首轮失败实际是副本触发原版事件 `3102768`，不是无入口；诊断证明入口 (6, 29) 能走到等候点。保留失败，补成“原版剧情期间不传送、通过原版 skipEvent 跳过后恢复入口步行”的检查。原始游戏文本与反编译诊断只保存在忽略目录，不提交。

正常步速 2、原版钟速的海滩检查实际为 1430 约 1500、1440 从入口进来、1510 才到。用户已选“从入口进来，必要时临时快走，争取准时”：固定钟点的约定按入口剩余路径、到说定钟点的时间和原版钟速算所需步速，最多提高到 4；原步速已经足够时不改，“马上去”没有固定截止钟点则照常走。抵达、取消、过期或清理约定时恢复进入该段路之前的步速。仍不能保证玩家一直同图或约定前才允许入场时绝不迟到，实际迟到的失约豁免保留。只改 Mod，不增加模型或 prompt 成本。

最终 Node **258/258**、C# **46/46**、类型检查和构建通过；限定原生 **263/263**、3 次真实保存、49 次真实读档，原档 6 文件 SHA256 不变。海滩原版钟速样本从 1510 改为 **1500 到达**，步速 4 → 2；立即邀请仍为 2。还覆盖 11 个地点、原版剧情暂停／恢复、取消及过期恢复步速、配偶／室友、保存和回滚。各批最终源码与 DLL 相同，失败、精确范围及边界见 [报告](test-results/2026-10-22-meeting-warp-windows.md)。本轮本地提交，正常安装与后端不部署。
