# 不会迟到：走路赶不上就趁玩家看不见时直接到

> 状态：用户 2026-10-22 说“继续做下一步 需要向我提问”。合并 Windows 的 `codex/call-off-windows-tests` 时问到“NPC 自己迟到算不算爽约”，用户答“想办法让 npc 不会迟到 可以考虑传送到指定位置”；再问传送方式，选“赶不上就趁你看不见时传送”。已实现（§5），等 Windows 验收（§6）。在 `m2c-farm-animals` 上（和合并 Windows 修复同一个合并提交之后）。

## 1. 为什么做

以前走路赶不上约定时间时有两种结果：

- 当天约的（`npc-same-day-meetings.md`）：立刻出发、晚到。“现在陪我下矿吧”答应了以后，玩家先到矿洞门口，要等 NPC 从镇上走一两个游戏小时。
- 隔天约的、约到后天的（`npc-meetings.md`、`npc-later-meetings.md`）：干脆不去，只在 SMAPI 日志里写“来不及在约定时间到”（比如约在沙漠、姜岛，出发太晚）。

Windows 验收还发现，晚到时记忆和等待时间都容易算错（已由 Windows 修成按实际到达算）。用户要的是 NPC 不迟到。

## 2. 决定

| 问题 | 决定 | 谁定的 |
|---|---|---|
| 怎么做到不迟到 | 能按时走到的照常走路；走路赶不上的，以及“马上去”的，只要玩家不在他所在的地图，就直接出现在约定地点 | 用户 |
| 玩家一直和他在同一张地图 | 不传送，免得当面消失（Windows 上一轮把“配偶当面消失”当成问题修掉了）；玩家一离开这张地图他就先到 | 用户（选项里写明） |
| 玩家已经在约定地点那张地图 | 不直接出现在等的位置，而是从这张地图的一个出入口进来（优先玩家看不到的出入口；都看得到时就从门口进来，像平常有人进门），再走过去 | 自定：“看不见时传送” |
| 什么时候开始可以传送 | 约定时间前半小时起；“马上去”的、或者已经过了那个时候的，从下一个十分钟起 | 自定：早到不超过半小时，免得在沙漠一等一上午 |
| 隔天约、约到后天的 | 也一样：以前赶不上就不去，现在也趁看不见时过去 | 用户（选项里写明） |
| 原日程 | 从可以传送的那一刻起到离开为止的原日程站先拿掉（和走路去时一样），离开时从约定地点回原日程；取消时放回（Windows 的 `Original`/`Origin` 照用） | 沿用 |
| 太晚 | 可以传送的时刻晚于 21:00 就不去（后端已经不接 21:00 以后说的“马上去”） | 沿用 |
| 赴约好感里“NPC 自己迟到不算爽约” | 按实际到达时间：说定了钟点的当天约定，实际到得比约定晚才不扣；有了传送基本不会出现 | 自定（问的时候用户选了不迟到，这条留作保险） |
| 配偶 | 不变（约在地牢门口的本来就是趁看不见时从家里出门） | 沿用 |
| 提示 | “马上去”的提示改成“和阿比盖尔约好马上在矿洞见”，定了钟点的仍是“约好 15:00 在海滩见” | 自定：传送以后不会再有推迟的时间 |

## 3. 成本

只改 Mod，后端和 prompt 不变：0 token、0 次调用。

## 4. 做法（Mod `Meetings.cs`）

- `PlanMeeting`：照旧先算走路的出发时间；走路赶不上（或算不准从哪出发、原版寻路找不到去的路）时，不再晚到或放弃，改成 `Warp`：`Depart = WarpDeparture(约定时间, 现在)`（约定前 30 分钟，最早下一个十分钟），从那一刻到离开的原站照样拿掉，只插回程那一站，不插去程。
- `WatchMeeting` 每次先看 `Warp` 的约定：到了 `Depart`、没有剧情、不在和玩家说话、没有被别的控制器占着，并且 NPC 不在玩家所在的地图，就：
  - 玩家不在约定地点那张地图：直接传到等的位置，面朝原定方向；
  - 玩家就在那张地图：传到这张地图某个出入口旁边能走到等的位置的空格（优先在屏幕外），再用原版寻路走过去。
- 之后和走路到的一样：到了记实际到达时间（Windows 的 `RecordArrival`）、招呼、等 90 分钟、回原日程；农场的从巴士站那一格照常进农场。
- 当天约定不再算“推迟后的时间”（`SoonestMeeting` 只剩配偶用）。

## 6. Windows 游戏内测试清单（用户来做）

1. 上午在镇上和阿比盖尔说“现在陪我下矿吧？”，她答应后提示“和阿比盖尔约好马上在矿洞见”。你一直和她在镇上时她不消失；你离开镇子去山上，到矿洞门口时她已经在等，SMAPI 日志“直接到了矿洞”。
2. 你先跑到矿洞门口站着等：她从山上地图的出入口进来，走到门口（日志“直接到了矿洞的入口，走过去”），不是在你眼前凭空出现。
3. 14:30 在沙漠约“三点海边见”：以前会晚到，现在你离开沙漠后她在 15:00 前出现在海滩；SMAPI 日志不再有“来不及在约定时间到”。
4. 前一晚约好第二天上午在骷髅洞穴见、而她走路赶不上的：第二天她趁你不在时到沙漠门口，不再不去。
5. 走路来得及的约定（镇上约广场）照旧走过去，路上看得到她。
6. 已经传送过去等着的约定，你在她到之前说“今天不去了”：她回原日程该在的地方，原站照常（Windows 的取消归程）。
7. 赴约好感：传送到了、你来了加分，你没来扣分。

Windows 现有脚本里有两组断言要跟着改（`tools/game-same-day-meetings.ts`）：

- “14:30 在沙漠约三点海边”：`same-day-late-fixed-time-reschedules-native-route` 原来期望 `Time > 1500`、走原版路线，`same-day-late-fixed-time-reaches-native-beach` 原来等路线走完；现在 `Time` 仍是 1500、`Warp` 为真、`Depart` 是 14:40，脚本把玩家传到海滩旁边，所以她从海滩的出入口进来再走到等的位置。
- “20:30 说现在去矿洞”：`same-day-too-late-native-client-rejects-instead-of-walking` 和 `same-day-too-late-uses-native-failure-hud` 原来期望去不了、提示“今天去不了矿洞了”；现在 20:40 可以传送过去，提示“和阿比盖尔约好马上在矿洞见”。

`tools/game-meeting-friendship.ts` 的 `actually-on-time-despite-late-estimate`（沙漠 14:30 约三点海边、玩家不来）现在也走传送，预期 −5 不变，但到达时刻由传送决定，要重跑确认。

## 7. 这次不做

- 玩家一直和 NPC 待在同一张地图时让他先走一步：仍然走路，赶不上就等你离开再到。
- 回程也传送：离开时照旧走原版日程回去。
