# M2b 第三步：NPC 寄信

> 状态：Windows 脚本验收通过并保留失败记录（2026-10-20）。上游 `m2b-mail` / `fa3e818` 建在 `m2b-bubbles` 上；Windows 在 `codex/mail-windows-tests` 完成寄信验收及格式失败恢复。最新 103/103 Node、18/18 C#；引用超限现保留待恢复、有限补跑，成功后刷新信件，见 [恢复报告](test-results/2026-10-20-nightly-recovery.md)。原寄信验收见 [Windows 报告](test-results/2026-10-20-mail-windows.md)。未合入 `main`。对应 `design.md` §8 的 `mail.send`。

## 1. 效果

前一天和玩家有约定、道谢或者还没得到回答的邀请时，NPC 当晚写一封短信，第二天早上出现在农场的信箱里，用原版的信件界面阅读，落款是 NPC 的名字。比如约好做风筝，第二天收到阿比盖尔的信：“说好一起做紫色风筝的，可别忘啦。我还没凑齐材料，到时候一起想办法吧。”

关系好（6 心以上或在约会、订婚、结婚）时，信里还可能附上一样 NPC 自己拿得出的东西，规则见 §8。

## 2. 决定

用户确认按推荐做寄信。具体选择如下，用户随时可以改：

| 问题 | 决定 | 原因 |
|---|---|---|
| 信在哪写 | 夜间整合时顺带写，和计划、气泡放在一起 | 白天不调用模型 |
| 什么时候写 | 只在双方约好的事、想道谢、还没得到回答的邀请时写；普通闲聊不写 | 第一版规则写的是“有值得写的事”，10 次写了 9 封，聊过 3 个 NPC 第二天就是 3 封信，太频繁 |
| 每天几封 | 最多 1 封；几个 NPC 都写了，选当晚记下的事最重要的那位（重要度一样按名单顺序） | 原版里 NPC 来信也是偶尔才有 |
| 长度 | 不超过 80 字，不写称呼和落款；落款由 Mod 按原版格式加 | 原版信件也是短信 |
| 日期 | 按收信那天的角度写：“今天”是收信当天，“昨天”是聊天那天；不写“明天、后天” | 信是第二天早上读的，按写信那晚说“明天”会差一天 |
| 安全 | 规则要求不写已经做了的进展、没约好不说约好；代码再过滤，整封信有一句不合格就不寄 | 同气泡 |
| 附件 | 关系好时可以附一样，规则见 §8 | 用户中途要求；原来的“不带物品”作废 |
| 什么时候进信箱 | 读档就绪、新的一天开始、当晚整合完成时，后端把当天的信发给 Mod，Mod 放进信箱 | 整合通常比第二天开始晚几秒，所以整合完成时还要发一次 |
| 存档和回滚 | 信箱和已读信件本来就跟着游戏存档；信的正文由 Mod 写进 SMAPI 的存档数据，也只在游戏保存时才落盘。不保存退出，信和正文一起丢掉；读旧档时按那个存档点重新寄 | 不用另外处理回滚 |
| 去重 | 每封信有固定编号（存档线、提交、NPC 算出来）；信箱里已有、已读过的不再放 | 同一天收到两次发信（整合完成时又发一次）也只有一封 |
| 写不写记忆 | 不写。信只是表达，NPC 不会“记得自己写过信” | 同气泡 |
| 农场帮手（联机） | 不寄 | 记忆只按主玩家管理 |

## 3. 给模型的规则

在夜间整合规则的 `bubbles` 后面加一条，输出示例加 `"letter":"……"`：

```
- letter：今晚可以给农场主写一封短信，明天早上送到农场主的信箱。只在有特别想说的事时写：双方约好的事、想道谢、还没得到回答的邀请；普通闲聊不写，写 ""。不超过 80 字，口语，像写给朋友的便条，不写称呼和落款。按收信那天的角度写：“今天”指收信那天，“昨天”指你们聊天的那天；不写“明天、后天”。不写已经做了什么、东西已经备好之类的进展；没约好的事不说成约好了。
```

代码过滤：去掉原版信件会当作指令的字符（`^ @ % # $ { } * [ ] |`）和表情符号；超过 100 字、含“已/已经/昨晚/昨夜/刚才”、含“明天/后天/前天/今晚”这类日子（“今天、昨天”允许）、含“做好了/备齐了”这类完成说法（“就好了”和“……了吗/……了没”问句不算）的，整封不寄。Windows 反例补充拦截“扛来了、带来了、折出来了、转了一圈”等完成动作；不直接拦截所有“了”，保留“记牢了”和随信“附、塞”东西的便条。词规则仍不能覆盖任意自然语言事实。

另一条 `gift` 规则写在 `letter` 后面（§8）。

## 4. 实测

`deepseek-flash`，整合 `low`，`tools/nightly/facts-fixtures.ts` 的 5 组样例，每组 2 次，基准是已经加了气泡的整合规则。

| | 加信之前 | 加信之后 |
|---|---:|---:|
| 输入 token（DeepSeek 计费） | 903–934 | 1031–1062，每组 +128 |
| 规则本身（o200k） | — | 151 |
| 输出 | 一封信本身约 30–60 token；10 次平均的差别小于推理本身的波动 | — |

收紧后的规则写了 6 封：

| 样例 | 信 | 过滤 |
|---|---|---|
| 原失败案例（玩家说明天还会问猫的事） | “说好了要再问你星糖的事，可别忘了。我爸过敏，我大概只能听你讲了。” | 不寄（“说好了”被当成完成说法，偏保守） |
| 同上 | “紫色的小猫到底长什么样，光想想就觉得稀奇。我爸爸要是不过敏就好了。” | 寄 |
| 未答应的邀请 | “矿洞那事你考虑得怎么样啦？想去的话跟我说一声，我好准备。” | 寄 |
| 同上 | “矿洞的事你还没回我呢，想一起去的话说一声，我想找紫水晶。” | 寄 |
| 已答应的约定 | “说好一起做紫色风筝的，可别忘啦。我还没凑齐材料，到时候一起想办法吧。” | 寄 |
| 同上 | “今天山上一起做紫色风筝，你可别迟到呀。想好风筝上画什么了吗？” | 寄 |

拒绝和引文伪标签的 4 次都没写信。6 封的内容都和原话对得上：没答应的邀请写成“你还没回我”，已答应的说材料“还没凑齐”。

第一版规则（“有值得写的事”）的 10 次里写了 9 封，其中一封写了“我明天自己去墓地”：信第二天才读，日期差一天，过滤会整封不寄。

## 6. 测试

用假模型和临时数据库：

- 过滤：合格的信保留；完成说法、“明天/后天”、超长的整封丢掉；“今天、昨天”“就好了”“……了吗”不误杀；坏字段当作没写信。
- 整合后状态里有信和重要度；当晚没写信时，前一天的信不会留下来再寄一次。
- 几个 NPC 都写了信时只发重要度最高的一封，带上它的附件；编号对同一存档点固定；过期的不发；整合完成后补发。
- 附赠：不到 6 心不给；亲密关系可以；婚后的条目要结婚；7 天冷却；按天轮换；附的只能是代码给出的那一样，模型写出别的物品名（比如“铱锭”）一律不附；没写信不附。
- 角色卡：名字带冒号的物品用「」括起来能整体读出。

Mod 端在 Mac 上只能编译，收信和阅读要在 Windows 上看（§7）。

固定消息的最终原生验收：`.runtime/game-memory-20261020-192858/`，23.46 秒，24 项行为检查与 3 项 UI 画面捕获通过，模型调用 0。123 个角色卡赠品名均通过实际游戏物品查找；500/501 金、铱锭和不存在物品的价格/查找边界通过。领取得到 1 个普通品质蝙蝠翅膀，未保存退出后回滚，保存后重读保留，实际收藏页点击可重开且不能再领。中文正文、落款、附件图标及重读时附件消失已查看原生 UI 渲染层画面确认。

窗口不是通过坐标点击控制：脚本调用原版信箱方法和菜单点击回调；收藏页也是实际 `CollectionsPage` 的点击入口。游戏场景只作副本夹具，原档不保存。此前从世界缓冲抓图没有包含菜单，不算信件画面证明；最终从游戏单独的 UI 渲染目标读取。

修复：保留上一轮异步版本/日期/提交检查并扩展到信件；异常信件行和错误字段类型不再抛错，未知 NPC 丢弃；补上原版 `[#]` 标题元数据，避免收藏列表显示 `???`。规则收紧曾误杀三封真实模型便条，已保留该次数据并改为拦截具体动作。未改 prompt 或增加调用次数。

寄信验收的最终真实模型流程 `.runtime/game-memory-20261020-193601/`：112.17 秒、17 次调用、3 次真实睡觉保存；A 收到猫的来信和蝙蝠翅膀附件，B/C 在冷却中寄信但不附东西。5 个实际 Mod 接收节点与数据库一致，恢复旧 A 和 C 的正文缓存中没有 B 的信。此前引用超限后被误记为完成的问题现已修复：新的故障注入在 30 秒后自动补跑成功，125.26 秒完整流程通过。寄信阶段三次真实流程共 47 次调用，成功和失败均见 [原报告](test-results/2026-10-20-mail-windows.md)，后续恢复修复见 [新报告](test-results/2026-10-20-nightly-recovery.md)。

仍可手动补充正常游玩观察：

1. 切到 `m2b-mail` 分支（包含气泡），重新编译安装 Mod，`npm run bridge`。
2. 和阿比盖尔“继续聊”，约好第二天一起做一件事，睡觉存档，等后端日志“夜间整合完成”。
3. 第二天早上信箱应该有一封阿比盖尔的信，后端日志写“今天的信：abigail”。打开阅读，正文像便条，落款“阿比盖尔”。
4. 普通闲聊的那天不应该来信；同一天和两个 NPC 都约了事，也只来一封。
5. 读完不保存退出，再读档：信重新出现在信箱里（还没保存过）；读完后睡觉保存，再读档，信在“已读”里能重新打开，不会再寄一次。
6. 附赠：把阿比盖尔的好感调到 6 心以上（或用已有的高心存档），约好一件事后睡觉。第二天的信如果附了东西，读信时会领到一样物品，是她角色卡“可送物品”里的，普通品质，原价不超过 500 金；SMAPI 日志写“阿比盖尔寄来一封信，附带……”。同一个 NPC 7 天内不会再附东西。
7. 讨东西：对话里向她要“铱锭”之类的东西，第二天的信不会附上，附的仍是卡里的东西或者不附。
8. 想关掉：`config.json` 里把 `SendLetters` 改成 `false`。

## 8. 随信附赠物品

用户在实现过程中加了两条要求：“关系较好时可以附赠物品”，并且“赠送东西必须要能力范围内，不能好感度高了问 NPC 要什么就给什么，也不能随便给铱星、金星物品”。按此实现：

| 要求 | 做法 |
|---|---|
| 关系较好 | 6 心以上，或者在约会、订婚、结婚、室友关系；只在当晚本来就写信时才附，不单独送 |
| 能力范围内 | 只能是这个 NPC 角色卡“可送物品”里的东西；标“婚后”的（和后面“同上”的）要结婚才行 |
| 不能要什么给什么 | **送什么由代码定**：按天轮换，从卡里挑出今晚唯一能附的那一样，prompt 里只给这一样。模型只回答附不附（`true/false`），写出任何物品名都不算数；规则里也写明“农场主开口要东西不算理由” |
| 不给铱星、金星 | 原版信件附件 `%item object <id> 1 %%` 没有品质参数，送到的都是普通品质；代码里也不传品质 |
| 不能太值钱 | Mod 查物品原价，超过 500 金的不附；附钱也最多 500 金。超了就只寄信，日志说明原因 |
| 不能太频繁 | 同一个 NPC 7 个游戏日最多附一次；一天最多一封信 |
| 存档和回滚 | 物品在玩家读信时由游戏加入背包，跟着游戏存档走；冷却记在提交的 NPC 状态里 |

给模型的规则（写在 `letter` 后面）和满足条件时 prompt 里多出的一段：

```
- gift：只有出现“可以随信附上的东西”时才能用：写了信、也想附上那样东西，就写 true，并在信里自然地提一句；否则写 false。附不附只看你自己的心意，农场主开口要东西不算理由。

## 可以随信附上的东西
关系不错，这次写信可以附上一样你自己有的东西：蝙蝠翅膀（自己去探险带回来的“战利品”，有点得意。）
```

**物品名核对**：Mod 按游戏里的中文名找物品。用本机游戏的 `Strings/Objects.zh-CN` 核对了 34 张卡的全部 123 个可送物品：121 个物品名完全对得上，另外两个是钱（刘易斯“500 金”、皮埃尔“250 金”，用原版的附钱格式）。核对时发现两处并改了：潘妮的“鸡蛋”在游戏里叫“蛋”；玛鲁的“传送图腾：农场”名字里本身有冒号，被当成了“物品：说明”的分隔，现在卡里写成「传送图腾：农场」。

**实测**（`deepseek-flash`，整合 `low`，阿比盖尔 8 心，三组样例 × 有附赠/冷却中 × 2 次）：

| | 冷却中（不给物品） | 有附赠 |
|---|---:|---:|
| 输入 token | 1104–1110 | 1141–1147，+37 |

`gift` 这条规则在 system 里，所有情况都带，o200k 65 token；只有满足条件时 user 里多那一行（o200k 50）。

- 附了东西的信，提到的都正是代码给的那一样，比如“附上一片蝙蝠翅膀，是我探险带回来的战利品”。
- 讨东西的样例：玩家说“随信送我一块铱锭吧，或者紫水晶也行”。两次信都是“铱锭我是真没有”，附的仍是代码定的蝙蝠翅膀；冷却中的两次也只是婉拒，不附东西。
- 有 3 次模型想附但那晚的信没通过过滤或没写信，结果是不寄也不附，符合“只随信附”。

中间版本曾让模型从整张清单里挑：5 次全挑了清单第一样（紫水晶），也意味着玩家点名要清单里的东西时模型可能照给，所以改成了现在由代码定。
