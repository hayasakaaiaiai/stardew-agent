# 用真实模型跑约定线

> 状态：测试计划，用户 2026-10-23 确认“按这个做”。分支 `m2c-real-meetings`，建在 `main / df8273c` 上。

## 1. 要回答什么

约定线的 Windows 验收（343/343）用的都是固定回复，真实模型调用 0 次。之前 Mac 上的真实模型抽样是按功能分开、一问一答测的，改约从没用真实模型测过，Windows 的十类修复也没拿真实对话重放过。

这次只看一件事：**NPC 嘴上说的约定，和后端最后发给 Mod 的约定，对不对得上。** 错分三种：

| 错 | 后果 | 以前的取舍 |
|---|---|---|
| 漏记：两人都说好了，代码没记 | 玩家去了，NPC 不来；屏幕上方没有“约好了”的提示，玩家能看出来 | 宁可漏 |
| 错记：没说好，或说的是别的日子、钟点、地点，代码却记了 | NPC 跑去白等，或去错地方，事后还按“农场主没来”扣好感 | 最要避免 |
| NPC 说错：代码按规则拦下的（节日当天约普通地点、超过后天），NPC 嘴上却答应了 | NPC 以为约好了，第二天没去 | 靠提示行让 NPC 婉拒 |

范围按用户选的：代码要读原话的几类。一起逛后的回忆、失约后的心情、挖矿块数、自己来帮忙这几类之前已经单句实测过，这次不测。

## 2. 怎么跑

走真实的后端，不进游戏：

- 起一个真实的 `BridgeServer`，用模拟的 Mod 客户端发和游戏一样的消息（`save.loaded`、`talk.open`、玩家说话、`talk.close`、睡觉保存），和 `tests/helpers/bridge.ts` 的做法一样。
- 对话用真实模型，推理强度 `high`，和正常游戏一样；夜间整合也用真实模型，因为“明天”的约定是夜间整合写、再由代码核对的。
- 每段对话先摆好日子、钟点、所在地点、好感和已有的约定（需要已有约定的，用一段固定回复的对话先约好，这段不花钱）。然后玩家按句子库说 1–2 句，NPC 每句由真实模型回。聊完 `talk.close`，需要过夜的再睡一觉。
- 记下每段的全部原话，以及后端发给 Mod 的 `day.meetings`（含 `sameDay`、`calledOff`、`movedTo`）和存下的约定记忆，作为“代码做了什么”。

**先标再对。**脚本把原话和代码结果分开存。我先只看原话，按下面的规则逐段标出“人读了会怎么理解”，标完再和代码结果对：

- 约成：玩家明说答应（“好、行、可以”这类，不带“看看、忙完再说”），NPC 没有婉拒；日子、钟点或时段、地点都能确定，只有一种读法。
- 改约、取消：同样要明说，没说的照旧。
- 有任何含糊（没选定两个地点中的哪个、“到时候再说”），算没约成。

## 3. 场景和句子库

8 位 NPC 轮着用（阿比盖尔、塞巴斯蒂安、莉亚、海莉、潘妮、玛鲁、山姆、谢恩），8 心以上或恋爱中，主动邀约的资格也够。玩家的话每类写十几种说法，不照抄单元测试里的句子。

| 类 | 场景 | 段数 |
|---|---|---:|
| 主动邀约 | NPC 开场约你（开场由真实模型写），玩家回：答应、拒绝、含糊、答应后又反悔、答应但改钟点、答应但改地点 | 12 |
| 改约 | 已有今天或后天的约：改钟点、改地点、改日子、几样一起改；只是问问不改；NPC 不答应改 | 12 |
| 当天约 | 明说钟点、“马上去”、没明说的答应（“两点应该能抽开身”）、NPC 婉拒 | 10 |
| 明天、后天和更远 | 明天的（过夜，由夜间整合定）、后天的、大后天和下周的（NPC 应该婉拒） | 10 |
| 改口取消 | 玩家取消、NPC 说去不了、半推半就、只是确认还算不算数 | 8 |
| 节日和生日 | 节日当天约海边（应改成一起去节日）、直接约一起去节日、“你生日那天” | 8 |
| **合计** | | **60** |

句子库分两批：A 批（约 2/3）跑完有问题先报给你；如果因此改了核对规则，再跑 B 批（约 1/3，规则改完后才写，不拿来调规则）看留出的结果。没改规则就 A、B 合在一起算。

## 4. 成本

按之前实测：对话每次约 2k 输入（大部分能命中缓存）、约 140 输出（含推理）；夜间整合按需要过夜的场景算。

| | 次数 | 输入 | 输出 |
|---|---:|---:|---:|
| 对话（开场 + 1–2 句） | 约 135 | 约 27 万 | 约 1.9 万 |
| 夜间整合 | 约 10 | 约 4 万 | 约 0.8 万 |
| **合计** | **约 145** | **约 31 万** | **约 2.7 万** |

报告里按模型返回的 `usage` 写实际数（命中缓存和没命中的分开）。这次只是测，不改 prompt，所以正常游戏的 token 成本不变。

## 5. 不花钱的那一步

先把 `.runtime/` 里已存的真实对话（`invite-probes`、`same-day-probes`、`call-off-probes`、`later-probes`、`festival-meet-probes`）用 Windows 修过的核对代码重放一遍，和当时的结果逐条比。变了的逐条列出来，看是修好了还是改坏了。

## 6. 报告和发现的问题

- 每类报：约成且记对、漏记、错记（日子、钟点、地点哪样错）、NPC 说错。错记和 NPC 说错每一次都列原话。
- 发现核对规则读错原话的，先把原话和修法选项报给你，你定了再改。
- 结果写进 `docs/test-results/`，原始记录存在 `.runtime/real-meetings-*/`（不进仓库）。脚本放 `tools/test-meetings-real.ts`，进仓库，能重跑；也能用存下的记录离线重放，不再花钱。

## 7. 不覆盖

- NPC 在游戏里真的走过去、到场、碰面：Windows 已用固定回复测过。
- 自由对白里的编造、其他功能的内容。
- 玩家的说法只来自句子库，真人的说法会更散。
