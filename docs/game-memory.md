# M3b：游戏存档与跨天记忆

> 2026-10-20。沿用 `design.md` §6 的提交规则和 M1 已实现的接口；本次接入由用户确认开始。不改记忆内核，不合并硬件分支。

## 1. 行为

- 游戏里的对话使用已有 `AgentMemory` 的召回策略，心数、关系和角色卡规则保持一致。
- `Saving` 时生成提交指针，通过 SMAPI save data 随游戏保存，并排队发送 `save.saving`。不在主线程等待后端。
- `Saved` 才确认提交；随后为实际的新日期打开工作区。缓存游玩中的日期作为 `dayEnded`，不使用保存过程中已经变化的日期。
- 不保存退出时发送 `title.returned`，丢弃当天内容；重新读档换 `loadNonce`。读取 `_old` 等旧档时按档内指针分叉。
- 新存档和首次安装没有指针，从创世提交开始。显式指针缺失时只允许退到指针里的已知父提交；父提交也缺失则提示错误，不按日期猜历史。沿用 M1 的严格对齐约束。
- 当前阶段仅支持单人/主玩家。农场帮手不写共享存档的记忆指针，避免多人对同一谱系竞争。

## 2. 协议与恢复

协议升级为 2，旧 Mod 必须随后端一同更新。

- 每次真实读档生成一个 `loadNonce`；同一次游戏的后端重连保持它不变。
- `save.loaded` 是每次连接的握手（`seq=0`），携带本次读档最初的日期、玩家和档内指针。后端用持久检查点恢复该 nonce 已处理到的日期，而不是把重连当成重新读档。
- 生命周期事件按递增 `seq` 缓存在 Mod 内，收到后端 `ack` 后移除，断线时补发，上限 2000。达到上限时停用本次读档的 AI 并提示，继续保留原版游戏。
- 玩家正在等待的模型请求不会在断线后自动重新调用；关闭当前聊天，重连后重新开口。已经完成的对话由记忆内核的 JSONL 恢复。
- 后端保留最近 2000 条消息的序号和内容摘要；相同消息重发返回原结果，序号相同内容不同则报错，过旧消息不重新执行。
- 所有回复带 `lineageId`、`loadNonce` 和请求 `seq`。取消、读档、换天、保存或断线后，迟到回复不会显示或写入新一天。

后端数据放在 `.runtime/game/`：`memory.sqlite`、`scratch/` 和 `bridge/`。`bridge/` 保存原子替换且刷盘的生命周期检查点及去重结果，不改变 SQLite 的表和记忆内核接口。准备、确认操作先记录意图，重启后按阶段重放；模型回复和它的去重结果写在同一个当天事件里，覆盖回复完成到检查点刷盘之间的崩溃窗口。

## 3. 实现边界

- 不改变提示词格式、记忆预算或好感度策略，没有新增运行时依赖。
- 不实现夜间自动整合、自主行动、机器人和游戏之间的记忆共享。
- 后端离线不阻止原版存档；同一游戏进程中的生命周期队列可在重连后补齐。退出游戏会失去尚未确认的队列，因此下次读档可能只能恢复父提交，并明确提示记忆缺口。
- 不支持删除数据库后自动猜测存档历史，也不自动清理旧提交。恢复文件（`scratch/` 的当天日志、`bridge/` 的检查点）在同一存档用新的 nonce 读档成功后删除旧的（2026-10-20，`m1-scratch-cleanup`）；不再读的存档各留一份。
- 跨进程共享同一记忆目录、多人同步和第三方“随时存档”Mod 不在本轮真机验收范围。

## 4. 验证

Windows 组合验收使用启动器新建的 `MemoryTest_<独立 ID>` 副本和独立后端数据库。副本改为“记忆验收”玩家并仅在副本中设置阿比盖尔 8 心；为避开商店的原版剧情，验收中把 NPC 和玩家放到副本的农舍空格。原档先备份并核对前后哈希。通过原版“自己说”输入回调提交指定信息，通过真实睡觉触发 Saving/Saved，随后测试不保存回滚、游戏保持打开时重启后端，以及恢复副本的 A 保存点后形成与 B 同父的 C 分支。每个保存或恢复节点先暂停，外部核对 prompt、SQLite 和存档指针后才继续；结束回标题页，异常暂停。外部启动器确认终态且没有保存操作后，备份副本并结束它自己启动的游戏进程。这是测试工具，不改变默认启动、提示词或记忆策略。

复现命令（先正常退出游戏，使用 Windows PowerShell 5 或更高）：

```powershell
.\tools\test-game-memory.ps1
```

源档固定为 `测试_436774213`，身份不符拒绝启动。运行目录是 `.runtime/game-memory-<时间>/`，含原档备份和前后哈希、A/B/C 副本保存点、真实模型调用、游戏事件、独立 SQLite、每个校验点的证据及 `result.json`。没有配置 `.env`、游戏仍在运行或 Mod 安装条件不满足时不会启动游戏。模型不记录指定信息、回复不符合预期、记忆上下文串档或存档指针不一致都会停止并报告失败，不把失败作为通过。

2026-10-20：67 项后端测试、类型检查和 TypeScript 构建通过，包含 23 项新桥接记忆测试。新增测试使用临时目录、真实 SQLite/记忆运行时和模拟 WebSocket Mod，不读取用户的游戏存档，不调用付费模型。其中一项真正 `SIGKILL` 后端子进程再恢复；另有检查点意图分别落在 SQLite 确认前后的故障窗口验证。

已覆盖：跨天召回、不保存退出、旧提交分叉、不同谱系隔离、同 nonce 重连、后端重启、准备和确认窗口、事件补发、重复/冲突序号、取消后的迟到回复、过期 nonce，以及协议输入验证。10 项 C# 检查通过，覆盖原有 5 项菜单回归和新增的不可变队列、顺序、确认、2000 条上限、过期确认与回复身份隔离。Release 编译为 0 警告、0 错误。

游戏内清单：和阿比盖尔说一件具体的新事并睡觉存档，第二天询问；再说另一件事不保存退出，重读后确认只记得前一件；游戏保持打开时重启后端，确认当天已完成对话仍在。只在 Windows 上确认，中文输入与原版台词保留沿用 M3a 清单。

好感度策略沿用 `dialogue-prototype.md` §14：0–1 心只召回三天内、重要度至少 4 的记忆，8 心以上放宽到六条。因此“模型没有选择记下”或“被低心数策略过滤”不等于存档丢失；跨天真机验证优先使用高心数 NPC，并核对实际记忆记录。

Windows 已安装协议 2 的 Mod 和后端。首次测试遇到模型 TLS 失败；11 时网络恢复后，阿比盖尔三轮真机对话 13.27 秒通过。随后完整真机组合验收通过：76.77 秒、13 次真实模型调用、3 次真实睡觉保存；跨天保留、不保存回滚、后端进程更换 PID 后恢复，以及旧档分叉均有 prompt、游戏文件和 SQLite 证据。原测试档 6 个文件 SHA256 均相同。C# 检查增至 13 项，覆盖正常启动不启用测试、拒绝原档/外网/无效配置，以及独立后端配置隔离。中文输入法等 M3a 项目仍待手测。详情见 [完整真机组合](test-results/2026-10-20-game-memory.md)、[首次验证](test-results/2026-10-20-memory.md) 和 [早期重测](test-results/2026-10-20-retest.md)。
